# 【根因】键盘弹窗:板子的蓝牙标识符自称是「键盘」

**你的判断是对的** —— 问题出在板子的**蓝牙身份标识**上,不在 HID 描述符。

## 一、真凶

`src/ble/hid_transport_ble.cpp` 里:

```cpp
adv->setAppearance(0x03C1);   // HID Keyboard(兼容性最好;0x03C0 = Generic HID)
```

**`0x03C1` 就是 BLE 规范里的「HID Keyboard」**。
这是我早期为了"兼容性"随手设的,注释里还写明了。

BLE 的 **Appearance**(外观)字段是设备对外声明"我是什么"的标准字段,
手机会读它。三星读到 `Keyboard`,就在你聚焦输入框时弹「是否连入外接键盘」。

**手机侧看到的证据**:

```
shim::record 005 ... 5e:41 BLE  cod:0-5-40 ... name:"ESP32S3 Touch HID"
                                   ↑
                Bluetooth Class of Device = Peripheral / Keyboard(0x10)
```

所以之前所有排查都找错了方向:
- ✅ HID 描述符确实已经**没有**任何键盘集合(设备分类只有 `TOUCH｜TOUCH_MT｜EXTERNAL`)
- ❌ 但**蓝牙广播里的身份仍然是 Keyboard** —— 这才是三星判断的依据

## 二、修法

Appearance 改成触摸屏该报的值:

| 值 | 含义 |
|---|---|
| 0x03C0 | HID Generic |
| **0x03C1** | **HID Keyboard ← 原来的错误值** |
| 0x03C2 | HID Mouse |
| **0x03C5** | **HID Digitizer Tablet ← 已改成这个** |
| 0x03C7 | HID Digital Pen |

```cpp
adv->setAppearance(0x03C5);   // 数字转换器/触摸屏
```

**已烧录。** 但 CoD 在手机的**缓存扫描记录**里仍显示 `0-5-40`,
所以必须**解绑 → 关开蓝牙 → 重新配对**,让手机重新读取。

## 三、需要你手动做一次

手机自动化重配一直卡住(反复解绑把蓝牙弄进了中间态),麻烦你手动:

1. 设置 → 蓝牙 → **ESP32S3 Touch HID** → 齿轮 → **取消配对**
2. **把蓝牙关掉再打开**(清缓存)
3. 重新配对
4. 随便点一个输入框试试 —— **应该不再弹窗了**

## 四、如果还弹(备用方案)

说明 CoD 不是从 Appearance 推出来的,而是手机根据 HID 描述符自己算的。
那就再试这两个值,依次验证:

1. `adv->setAppearance(0x03C0);`  ← HID Generic(最中性)
2. 如果还不行,查 Android 侧 `BluetoothClass` 是怎么给 LE HID 设备定类的

## 五、经验教训

> **"设备说自己是什么"和"设备的实际能力"是两回事,两边都要对。**
>
> 我把 HID 描述符里的键盘集合删得干干净净,却忘了蓝牙广播里的
> Appearance 还在自称键盘 —— 排查时一直盯着描述符,漏了广播层。

这类"标识与实际不一致"的问题,排查时应该**从对端(手机)能看到的所有信息**
逐项核对:广播数据(Appearance / 设备名 / Service UUID)、
Class of Device、HID 描述符、设备分类 —— 而不是只看自己写的那一层。
