# 三星「是否连入外接键盘」弹窗 —— 调查结论

## 一、这是什么

手机连上板子后,只要**聚焦输入框**,三星就弹出:

```
是否连入外接键盘?
   [否]        [是]
   ○ 下次不再提示
```

## 二、逐条排除的过程(都做了实测)

| 假设 | 做法 | 结果 |
|---|---|---|
| ① 描述符里有键盘集合 | 把 Keyboard/Consumer/Mouse 全部移除(212B → 92B),设备分类变成 `TOUCH｜TOUCH_MT｜EXTERNAL` | ❌ 弹窗依旧 |
| ② 描述符 Collection 不配对导致 HID 层拒绝连接 | 修掉多余的 `0xC0`,校验开=闭=2 | ✅ 修好了 HID 层(之前蓝牙连着但内核没设备),**但弹窗依旧** |
| ③ 蓝牙残留记录 | 解除配对后再重配 | 解除配对期间**无弹窗**,一旦配对就恢复 |
| ④ 设备处于「已连接」状态 | 在蓝牙设置里点设备断开(内核设备数变 0) | ❌ **仍然弹窗** |
| ⑤ 三星白名单 `sip_keyboard_type_mouse_id_list` | 把我们的 `2562:1024` 追加进去 | ❌ 无效(已恢复原值) |
| ⑥ 「下次不再提示」 | 分别试 `否`+勾选、`是`+勾选 | ❌ 都不持久,设置库里没有任何字段变化 |

## 三、结论

> **触发条件是「存在已配对的 HID 设备」,与"是不是键盘""有没有连着"都无关。**
>
> 只要板子和手机是**配对状态**,聚焦输入框就会弹。

这是三星系统层面的行为,**没有找到可以由 App 或 adb 关闭的开关**。

## 四、但有个好消息

**关掉弹窗之后,输入就正常了。**

实测:
```
点「否」→ 弹窗关闭
输入 hello → 输入框内容 = hello ✅
弹窗没有再出现
```

所以实际影响是:**每个输入场景多点一次「否」**,不是"完全无法输入"。

## 五、可选的应对方式

| 方式 | 说明 | 代价 |
|---|---|---|
| **A. 直接点「否」**(推荐) | 弹一次点一次,之后正常输入 | 每次输入多点一下 |
| **B. 需要大量打字时先解绑板子** | 蓝牙设置 → 设备齿轮 → 取消配对 | 用完要重新配对 |
| **C. 用电脑浏览器开板子的网页控制台** | 打字在电脑上完成 | 需要电脑 |
| **D. 只在板子工作时配对,平时解绑** | 用不到触摸注入时保持解绑 | 来回切换麻烦 |

## 六、给后续开发的启示

**不要在设计里假设"板子连着的时候手机还能顺畅手输"。**
所以:
- App 里**需要输入的地方要尽量少**(流程编辑尽量用点击、选择,少用键盘);
- 定时/坐标这类参数**优先用步进器(+/-)**而不是纯文本输入;
- 这个限制要写进 App 的「关于 → 重要提醒」里。

## 七、复现步骤(留给以后排查)

```bash
# 1. 确认设备已配对
adb shell dumpsys bluetooth_manager | grep -A2 mInputDevices

# 2. 聚焦任意输入框
adb shell am start -a android.settings.SETTINGS
adb shell input tap 515 2079

# 3. 看弹窗
adb shell uiautomator dump /sdcard/x.xml && adb shell cat /sdcard/x.xml | grep 外接键盘

# 4. 解除配对后再试 → 弹窗消失
```
