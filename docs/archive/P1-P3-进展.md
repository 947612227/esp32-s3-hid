## P1 顶栏时间 + 网络校时 + 弹窗规范 ✅

| 项 | 实现 |
|---|---|
| 顶栏时间 | 「触摸注入板」右侧,精确到秒,每秒走动 |
| 校时 | 自写 SNTP 客户端(`NtpClient`),**不依赖任何第三方库** |
| 服务器 | 依次尝试 `ntp.aliyun.com` → `cn.pool.ntp.org` → `time.windows.com` → `pool.ntp.org` |
| 首次启动 | 自动同步一次 |
| 点时间 | 立即重新同步,提示偏差(如 `-86 ms`) |
| 长按时间 | 打开「时间设置」:当前时间 / 同步状态 / 偏差 / 时区 |
| 时区 | **18 个城市**可选,含 UTC 偏移显示(如「北京/上海 UTC+8」) |
| 弹窗规范 | 标题+按钮**在顶部**;**点外部不关闭**;统一由 `Dialogs` 提供 |

> 注意:普通 App 无权修改系统时钟,所以做法是保存
> `offset = 网络时间 - 本机时间`,显示时用 `now + offset`,两次同步之间平滑走时。

### 踩的坑(重要)

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 列表项**点不动** | ListView 套在 ScrollView 里收不到点击 | `Dialogs.show(..., wrapScroll=false)` |
| 2 | 仍然点不动 | 改用"可点击的行"后依旧 | — |
| 3 | **输入文字后**点不动 | **输入法弹出时点击被吃掉**(实测连"取消"按钮都点不了) | ① 改成独立全屏页面(避开弹窗);② **输入停顿 1.3 秒后自动收起键盘**;③ 页面加黄字提示 |
| 4 | 弹窗"看到的和点到的错位" | 输入法弹出/收起导致弹窗重排 | 窗口设 `SOFT_INPUT_ADJUST_NOTHING` + 靠上贴边 |

**最终方案**:App 列表做成**独立全屏 Activity**(`AppListActivity`),
彻底避开 AlertDialog 与输入法的冲突,交互也更自然(返回键直接退出)。

## ⚠️ 严重回归:界面全空(已修复)

**现象**:App 打开后只剩标题栏,且标题跑到屏幕中间,**5 个页签和所有内容都消失**。

**排查过程**:
运行时打印视图结构(比看截图猜有效得多):

```
headerBox children=3
  hb[0] LinearLayout h=1994   ← 标题栏占了 1994px(整屏)
  hb[1] LinearLayout h=0      ← 页签被挤成 0 高
  hb[2] FrameLayout  h=0      ← 内容被挤成 0 高
```

**根因**:顶栏里用来"把三横推到最右"的空白 `View`:

```java
View spacer = new View(this);
r1.addView(spacer, new LinearLayout.LayoutParams(0, WRAP_CONTENT, 1f));
```

**裸 `View` 在 `AT_MOST` 测量下,`onMeasure` 会直接返回可用空间的全部高度**
(`View.getDefaultSize()` 对 `AT_MOST` 的行为就是返回 `specSize`),
所以这个"留白"把整屏吃掉了。

之前这里是「地址」按钮(Button 会正常 wrap),换成 `View` 才触发。

**修法**:必须给明确高度。

```java
r1.addView(spacer, new LinearLayout.LayoutParams(0, dp(1), 1f));
```

**教训**:
1. **裸 `View` 不能当弹性占位符用**(至少要给固定高度,或用 `Space`);
2. 界面出问题时,**先打印各容器的子节点数和实际高度**,比看截图快得多;
3. 改完布局**必须截图确认**,不能只看"编译通过"。
