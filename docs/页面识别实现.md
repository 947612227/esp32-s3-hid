# 页面识别:实现记录

> 调研见 [`页面识别调研.md`](页面识别调研.md)。本文是**第 1 步(识别 + 显示)**的落地记录。

## 做了什么

| 项 | 说明 |
|---|---|
| `PageWatcher.java` | 无障碍服务,**只看不点** |
| `res/xml/page_watcher.xml` | 服务配置(只申请读窗口内容) |
| 悬浮窗 | 新增 `🔍 ProjectDetailActivity` 一行 |
| 设置页 | 「页面识别」状态 + 一键跳转系统设置 |

## 隐私边界(写死在代码和配置里)

```xml
android:canRetrieveWindowContent="true"
<!-- 没有 canPerformGestures,没有点击/输入能力 -->
```

服务说明文字(用户授权时能看到):

> **只看不点**:读取当前页面的名称和文字,用于在悬浮窗和日志里显示"现在在哪个页面",方便排查流程为什么点空。本服务不会代替你点击或输入任何内容。

**点击始终走 HID 注入**(系统级真实触摸),不用无障碍的 `ACTION_CLICK`。

## ⚠️ 踩到的三个坑(都很关键)

### 坑 1:adb 写不进无障碍设置(MIUI 会回滚)

```bash
adb shell settings put secure enabled_accessibility_services com.dsh.touchpad/com.dsh.touchpad.PageWatcher
# 看起来成功了,但 dumpsys 里 Enabled services:{} —— 被 MIUI 回滚成 null
```

**只能走 UI 手动开。**

### 坑 2:MIUI 开了个「危险」二次确认,还有 4 秒倒计时

点开关后会弹:

```
⚠️ 危险
"无障碍"为高度敏感权限…财产安全将会受到威胁。
  ☐ 我已知晓可能存在的风险,并自愿承担可能导致的后果
                          [确定(4)]   [取消]
```

必须先**勾选**那个复选框,再等倒计时走完,「确定」才能点。

### 坑 3:`adb shell am force-stop` 会把无障碍设置**清掉**

实测:开启成功后我跑了一次
```bash
adb shell am force-stop com.dsh.touchpad
```
再看 → `enabled_accessibility_services = null`。

**MIUI 把"强停应用"当成安全事件,顺手把它的无障碍权限撤销了。**

> 影响:调试时别用 `force-stop`,改用 `am start` 直接拉起。
> 用户侧要注意:如果在"最近任务"里**划掉**这个 App,MIUI 可能也会撤销无障碍 —— **建议加入内存白名单**。

## 正确的开启步骤(给用户看)

1. 打开「触摸注入板」→ 右上角菜单 → 设置
2. 找到「页面识别」→ 点「❌ 未开启 —— 点这里去开」
3. 进入 **已下载的服务** → 点「触摸注入板 · 页面识别」
4. 打开右上角开关
5. 弹「危险」→ **勾选「我已知晓」** → 等 4 秒 → 点「确定」

开启后设置页会显示:
```
页面识别
  ✅ 已开启(当前:大麦 · ProjectDetailActivity)
```
