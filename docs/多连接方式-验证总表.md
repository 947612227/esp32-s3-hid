## ④ 三种连接方式的端到端验证

### 🎉 蓝牙方式 —— **完全验证通过**

**条件:手机 WiFi 完全不可达(公司网要飞连认证),蓝牙是唯一通路。**

```
App 侧:  → BLE  /api/status   ⇒  STATUS     ← OK 187B  ✅
         → BLE  /api/scripts  ⇒  LIST       ← 流程列表正常显示 6 个  ✅
         → BLE  /api/logs     ⇒  LOG        ← OK 237B(单片)  ✅
         → BLE  /api/page     ⇒  PAGE       ← 带真实 Activity 名  ✅
         → BLE  /api/run?index=1 ⇒ RUN 1    ← 完整链路  ✅

板子侧:  [ble] 控制命令:...
         [ble] 控制响应 483 字节,分 3 片

结果:    >>> 4s 后:手机已回到桌面 ✅
        (证明流程的触摸注入成功了)

稳定性:  发出 15 · 成功 6 · 失败 0 · 丢弃 0 · 崩溃 0  ✅
```

**⇒ 「发命令(蓝牙)→ 板子执行 → 注入触摸(蓝牙)」整条链路在无 WiFi 条件下走通。**

### ⏳ WiFi 方式 —— 待验证

代码路径就是原来一直在用的 HTTP ✅ 逻辑没动过 ✅
**待验证**:把控制方式切成「只用 WiFi」跑一遍,确认回落正常。

> 注意:验证需要手机连上板子热点(否则 App 的 HTTP 够不到 192.168.4.1)✅

### ⏳ USB 直插 —— 待硬件

需要 **OTG 转接线**把板子的 `USB` 口接到手机 ✅
**检测逻辑已就绪**(查 Espressif VID)✅ 但没有硬件没法实测 ✅

**USB 方式的控制链路**:固件刷 `usb` 环境时 **没有 BLE**(那个环境不编译 `src/ble/`)⇒
**USB 方式下控制只能走 WiFi** ✅ 这点要在文档里写清楚 ✅
