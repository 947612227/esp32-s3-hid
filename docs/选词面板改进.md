# 选词面板:读不到「已预约」+ 不能滚动 + 排得乱

## 你反馈的两件事

> 看下我当前的页面,已预约按钮没有出现在弹窗中,
> 另外弹窗是不是可以支持上下滑动,现在排着有点乱

**两个都是真问题,原因如下。**

---

# 问题①:「已预约」读不到 —— **只读了 `getText()`**

```java
CharSequence tx = n.getText();     // ← 只读这一个
```

Android 上文字的来源有**两个**:

| 方法 | 谁用它 |
|---|---|
| `getText()` | 普通 `TextView` / `EditText` |
| **`getContentDescription()`** | **自定义按钮 / 图片按钮 / Compose 画的控件** |

**大麦的「已预约」是自定义按钮,文字在 `contentDescription` 里** ——
只读 `getText()` 就**完全读不到**。

## 修法

```java
CharSequence tx = n.getText();
if (tx == null || tx.toString().trim().isEmpty()) {
    tx = n.getContentDescription();       // ← 兜底读这个
}
```

顺带把覆盖上限也提了:

| | 改前 | 改后 |
|---|---|---|
| 最多读几个词 | 28 | **40** |
| 最多遍历几个控件 | 400 | **700** |

> 页面元素多的时候(比如电商详情页),400 个节点可能还没走到底就停了。

---

# 问题②:不能滚动 → 加 ScrollView,底部按钮固定

原来整个面板是一个 `LinearLayout`,词一多就超出屏幕,而且**底部的「关闭」被挤到看不见**。

## 改法:分成两层

```
┌─────────────────────────┐
│ 外层(固定背景 + 圆角)     │
│  ┌───────────────────┐  │
│  │ ScrollView        │  │  ← 高度权重 1,占满剩余空间
│  │   标题 + 说明 + 词  │  │     词太多就上下滑
│  └───────────────────┘  │
│  [用页面名]   [关闭]      │  ← 固定在底部,永远看得见
└─────────────────────────┘
```

```java
outer.addView(sv, new LinearLayout.LayoutParams(
        ViewGroup.LayoutParams.MATCH_PARENT, 0, 1f));   // 权重 1
outer.addView(foot);                                    // 固定底部
```

面板高度**按内容算,最多占屏幕 76%**:

```java
outer.measure(...);
int finalH = Math.min(outer.getMeasuredHeight() + dp(4), (int)(screenH * 0.76));
```

# 问题③:"排着有点乱" → ⭐ 的词排最前面

原来词的顺序就是控件树的遍历顺序 —— ⭐ 的关键字**埋在几十个词中间**。

现在**⭐ 的全部排到最前面**:

```java
for (String w : words) {
    if (prev.contains(w.trim())) olds.add(w); else news.add(w);
}
news.addAll(olds);      // ⭐ 在前,普通的在后
words = news;
```

配合之前的配色:

```
╔═══════════╗ ╔═══════════╗
║ ⭐ 抢票预约 ║ ║ ⭐ 我的订单 ║   ← 暗金底 + 亮金字(能用的)
╚═══════════╝ ╚═══════════╝
  [首页]  [影院·场馆]  [大麦VIP]     ← 暗灰底 + 中灰字(别用的)
```

**好东西在最上面,不用翻。**

# 附带修掉:Activity 名有时是空的

```
当前页面:(未知)
```

**Activity 名平时只能从 `WINDOW_STATE_CHANGED` 事件里拿** ——
刚连上服务、用户还没切过窗口时,它一直是空的。

## 修法:用**窗口标题**兜底

```java
java.util.List<AccessibilityWindowInfo> ws = inst.getWindows();
for (AccessibilityWindowInfo w : ws) {
    if (w.getType() != TYPE_APPLICATION) continue;
    CharSequence t = w.getTitle();
    if (t != null && t.toString().endsWith("Activity")) { sAct = t.toString(); break; }
}
```

只在 `sAct` 为空时查一次,不浪费性能。实测:

```
改前: act = (空)
改后: act = com.dsh.touchpad.MainActivity    ✅
```

# 教训

## 1. Android 的文字有**两个**来源

`getText()` **和** `getContentDescription()`。
**做无障碍读取时两个都要读** —— 漏一个就会"有些按钮读不到",
而且很难猜是哪个。

## 2. 内容会超长的面板**必须能滚**

而且**操作按钮要固定在底部** ——
让用户为了点「关闭」而滚半天是很差的体验。

## 3. 顺序也是信息

几十个词平铺出来,用户不知道看哪里。
**把推荐的排最前面 + 用颜色区分强弱** —— 布局本身就在引导选择。

## 4. 系统给的数据可能"暂时是空的"

`Activity` 名依赖事件,事件没来就是空。
**该有兜底来源**(这里是窗口标题),别让界面出现"(未知)"。
