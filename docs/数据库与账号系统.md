### ⚠️ 踩的坑:密码强度策略的鸡生蛋问题

MySQL 8 默认装了 `validate_password` 组件,`zhangjia` 这种密码**直接被拒**:

```
ERROR 1819: Your password does not satisfy the current policy requirements
```

而改密码又要求先改密码:

```
ERROR 1820: You must reset your password using ALTER USER statement
```

**解决办法**:

```bash
systemctl stop mysqld
mysqld --skip-grant-tables --skip-networking --user=mysql &
mysql -uroot -e 'DELETE FROM mysql.component WHERE component_urn="file://component_validate_password";'
systemctl restart mysqld          # ⚠️ 必须重启,组件已经加载进内存了,FLUSH 卸载不掉
mysql -uroot -p'<临时密码>' --connect-expired-password \
  -e 'ALTER USER "root"@"localhost" IDENTIFIED BY "zhangjia";'
```

## 账号系统

### 安全设计

| 项 | 做法 |
|---|---|
| 密码存储 | **scrypt**(N=16384, r=8, p=1),格式 `scrypt$N$r$p$salt$hash` |
| 密码校验 | `crypto.timingSafeEqual`,防时序侧信道 |
| 会话 | 随机 64 位 token 存**数据库**,7 天过期,HttpOnly + SameSite=Lax cookie |
| 角色 | `admin`(可增删改)/ `viewer`(**只读**) |
| 审计 | 登录成功/失败、建号、改密、停用、删号、传固件/APK、设策略**全部记录** |
| 防自伤 | 不能停用自己、不能删自己 |

## ⚠️ 安全提醒:3306 暴露在公网

你说 3306 已放行 —— **这意味着任何人扫到你的 IP 都能尝试连数据库**。
`zhangjia` 这种密码用暴力破解几分钟就能试出来。

**强烈建议至少做下面一条**:

1. **阿里云安全组把 3306 的来源限制成你自己的 IP**(最有效)
2. 或者干脆**关掉 3306 对外**,只让本机访问(`bind-address = 127.0.0.1`)——
   反正网页服务就在同一台机器上,不需要远程连
3. 如果要远程连,给 `touchpad` 账号换个**强密码**,并限制来源:

```sql
-- 只允许某个 IP 连
CREATE USER 'touchpad'@'1.2.3.4' IDENTIFIED BY '<强密码>';
GRANT ALL ON touchpad.* TO 'touchpad'@'1.2.3.4';
DROP USER 'touchpad'@'%';       -- 删掉"任何来源"那个
```

> 现在的配置是 `touchpad@'%'`(任何来源)+ 密码 `zhangjia`。
> **强烈建议你至少把安全组收紧。**

# 🐛 修掉的 bug:改成 MySQL 版后满屏 404

## 现象

你说"网页很多都是 404,啥都没有"。

## 真实原因(我的错)

重写服务端时,把管理接口从 **`/admin/api/*`** 改成了 **`/api/admin/*`**,
但**看板 HTML 里旧的那几处引用忘了跟着改**:

| 看板里调的 | 服务端实际有的 | 结果 |
|---|---|---|
| `/admin/api/summary` | ❌ 没有 | **404** |
| `/admin/api/boards` | ❌ 没有 | **404** |
| `/admin/api/phones` | ❌ 没有 | **404** |
| `/admin/api/firmware` | ❌ 没有 | **404** |
| `/admin/api/apk` | ❌ 没有 | **404** |
| `/admin/api/policy` | ❌ 没有 | **404** |
| `/api/admin/users` | ✅ 有 | OK |
| `/api/admin/audit` | ✅ 有 | OK |

页面本身能打开(200),但里面**每一个数据区块都在 404**,
所以看起来就是"啥都没有"。

## 修了什么

### ① 把 10 处旧路径全部改成新前缀
```
/admin/api/*  →  /api/admin/*
```

### ② 旧的 `/admin/api/*` 加 307 跳转兼容
万一浏览器还跑着缓存的旧页面,也不会满屏 404。

### ③ 看板 HTML 加 `Cache-Control: no-store`
**这是根因的根因** —— 前端页面改了但浏览器还在跑旧的,
以后不会再出现"我明明改了,你看到的还是老的"。

### ④ 加了**可见的错误提示**

以前接口 404,页面就永远显示"加载中…",**看不出任何问题**。
现在:

- 顶部弹红色横幅:`⚠️ 接口 404:/api/admin/summary(路径可能不对)`
- 各区块也显示 `加载失败:HTTP 404`

### ⑤ 顺手消掉 `/favicon.ico` 的 404
加了内联 SVG 图标。

## 教训

**改接口路径时,前后端要一起改。**
而且**必须加禁用缓存** —— 否则前端改了、浏览器跑的还是旧的,
排查方向会被完全带偏(我一开始还以为是浏览器缓存,结果是自己漏改了)。
