# 多连接方式 · 第一步:自动检测三种连接

## 你要的

> 板子和手机通过蓝牙连接后,读取板子信息,app 上连接成功后上报信息到服务器,
> app 上支持多种连接方式,蓝牙或 wifi,或 usb 直插。
> app 启动自动检测是否蓝牙连接,是否直插连接,wifi 连接我不确认能否自动检测到。

**第一步做完了:三种连接都能自动检测 + 界面显示 + 变化时上报服务器。**
**WiFi 也能自动检测**(直接探上次成功的地址,1.2 秒超时)。

# ⚠️ 先纠正一个关键概念:**这里有两条独立的链路**

我把代码翻了一遍,确认现状是:

```
BLE 侧:  只有 HID over GATT(HOGP)   ← 没有控制用的自定义特征
App 侧:  控制全靠 HTTP               ← 完全没用 BluetoothAdapter/Gatt
```

| 链路 | 干什么 | 现在走什么 |
|---|---|---|
| **HID 链路** | 板子往手机**注入触摸** | BLE HID 或 USB HID |
| **控制链路** | App 读状态 / 跑流程 / 传脚本 | **WiFi HTTP(唯一)** |

## 所以你的疑问,答案是:

> 如果选了 WiFi 连接…是不是通信就走 WiFi 了,选蓝牙就走蓝牙?

**"选蓝牙/WiFi" 现在讲的是 HID 链路,不是控制链路** ✅

| 刷的固件 | 触摸注入走 | App 控制走 |
|---|---|---|
| `ble` | **蓝牙** | **仍然是 WiFi** ⚠️ |
| `usb` | **USB** | **仍然是 WiFi** ⚠️ |

**⇒ 现在无论刷哪个,App 控制板子都必须有 WiFi**
**⇒ 蓝牙目前只负责注入触摸,不负责传数据**

**你实测的处境正好卡在这**:三星上蓝牙 HID 连得好好的,
但 App 读不到板子(WiFi 不通)⇒ **所以第二步要做 BLE 控制通道**。

# 一、检测什么、怎么检测

## ① 蓝牙 HID / USB 直插 —— 查「输入设备」

```java
// ⚠️ 为什么查 InputDevice 而不是 BluetoothAdapter:
//    板子是以"触摸屏"身份接入的 —— 只要它真连上了,
//    系统输入设备列表里就会出现它。
//    这比查蓝牙配对状态准得多:配对过 ≠ 现在连着。
for (int id : InputDevice.getDeviceIds()) {
    InputDevice d = InputDevice.getDevice(id);
    String nm = d.getName();
    if (nm.toLowerCase().contains("esp32") || ...) { ... }
}
```

**USB** 另外查一道(认 Espressif 的 VID):

```java
UsbManager um = (UsbManager) ctx.getSystemService(Context.USB_SERVICE);
for (UsbDevice d : um.getDeviceList().values()) {
    if (d.getVendorId() == 0x303a) { st.usbHid = true; }   // ESP32-S3 原生 USB
}
```

**三星实测:**

```
系统输入设备:
  Device 22: ESP32S3 Touch HID
    Sources: TOUCHSCREEN          ← 板子作为触摸屏接入了 ✅
```

## ② WiFi 可达 —— 直接探上次成功的地址

用 `/api/status`,**1.2 秒超时** ✅

> 你担心"WiFi 能不能自动检测" —— **能** ✅
> 不过后台轮询**不每次都广播**(广播要等 6 秒,太重),
> 只探上次成功的地址,探不到就提示用户点「🔍 自动查找板子」✅

探测时会**认出是不是板子**(返回的 JSON 里有 `hid`/`scriptCount`/`fw` 才算),
避免把别的 HTTP 服务当成板子 ✅

# 二、界面

状态页最上面**单独一张「连接方式」卡**:

```
连接方式
🔵 蓝牙 HID  ·  📵 WiFi 不可达   (1ms)
蓝牙 HID = 板子的触摸屏已接入;USB = 直插;WiFi = App 能读到板子。每 5 秒自动刷新。
```

> ⚠️ **为什么单独一张卡**:一开始放在「板子状态」卡里,
> 结果 `fetchStatus` 失败时会 `statusCard.removeAllViews()` ——
> **把连接方式那行一起清掉了**,用户反而看不到"到底哪条链路通" ✅
> 实测踩过,所以拆出来 ✅

**每 5 秒自动刷新**(挂在 1 秒的 UI 节拍上,每 5 次做一次)✅
**检测在后台线程**(WiFi 探测要等超时,不能卡界面)✅

# 三、上报服务器

## 接口

```
POST /api/v1/app/link
  { boardMac, deviceId, mode, hid }
```

`mode` 取值:`ble` / `usb` / `wifi` / `ble+wifi` / `usb+wifi` / `none`

## 数据落到 `boards` 表

```sql
ALTER TABLE boards
  ADD COLUMN link_mode VARCHAR(16),   -- 当前怎么连的
  ADD COLUMN link_hid  VARCHAR(64),   -- HID 设备名
  ADD COLUMN link_by   VARCHAR(64),   -- 哪个手机报的
  ADD COLUMN link_at   DATETIME;      -- 最后上报时间
```

## ⚠️ 坑:App 拿不到板子 MAC,就永远报不上去

**死循环**:要报连接方式 → 需要板子 MAC → 读 MAC 要连上板子 → 连不上 ✅

**解法两层:**

**① 缓存 MAC** —— 每次成功读到板子就把 MAC 存本地,以后读不到也能用 ✅

**② 从蓝牙 MAC 推**(兜底)✅

ESP32 约定:**WiFi MAC 和 BT MAC 相邻** ✅ 实测这块板:
```
WiFi  28:84:85:89:78:C8
BT    28:84:85:89:78:C9      ← 正好差 1
```

```java
// 已配对设备能拿到真实地址(Android 6+ 对非配对设备会返回 02:00:...)
String addr = bluetoothDevice.getAddress();      // 28:84:85:89:78:C9
return minusOne(addr);                            // → …78:c8
```

## ③ 又一个坑:Android 12+ 要 `BLUETOOTH_CONNECT`

`getBondedDevices()` / `getName()` / `getAddress()` 在 **API 31+** 都需要
**`BLUETOOTH_CONNECT` 运行时权限** ✅ 没有就抛 `SecurityException` ✅
被 `catch` 吞掉之后**什么都没发生** ✅ 查了半天 ✅

```xml
<!-- 老系统用这两条 -->
<uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN" android:maxSdkVersion="30" />
<!-- Android 12+ 用这条,而且要**运行时申请** -->
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
```

> **教训:被 catch 吞掉的 SecurityException 最难查。**
> 以后凡是"读系统信息失败但没报错"的,先怀疑权限 ✅

# 五、下一步(第二步)

**BLE 控制通道** —— 让 App 能**通过蓝牙**读写板子,彻底不依赖 WiFi。

要做:
1. 固件在 BLE 上新增**自定义 GATT 控制服务**(RX 写 / TX 通知)
2. **分片传输**(BLE MTU 有限,流程脚本可能几 KB)
3. App 端加 **BLE 传输层**
4. 让用户能选「控制走蓝牙还是 WiFi」

做完之后你的设想就完整了:
- **选蓝牙** → 触摸 + 控制都走蓝牙,手机不用连板子 WiFi ✅
- **选 WiFi** → 都走 WiFi(带宽大,适合传长流程)✅
- **USB 直插** → 触摸走 USB,控制走 WiFi(或以后也走 USB CDC)✅
