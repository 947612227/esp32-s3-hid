# 智能等待(waitfor)怎么用 + 页面识别为什么之前不好用

## 先说结论:之前不是你不会用,是**功能本身有缺陷**

你反馈的两个现象:

> 打开大麦的主页显示的是 MainActivity,切换到我的页面还是 MainActivity,
> 有时候是别的,来回切换页面都不会变得

**全是真的,而且根因有三层。**

---

# 第一层:大麦是「单 Activity + Fragment」架构

大麦的「首页」和「我的」是**同一个 Activity 里的两个 Fragment** 切换的。

所以 `cn.damai.homepage.MainActivity` **一直是这个值 —— 技术上完全正确,但对"识别页面"毫无用处**。

> **现代 App 大量这么设计**(微信、淘宝、大麦…),光看 Activity 名根本分不出页面。

---

# 第二层:页面文字里大部分是**共用的**

我把页面文字也读出来了,结果发现:

```
北京 / 搜索 / 证照信息 / 世你·万圣之夜 / 首页 / 影院·场馆 / 大麦VIP / 发现 / 我的
└顶栏┘                    └推荐内容┘      └────── 底栏页签(每页都一样!)──────┘
```

**只有中间那块推荐内容在变** —— 而底栏页签、顶栏城市**每页都有**。

所以我第一版"取前几段文字当特征"**正好取到这些共用的**,还是分不出来。

---

# 第三层:Event 会把 Activity 名**污染**

```
当前页面:LinearLayout      ← 弹窗/浮层触发 WINDOW_STATE_CHANGED,className 是控件类
```

`WINDOW_STATE_CHANGED` 不只对 Activity 触发,**弹窗、浮层也会** ——
那时候 `className` 是 `LinearLayout` / `FrameLayout` 这种控件类,
把 Activity 名覆盖掉了。

> 这就是你说的"**有时候是别的**"。

---

# 修了什么

## ① Activity 名只认"像 Activity 的"

```java
if (nv.endsWith("Activity") || nv.endsWith("ActivityAlias")) {
    sAct = nv;   // 其它一律不认(LinearLayout 之类会被过滤掉)
}
```

## ② 页面变化检测不再只看 Activity

**任何**窗口/内容变化都标记"脏",然后重算「页面特征」:

```java
public static void refreshIfDirty() {
    String txt = pageText(inst, 28);
    String sig = sAct + " | " + txt;
    if (!sig.equals(sSig)) { sSig = sig; sRev++; }   // 特征变了 → 立刻推给板子
}
```

## ③ 悬浮窗现在显示**页面文字**(不只有 Activity)

```
🔍 触摸注入板 · MainActivity · 我的订单 / 抢票预约 / 优惠卡券 / 我的票夹
```

**一眼就能看出页面变了。**

---

# 最关键的改进:帮你找出「本页独有的词」

既然页面文字大部分是共用的,那怎么知道该拿哪个词当关键字?

**办法:记住上一次的词集,新出现的标 ⭐。**

## 用法(三步)

```
① 在大麦【首页】点悬浮窗的 🔍
   → 列出首页所有词(第一次没有 ⭐)

② 切到大麦【我的】,再点 🔍
   → ⭐ 标出「上一页没有、只在本页出现」的词

③ 点任意一个 ⭐ 词
   → 自动把整行 waitfor 复制到剪贴板,粘到流程里就能用
```

## 实测效果

在【我的】页点 🔍:

```
当前页面:MainActivity
⭐ = 上一页没有、只在本页出现的词 —— 推荐用它当关键字

⭐[我的订单]  ⭐[关注]      ⭐[粉丝]      ⭐[获赞]
⭐[现场足迹]  ⭐[纪念票]    ⭐[待授权]    ⭐[立即升级]
⭐[优惠卡券]  ⭐[抢票预约]   ⭐[想看]      ⭐[我的票夹]
⭐[查看更多票]

 [首页] [影院·场馆] [大麦VIP] [发现]      ← 没有 ⭐
```

**⭐ 的正是本页独有的**(`抢票预约` 就是抢票要用的那一页);
**没 ⭐ 的是两页都有的**(`首页 / 大麦VIP`…)—— **用了会误判**。

点 `⭐抢票预约` → 剪贴板里就是:

```
waitfor 抢票预约 8000 等「抢票预约」出现
```

**直接粘到流程里就行了。**

# waitfor 完整用法

## 基本语法

```
waitfor <关键字> [超时ms] [备注]
```

| 部分 | 说明 |
|---|---|
| **关键字** | 页面上的一个词,或 Activity 短名;包含匹配、忽略大小写 |
| **超时ms** | 最多等多久,**默认 15000**(15 秒) |
| **备注** | 超时后面随便写,只为了让脚本好读(不参与匹配) |

## 三种关键字写法

| 写法 | 匹配什么 | 例子 |
|---|---|---|
| 普通文字 | **页面文字** 和 **Activity 名** 都找 | `waitfor 抢票预约 8000` |
| `@` 前缀 | **只**匹配 Activity | `waitfor @NcovSkuActivity 8000` |
| Activity 短名 | 不用写全包名 | `waitfor ProjectDetail 8000` |

## 行为

- **匹配到** → 立刻继续(日志写"页面已出现,等了 0 ms")
- **超时** → **继续往下走,不报错**(日志写"超时,继续执行")

> 设计成"超时不报错",是因为写脚本的人通常是"**希望**等到",
> 而不是"**必须**等到" —— 硬失败会让整个流程断掉。

# 一个完整例子

```
# 等大麦首页(开屏广告期间会一直等)
waitfor homepage 15000 等大麦首页

# 按页面分岔:在首页才点
ifpage homepage
    T 0.919 0.908 30 点右下角「我的」
else
    wait 1 不在首页,跳过(避免点错)
endif

# 等「我的」页 —— 用 ⭐ 挑出来的关键字
waitfor 抢票预约 8000 等抢票预约入口出现
ifpage 抢票预约
    T 0.639 0.403 30 点「抢票预约」
else
    wait 1 没进「我的」,跳过
endif

# 等预约票档页
waitfor NcovSkuActivity 10000 等预约票档页
T 0.622 0.912 40 点「立即预订」
```

**核心思路**:

| 写死 wait | 用 waitfor |
|---|---|
| `wait 3000` 猜页面加载完了 | 等到页面**真的**出现 |
| 页面慢 → 点空 | 页面没到就等 |
| 页面不对 → **点到别的地方** | `ifpage` 判断,**不对就跳过,绝不乱点** |

# 排查清单:waitfor 不生效怎么办

| 现象 | 检查 |
|---|---|
| 悬浮窗没有 🔍 那一行 | **页面识别没开** → 设置 → 页面识别 |
| 设置里显示"已开启"但没反应 | **MIUI 绑定卡死** → **重启手机** |
| 悬浮窗的页面文字**一直不变** | App 被杀了 → 看有没有常驻通知(前台服务) |
| 关键字匹配不上 | 用 🔍 挑 **⭐ 的词**;别用底栏页签那种共用的词 |
| 板子收不到页面 | 看板子 `/api/page` → `act` 和 `text` 有没有值 |

# 教训

## 1. **"单 Activity + Fragment" 让 Activity 名失去意义**

做页面识别,"当前 Activity" 这个信号**在现代 App 上基本没用**。
必须结合**页面内容**。

## 2. **页面内容里大部分是共用的**

底栏页签、顶栏城市、状态栏……**每页都有**。
直接"取前 N 段文字"会取到这些没用的。

**要么做差异(⭐ 方案),要么让用户自己挑。**

## 3. **同一个 Event 会为不同东西触发**

`WINDOW_STATE_CHANGED` 也会为弹窗/浮层触发,
`className` 那时候是控件类 —— **不能无条件当真**。

## 4. 用户的"偶现/有时候"往往有确定的原因

"有时候是别的"→ className 被污染 ✅
"切来切去都不变"→ 只比 Activity + onPause 停了推送 ✅

**每一个模糊的描述背后都是一个具体的 bug,去把它挖出来。**
