# 坐标精度问题 + 一个藏得深的 bug

## 你问的:`0.923 0.911` 保存后变成 `0.9230 0.9110`,有问题吗?

**没有问题,零精度损失。**

### 证明

```python
strtof("0.923")  ==  strtof("0.9230")     # 解析出的是同一个 float
0.923f * 32767   ==  0.9230f * 32767      # 都是 30244
像素位置          ==  996.840             # 一模一样
```

实测数据:

| 写法 | 解析出的 float | 发给内核 | 像素 |
|---|---|---|---|
| `0.923` | 0.923 | **30244** | 996.840 |
| `0.9230` | 0.923 | **30244** | 996.840 |

**为什么显示会变**:板子把脚本**重新序列化**给 App/网页看时用了 `%.4f`
(4 位小数),所以 `0.923` 被补成 `0.9230`。纯粹是**格式化**,不影响执行。

## 但顺手做了两件事

### ① 去掉多余的 0(让"写什么读什么"一致)

```cpp
// 0.9230 → 0.923 · 0.2000 → 0.2 · 0.0000 → 0.0
static void trimTrailingZeros(char *s);
```

**踩到的坑**:第一版没生效 —— `memmove` 之后指针 `q` 已经失效,
结果 `0.5` 处理了、`0.2500` 没处理。改成删除后从 `keepEnd` 继续。

### ② 🐛 **发现备注会丢**(严重)

`scriptToText()` **完全没输出 `note`** —— 而它就是
`/api/script?index=N` 返回的 `text`。后果:

- **App 打开流程编辑 → 备注丢失 → 一保存就没了**
- 网页「编辑」/「复制」同样丢备注

已修:`out += " " + st.note`。

### 往返实测

```
写入                      读回
T 0.923 0.911 60 点我的 → T 0.923 0.911 60 点我的      ✅
wait 300 等加载        → wait 300 等加载             ✅
T 0.5 0.25 60          → T 0.5 0.25 60               ✅
S 0.5 0.75 0.5 0.25 260 上滑 → 原样                  ✅
K 40 回车键             → K 40 回车键                  ✅

```

**唯一差异**:`50%` 被规范化成 `0.5` —— 这是**故意的**(板子内部统一按归一化存),
两者**数值完全相同**,而且备注「百分比写法」保留了 ✅

## 网页版流程复制:自动避重

原来网页用 `prompt()` 让用户填名字,而板子的 `/api/save` 是**同名即覆盖** ——
填错了会**覆盖已有流程**。

现在:

```js
function uniqueCopyName(base, existing) {
  // 「XX 副本N」先摘掉后缀,避免「XX 副本 副本2」
  const m = base.match(/^(.*?) 副本\d*$/);
  if (m) base = m[1];

  let cand = base + ' 副本';
  if (!existing.includes(cand)) return cand;
  for (let i = 2; i < 100; i++) { ... }
}
```

**两层保护**:
1. `prompt` 的默认值就是算好的不重名
2. 用户如果手动改成已存在的名字 → **再自动避重一次**,不覆盖

实测:

| 操作 | 结果 |
|---|---|
| 复制「大麦」 | → `大麦 副本4` |
| 复制「大麦 副本」 | → `大麦 副本4`(摘掉旧后缀再编号) |
| 复制「大麦 副本2」 | → `大麦 副本4` |
