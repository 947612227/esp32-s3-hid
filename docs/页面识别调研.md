# 调研:App 能知道大麦当前在哪个页面吗?

> 你提到"Windows 编程上有页面句柄" —— Android 上确实有等价物,而且信息比 HWND 更丰富。
> 本文全部结论都基于**真机实测**(小米 8 / Android 10 / 大麦 cn.damai)。

## 结论

**能,而且比 Windows 的窗口句柄给得更多。**

| Windows | Android 等价物 |
|---|---|
| `GetForegroundWindow()` → HWND | `dumpsys window` 的 `mCurrentFocus` |
| 窗口类名 (`FindWindow("Notepad")`) | **Activity 全类名** |
| 控件 ID (`GetDlgItem(h, IDOK)`) | **`resource-id`(如 `title_tv`)** |
| `GetWindowText()` | 控件的 `text` |
| 遍历子控件 | 完整 View 树(实测一页 77 个带 id 的控件) |

**但有个前提**:普通 App **拿不到**(Android 沙箱隔离),
必须走下面两条路之一 👇

## 四条技术路线对比

| 路线 | 能拿到 | 需要什么 | 适合我们吗 |
|---|---|---|---|
| **① AccessibilityService**(无障碍) | 包名 + Activity + 完整控件树 + 文本 | 用户手动开一次无障碍 | ✅ **唯一可行** |
| ② `UsageStatsManager` | **只有包名**,没有页面 | `PACKAGE_USAGE_STATS` 特殊权限 | ❌ 粒度不够 |
| ③ `ActivityManager.getRunningTasks()` | 自己的任务 | — | ❌ Android 5+ 已废弃 |
| ④ adb `dumpsys` / `uiautomator` | 全部 | **要 root 或连电脑** | ❌ 手机上的 App 用不了 |

**结论:要用 ① 无障碍服务(AccessibilityService)。**

### AccessibilityService 能给什么

```java
// ① 页面切换事件 → Activity 类名 + 包名
@Override public void onAccessibilityEvent(AccessibilityEvent e) {
    if (e.getEventType() == AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED) {
        String pkg = e.getPackageName().toString();   // cn.damai
        String act = e.getClassName().toString();     // ...NcovSkuActivity
    }
}

// ② 当前页面的完整控件树
AccessibilityNodeInfo root = getRootInActiveWindow();
// root.getChild(i) 递归遍历,每个节点有:
//   getText()              → "预约想看票档"
//   getViewIdResourceName() → "cn.damai:id/tv_price_name"
//   isClickable()           → true/false
//   getBoundsInScreen()     → 屏幕坐标!
```

**注意最后一条**:节点自带**屏幕坐标** ——
也就是说,无障碍不光能"看",还能直接告诉你**该点哪儿**,
甚至可以 `performAction(ACTION_CLICK)` **直接点**,完全不用 HID 注入。

> 但我们**不建议**改成那样:
> 无障碍的 `ACTION_CLICK` 对 Flutter/游戏/自绘控件经常无效,
> 而 HID 注入是**系统级真实触摸**,通用性强得多。
> 定位用无障碍,**点击还是用 HID** —— 两者配合最好。

## 用起来能解决什么(对我们这个项目)

现在的流程是**盲点**:`wait 3000` 猜页面加载完了,然后按坐标点。
页面慢一点/改版一点,就点空。

有了页面识别,可以:

### ① 等待页面就绪(替代写死的 wait)

```
等待页面 NcovSkuActivity 超时 10s
点击 抢票预约
```

比 `wait 3000` 可靠得多 —— 快的时候 800ms 就走,慢的时候等到 10 秒。

### ② 校验后再点(避免点空)

```
等待文字 王源
等待文字 可预约
点击 抢票预约
```

### ③ 识别登录失效,直接报错

```
如果是页面 LoginActivity
    中止 "登录已失效,请先登录"
```

比现在"点了没反应,不知道为啥"清楚一万倍。

### ④ 抢到没有,程序能知道

```
等待文字 抢票成功 超时 30s
如果是页面 OrderConfirmActivity
    日志 "已进入订单页"
```

### ⑤ 条件分支

```
如果是页面 NcovSkuActivity
    点击 0.5 0.9
否则
    中止 "不在预约页"
```

## 成本与风险

| 项 | 说明 |
|---|---|
| **用户操作** | 要在系统设置里手动开启无障碍(一次性) |
| **权限提示** | 开启了无障碍的 App,部分银行/支付类会拒绝运行 —— 建议**用完能关** |
| **小米/MIUI** | 无障碍可能被"省电策略"杀掉,需要加白名单 |
| **大麦改版** | `resource-id` 会变 —— 但比坐标稳,至少能一眼看出"锚点没了" |
| **自绘/Flutter 页面** | 拿不到 `resource-id`,只能靠文字 —— 仍然比坐标强 |
| **合规** | 无障碍权限敏感,**必须只用于本机自动化,不做任何数据外传** |

## 建议的实现路径

**分两步,先做最小可用版:**

### 第 1 步:页面识别 + 日志(不改脚本语法)

- App 加一个 `AccessibilityService`
- 悬浮窗和日志里**实时显示**:`当前页面:大麦 / NcovSkuActivity`
- **流程日志里也记一笔**:每步执行前记录当时在哪个页面
  → 出问题时能一眼看出"第 3 步的时候页面还停在详情页"

**这一步零风险**(不改执行逻辑),但排障价值极大。

### 第 2 步:加两条脚本指令

```
waitfor <文字|activity> [超时ms]     # 等到出现再继续
ifpage  <activity> ... endif         # 页面分支
```

配合现有引擎扩展,不用推翻任何东西。

## 复现命令(你自己也能验)

```bash
# 当前页面是哪个 Activity
adb shell dumpsys window | grep mCurrentFocus

# 页面上有什么(文字 + resource-id + 坐标)
adb shell uiautomator dump /sdcard/o.xml && adb pull /sdcard/o.xml .
```

> 这两条命令对应 App 里无障碍服务能拿到的**同一份数据** ——
> 我只是用 adb 把"无障碍能看到什么"提前展示出来了。
