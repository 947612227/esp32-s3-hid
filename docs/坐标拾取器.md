# 坐标拾取器

**不用再心算比例 —— 在目标 App 里点哪儿,坐标就是哪儿。**

## 一、先说清楚「录制」的原理与边界

你见过的"录制"功能,绝大多数用的是 **无障碍服务(AccessibilityService)**:

| 能力 | 无障碍服务 | 普通悬浮窗(我们用的) |
|---|---|---|
| 读到界面元素(文字/位置/大小) | ✅ | ❌ |
| 知道你在别的 App 里点了什么 | ✅ | ❌ |
| 拿到**任意位置**的坐标 | ⚠️ 只能拿元素位置 | ❌ |
| "边正常用 App 边录" | ✅ | ❌ |

**关键限制**:Android **不允许普通 App 观察"发给别的 App 的触摸"**。
所以"一边正常用、一边把每次点击录下来",**没有无障碍或 root 做不到**。

## 二、我们用的办法:临时取点层

需要取坐标时,盖一层**可触摸的全屏透明窗口**,你点哪儿就记哪儿,
取完自动消失。

**代价**:这一次点击会被取点层拿走,**不会下发给下面的 App**
(所以是"取完再返回",不是"边用边录")。

**正确用法**:
```
① 先在目标 App 里翻到那一页
② 点悬浮窗上的 📐
③ 点你要的位置  → 坐标到手,并自动复制到剪贴板
```

## 三、悬浮窗上多了个按钮

```
[⠿] [📐] [◀]
 │    │    └─ 收起
 │    └────── 拾取坐标(新增)
 └─────────── 拖动
```

拾取后在悬浮窗面板里会显示:
```
📱 大麦
📍 已拾取:0.833 0.777(已复制)
```

## 四、在流程编辑器里直接用

参数编辑页会自动列出最近拾取到的点,**点一下填入**:

```
S 直线滑动(x1,y1,x2,y2)
──────────────────────────────
X 坐标        0.500
[────●───────────────────]
Y 坐标        0.750
...
从悬浮窗 📐 拾取到的坐标(点一下填入)
[📍 第1个点:0.741 0.648 (74.1%, 64.8%)]
[📍 第2个点:0.278 0.259 (27.8%, 25.9%)]
[清空拾取记录]
──────────────────────────────
将要插入的这一行:
S 0.740 0.647 0.277 0.259 300
```

条数按指令需要自动匹配:`T/D/H` 只给 1 个点,`S/P` 给 2 个,`C` 给 3 个。

**拾取记录是持久化的**(存 SharedPreferences),App 重启不丢 ——
因为"先去目标 App 取点、再回来编辑流程"中间很可能要切来切去。

## 五、实测验证(闭环)

**取点准确性**:

| 操作 | 结果 |
|---|---|
| 点屏幕 (900, 1800) | 拾取到 `0.833 0.777`(= 900/1080, 1800/2316)✅ |
| 点屏幕 (800, 1500) | 拾取到 `0.741 0.648` ✅ |
| 点屏幕 (300, 600) | 拾取到 `0.278 0.259` ✅ |

**和板子的注入闭环**:

```
拾取 0.833, 0.777  →  板子执行 tap
                  →  内核收到 X=27295(83.3%) Y=25460(77.7%)
                  →  换算回像素 (900, 1800)  ← 与拾取位置完全一致 ✅
```

**填入流程**:

| 操作 | 预览 |
|---|---|
| 初始 | `S 0.500 0.750 0.500 0.250 300` |
| 点「第1个点」 | `S 0.740 0.647 0.500 0.250 300` |
| 点「第2个点」 | `S 0.740 0.647 0.277 0.259 300` ✅ |

## 六、踩到的两个坑(都挺隐蔽)

### 坑 1:取点层的"高度"不等于屏幕高度

一开始用 `e.getX()/v.getWidth()` 归一化,结果点屏幕 y=1800 算出来是 **0.817**,
而正确值是 0.777。

原因:这层窗口被状态栏挤掉一截,**窗口高度 ≠ 屏幕高度**。
而且 `getResources().getDisplayMetrics()` 在悬浮窗上下文里返回的是
**去掉状态栏+导航栏的内容区**(2088),不是整屏(2316)。

**修法**:用 `getRawX/getRawY`(屏幕绝对坐标)+ **真实屏幕尺寸**
(`getMaximumWindowMetrics()` / `getRealMetrics()`)。

> 这点特别重要:板子的触摸注入是按**整屏**归一化的,两边必须用同一个基准。

### 坑 2:`finish() + startActivity()` 会把参数重置

填入拾取坐标后想刷新滑块,图省事用了"重启 Activity"。结果新 Intent 里
没有新值,参数被重置回默认。

**修法**:原地刷新 —— 记住所有 SeekBar 和它们的刷新动作,填入后
`setProgress()` + 重绘 + 更新预览。

## 七、实现位置

| 文件 | 职责 |
|---|---|
| `CoordPicker.java` | 取点层 + **持久化**的拾取历史 |
| `FloatingWindow.java` | 📐 按钮、结果显示、自动复制到剪贴板 |
| `CmdParamActivity.java` | 「从拾取填入」快捷 + 原地刷新 |

## 八、如果以后想要"真录制"

需要加一个 **AccessibilityService**(无障碍服务):
- 需要在系统设置里手动开启
- 能读到界面元素,可以**按文字锁定目标**(比坐标更抗界面变化)
- 能做"录制点击序列"

代价是要申请无障碍权限、代码量也大得多。当前这套"按坐标 + 取点器"
已经能覆盖大部分固定界面的场景。
