## 0. 这套系统是什么

```
        ┌──────────────────────────────┐
        │  控制中心(阿里云)           │
        │  120.55.183.206              │
        │  · MySQL 存台账              │
        │  · 固件 OTA 分发             │
        │  · APK 分发                  │
        │  · 网页看板 + 账号            │
        └───────▲──────────────▲───────┘
                │              │
     心跳/拉固件│              │查更新/上报
                │              │
        ┌───────┴──────┐  ┌────┴─────────┐
        │  ESP32-S3 板子│  │  安卓手机 App │
        │  (HID 触摸屏) │  │              │
        └───────┬──────┘  └────┬─────────┘
                │              │
                │ BLE HID      │ WiFi 局域网
                │ (注入触摸)    │ (推页面/读状态)
                ▼              ▼
        ┌──────────────────────────────┐
        │        被控手机               │
        │  (大麦 / 任意 App)            │
        └──────────────────────────────┘
```

**三个部分,各司其职:**

| 部分 | 干什么 | 必需吗 |
|---|---|---|
| **ESP32 板子** | 被手机识别成**真触摸屏**,按脚本注入点击/滑动 | ✅ 必需 |
| **手机 App** | 录流程、看日志、坐标拾取、悬浮窗、定时 | 强烈建议 |
| **控制中心** | 多设备台账、固件/APK 远程分发 | 可选 |

> **只用板子也能跑**:板子有网页控制台,不用装 App。
> App 和控制中心是"更好用"的加成。

### 它解决的唯一问题

安卓上**不能用鼠标那种"绝对坐标"**去点屏幕(会变成光标,不会触发触摸事件)。
必须伪装成一个**真正的触摸屏**,让系统把坐标当"手指落在屏幕上"处理。

本工程做的就是这件事 —— 用 ESP32-S3 模拟 HID 触摸屏,并配一套脚本引擎。

### 用途边界

这是个**通用的触摸注入工具**,按你录的坐标点击。
**请在你自己的设备和你自己的账号上使用。**

## 1. 快速开始

最短路径,四条命令:

```bash
# ① 编译并烧录固件(插上板子)
pio run -e ble -t upload

# ② 编译手机 App
cd android-app && ./build.sh

# ③ 装到手机
adb install -r build/触摸注入板.apk

# ④ (可选)部署控制中心
cd ../server && SSHPASS=<服务器密码> ./tools/deploy.sh
```

然后:

1. 手机 **蓝牙** 配对板子(板子叫 `ESP32S3 Touch HID`)
2. 打开 App → 允许**悬浮窗权限**
3. App 里 → **选择 APP**(要操作的目标,如大麦)
4. 悬浮窗点 **📐** 拾取坐标 → 新建流程把它们串起来
5. 点 **运行**

## 2. 硬件

| 物料 | 说明 |
|---|---|
| **ESP32-S3 开发板** | 需 **8MB Flash + PSRAM**(N8R8 或 N16R8) |
| USB 数据线 | 要能传数据,不是纯充电线 |
| 被控手机 | Android 10+(蓝牙要支持 BLE HID) |

**接线本身不需要** —— 板子只用 USB 供电 + 蓝牙通信,不用往手机接任何线。

> ⚠️ 板子有**两个 USB 口**:
> - **原生 USB 口**(右侧)→ 固件下载走这个,设备名 `usbmodem1101` / `usbmodem101`
> - **CH343/UART 口**(左侧)→ 串口日志走这个
>
> 本工程配置了 `ARDUINO_USB_CDC_ON_BOOT=0`,所以**原生 USB 口上没有 Arduino 的 `Serial` 输出**。
> 想看串口日志要接左边的口。**原生口只能看到 ESP-IDF 自己的日志。**

## 3. 固件:编译 / 烧录 / 无线升级

### 3.1 环境

```bash
pip install platformio        # 或 brew install platformio
```

### 3.2 三个编译环境

| 环境 | 用途 |
|---|---|
| `ble` | **蓝牙版(推荐)** —— 板子做 BLE HID 触摸屏 |
| `usb` | USB 版 —— 板子插线当触摸屏(少了蓝牙的兼容问题) |
| `usb_touchtest` | 自测用 —— 上电跑一段演示手势 |

```bash
pio run -e ble                      # 只编译
pio run -e ble -t upload            # 编译 + 烧录
pio device monitor -b 115200        # 看串口(要接 CH343 口)
```

### 3.3 配置(`secrets.h`)

```c
#define WIFI_SSID   "你家 WiFi 名"
#define WIFI_PASS   "密码"
#define AP_SSID_PREFIX "ESP32-Touch"     // 连不上时开的热点名
#define AP_PASS     "12345678"           // 至少 8 位

// 控制中心(可选,留空就不上报)
#define SERVER_URL    "http://120.55.183.206"
#define SERVER_TOKEN  "board_xxxxx"
#define HEARTBEAT_MS  (60UL * 60UL * 1000UL)   // 心跳间隔,默认 1 小时
```

> `secrets.h` 已加进 `.gitignore`,**不会进版本库**。
> 模板见 `secrets.example.h`(复制成 `secrets.h`)。

⚠️ **`secrets.h` 里编译进去了 WiFi 明文密码**。给别人固件前记得改掉。

### 3.4 版本号(OTA 用)

```ini
# platformio.ini
build_flags =
    -DFW_VERSION=\"1.0.0\"      ← 每次发新版改这里
```

**板子据此和服务器比对,决定要不要提示升级。**

### 3.5 无线升级(OTA)

**升级固件不用插 USB。**

```bash
tools/ota.sh                    # 默认 192.168.5.37
tools/ota.sh <板子IP>
```

流程:编译 → HTTP 上传 → 板子写进备用分区 → 重启(约 3~25 秒)。

| 项 | 说明 |
|---|---|
| 原理 | 双 app 分区(`ota_0`/`ota_1`),新固件写空槽,重启切换 |
| **流程会不会丢** | **不会** —— 升级不碰脚本文件系统 |
| 注意 | 升级中别断电;固件不能超过 3MB(现在约 1.2MB) |

**从控制中心升级**(推荐,多设备时):

1. 本地改 `FW_VERSION` → 编译
2. 看板上传固件,或:
   ```bash
   curl -u admin:<密码> -X POST http://120.55.183.206/admin/api/firmware \
     -F "file=@.pio/build/ble/firmware.bin" -F "version=1.1.0" \
     -F "channel=stable" -F "notes=更新说明"
   ```
3. 等板子下次心跳(或重启板子强制心跳)
4. **App 上会显示「板子固件 1.0.0 → 1.2.0」**
5. 点那行 → 弹确认框 → **「开始升级」** → 板子自己去服务器下载、写入、重启

> App 里点「开始升级」走的是 `POST /api/ota/from-server` ——
> **板子自己去控制中心拉固件**,边下边写,流式不占内存。

**⚠️ 版本号要对上**:`platformio.ini` 里的 `FW_VERSION` 必须和服务器上标注的版本一致,
否则板子会**反复提示升级**(它以为自己还是旧的)。

> **板子不自动升级** —— 避免打断正在跑的抢票流程。

## 4. 板子首次配网

### 正常情况:什么都不用做

板子出厂时 `secrets.h` 里编译了你家 WiFi,上电自动连。

### 换了网络 / 首次到新地方

```
板子上电
  ├─ 试 NVS 里存的凭据(你在 App 里配过的)
  ├─ 试编译期默认凭据(secrets.h)
  └─ 都失败 → 开热点 ESP32-Touch-XXXX / 密码 12345678
                    ↓
             手机连这个热点 → App 自动发现板子(在 192.168.4.1)
                    ↓
             App 里填新 WiFi → 板子切过去,热点关掉
```

**板子自己的热点名**取 MAC 后两位。注意:**WiFi MAC 和蓝牙 MAC 差 1**
(例:热点 `ESP32-Touch-5E40`,蓝牙显示 `5e:41`)—— 这是 ESP32 的正常行为。

### 忘掉当前 WiFi

```bash
curl -X POST "http://<板子IP>/api/system?op=forgetwifi"
```

或者网页控制台 →「忘记 WiFi(进热点模式)」。

## 5. 手机 App

### 5.1 编译安装

```bash
cd android-app
./build.sh                 # 产出 build/触摸注入板.apk
./build.sh --install       # 顺便 adb 安装
```

**不需要 Gradle / Android Studio** —— 脚本直接用 SDK 的 `aapt2` + `javac` + `d8` + `apksigner`。

### 5.2 需要哪些权限

| 权限 | 用途 | 怎么给 |
|---|---|---|
| **悬浮窗** | 悬浮窗、坐标拾取 📐 | 首次会引导跳系统设置 |
| 网络 | 连板子 | 安装时自动 |
| **无障碍**(可选) | 页面识别 | 设置 → 页面识别 → 点进去开 |
| 查其他应用 | 选目标 App | 安装时声明 |

**蓝牙不需要 App 权限** —— 那是系统层面配对板子。

### 5.3 界面

| 页签 | 内容 |
|---|---|
| **状态** | 板子信息、HID 状态、固件版本、维护按钮 |
| **流程** | 流程列表(可复制/编辑/删除)、新建 |
| **控制** | 底部三键、音量、屏幕开关、滑动 |
| **手势** | 常用手势快捷触发 |
| **日志** | 板子运行日志(含人类语言步骤) |

### 5.4 新建一个流程

1. **流程** 页 → **新建流程**
2. 两种编辑方式(可来回切):
   - **可视化**:点指令库选指令 → 拖滑块调参数
   - **文本**:直接写脚本
3. 悬浮窗点 **📐** 拾取坐标 → 点一下就能填进参数
4. **保存到板子**(流程存在板子 Flash 上,断电不丢)

### 备注怎么加

**参数后面直接写中文就行**:

```
T 0.923 0.911 60 点我的票
wait 3000 等页面加载
```

日志会显示「**点击:点我的票**」,而不是一串坐标。

**两种写法**(效果一样):

| 方式 | 怎么做 |
|---|---|
| **文本** | 参数后面接中文。规则:第一个不是数字的词开始,后面全算备注 |
| **可视化** | ⛭ 指令库 → 点一条指令 → 滑到底下的「备注(可选)」框 → 插入 |

> 编辑器里那行黄色 `💬 备注:…` 点开有完整说明。
> **不写也完全可以**,只是日志显示坐标而已。
> **编辑流程时备注不会丢。**

### 5.5 悬浮窗

把柄是竖排 **5 个按钮**:

| 按钮 | 作用 |
|---|---|
| `⠿` | **拖动**(只能从这个拖) |
| `🙈` | **暂时隐藏** 15 秒(开屏广告挡住跳过按钮时用) |
| `📐` | **坐标拾取** —— 在真实界面点哪儿取哪儿 |
| `🔍` | **复制页面句柄**(贴进 `ifpage` 用) |
| `◀` | **收到边框**,只剩 `📋`,点它弹回来 |

> **面板本身不可触摸**(`FLAG_NOT_TOUCHABLE`)——
> 否则板子注入的点击会被它吃掉,流程就点空了。

### 5.6 定时

**流程** 页 → 某个流程 → **定时…**

| 模式 | 说明 |
|---|---|
| 不定时 | 只在你点「运行」时执行 |
| 指定时刻 | 到点执行,如 `2026-10-05 19:30:00` |
| 倒计时 | 从现在起 N 时 N 分 N 秒后执行 |

**支持执行次数**(1~99 次)。

> ⚠️ 定时存在**手机 App 的本地设置**里,不在板子上。
> 所以 **App 必须活着**定时才会触发 —— 建议加进 MIUI 后台白名单。

### 5.7 频率(流程自己的属性)

**流程** 页 → 某个流程 → **频率…**

```
频率:大麦app 三星s23                    [取消]  [保存]
─────────────────────────────────────────────────
启用频率
  ✅ 已启用(点一下关闭)
  启用后:这个流程每次被运行/定时触发时,会按下面的配置循环执行。
  不启用 → 运行一次就结束。

每隔多少毫秒重跑一遍    间隔 100    [−] [+]
连续执行多久            小时 0 / 分钟 1 / 秒 0
```

#### ⚠️ 关键:频率**跟着流程走**

| | |
|---|---|
| **这是流程的属性** | 保存在流程的附加信息里,**不是**临时的"开始/停止"会话 |
| **只配置,不执行** | 对话框里**只有「保存」和「取消」**,没有开始/停止 |
| **什么时候生效** | 这个流程被 **「运行」** 或 **定时触发** 的时候 |
| **没启用频率** | 运行一次就结束 |
| **启用了频率** | 按配置循环跑,到时间自己停 |

#### 界面上能看到的

**流程卡片**:
```
○ 大麦app 三星s23                          9 步
  定时:未设置
  🔁 频率:每 100 毫秒 · 连续 1 分 0 秒
```

**点「运行」时的确认框**:
```
确定后:启动该 App → 执行流程
🔁 已启用频率
每 100 毫秒 重跑一遍,连续 1 分 0 秒 后自动停。
由板子计时,App 被杀也会按时停。
```

**悬浮窗**(运行中):
```
🔁 大麦app 三星s23 每 100 毫秒 · 还剩 0:42
```

#### 参数

| 项 | 说明 |
|---|---|
| **启用开关** | 关掉 = 运行一次(默认关) |
| **间隔** | 每 N 毫秒重跑一遍,下限 **10ms** |
| **连续执行多久** | 时/分/秒,**默认 0 时 1 分 0 秒**;都可输入、可 − / + |
| **三个都填 0** | 不限时长,跑到你点「停止」 |

> 💡 「间隔」只是**两次执行之间的最小间隔** ——
> 流程本身耗时更长时会连续执行,**不会报错**。
> 实测:间隔 100ms + 流程耗时 20s → 实际就是背靠背跑。

**⚠️ 时长控制在板子侧** —— App 被杀掉也会按时停,不会一直点下去。

**实测**:
```
[net] 定时循环已开启:脚本 #1,每 100 毫秒,连续 60 秒
[net] 已开始频率执行:每 100 毫秒一次,连续 60 秒后自动停
[script] 完成:9 步,耗时 20294 ms
[net] 定时循环到时停止(已连续执行 60 秒)     ← 精确 60 秒
```

**停止**:维护页的「停止脚本」会**同时**停掉频率循环
(否则当前这轮停了,下一轮又会被拉起来)。

## 6. 脚本语法(完整指令表)

流程存在板子 `/scripts/<名字>.txt`,**一行一个动作**,`#` 开头是注释。

### 6.1 动作指令

| 指令 | 写法 | 说明 |
|---|---|---|
| 点击 | `T x y [ms]` | 默认 40ms |
| 双击 | `D x y [间隔]` | 默认 90ms |
| 长按 | `H x y [ms]` | 默认 900ms |
| 直线滑 | `S x1 y1 x2 y2 [ms]` | 默认 220ms |
| 曲线滑 | `C x1 y1 cx cy x2 y2 [ms]` | 二次贝塞尔,`cx cy` 是控制点 |
| 双指滑 | `P x1 y1 x2 y2 [间距] [ms]` | 两指同步滑 |
| 捏合 | `Z cx cy 起始间距 结束间距 [ms]` | 大→小是捏合 |
| 按键 | `K usage` | USB HID usage(⚠️ Android 上不生效) |
| 多媒体 | `V usage` | 如 `V 233`=音量+ |
| 等待 | `wait ms` | 暂停 |

### 6.2 流程控制

| 指令 | 写法 | 说明 |
|---|---|---|
| 重复 | `repeat n` | **把其后所有步骤整体重复 n 次** |
| 跳转 | `goto label` | 跳到 `#label` 位置 |

> `goto` 有 1024 步保护,死循环会报错退出。

### 6.3 页面条件(需要开「页面识别」)

| 指令 | 写法 | 说明 |
|---|---|---|
| 等待页面 | `waitfor <关键字> [超时ms]` | 等到页面上出现关键字,默认最多 15 秒 |
| 如果是页面 | `ifpage <关键字>` | 匹配则继续,否则跳到 `else`/`endif` |
| 否则 | `else` | 上一支不成立时走这里 |
| 结束判断 | `endif` | 必须和 `ifpage` 配对 |

**关键字规则**(故意做得宽松):

- **包含匹配**、**忽略大小写**
- 写 Activity **短名**就行(`NcovSkuActivity`)
- 加 `@` 前缀 → **只**匹配 Activity;不加 → Activity 和页面文字都找

```
waitfor 预约想看票档 10000
ifpage NcovSkuActivity
    T 0.5 0.5 60 在预约页点中间
else
    T 0.5 0.9 60 不在预约页点底部
endif
```

> **超时会继续往下走,不报错** —— 设计者可能只是"希望"等到,不是"必须"等到。
>
> **超时位置**:从左往右**第一个纯数字**。所以备注写在超时**后面**:
>
> ```
> waitfor 预约想看票档 10000 等预约页出现
>         └── 关键字 ──┘ └超时┘ └── 备注(忽略)──┘
> ```
>
> ⚠️ **必须开着「页面识别」** `waitfor` 才有意义(板子需要 App 推页面)。
> 而且要保证 App 能在后台活着 —— 见 [帮助 → App 老是被杀]。

### 6.4 坐标三种写法(可混用)

```
T 0.5 0.5        # 归一化(推荐,换分辨率不用改)
T 50% 50%        # 百分比
T 16384 16384    # 逻辑坐标 0..32767
```

### 6.5 备注(可选)

参数**后面**接文字就是备注,日志会显示人类语言:

```
T 0.923 0.911 60 点我的
wait 3000 等页面加载
S 0.5 0.75 0.5 0.25 260 上滑列表
```

执行时输出:

```
[1/3] 点击:点我的
[2/3] 等待:等页面加载
[3/3] 滑动:上滑列表
```

**不写备注也完全可以**,那样显示坐标。

> 规则:从第一个**非数值**的词开始,后面全算备注。
> 所以 `T 0.5 0.5 点我的`(省略 ms)也合法。

### 6.6 完整例子

```
# 双十一抢票流程
waitfor 预约想看票档 10000
ifpage NcovSkuActivity
    T 0.50 0.96 60 抢票按钮
    wait 800 等弹窗
    T 0.50 0.62 60 确认购买
    wait 1500 等订单页
    T 0.50 0.85 60 提交订单
else
    T 0.50 0.96 60 不在预约页,点底部
endif
```

## 8. 日常使用:以抢票为例

### 准备工作(买票前)

- [ ] 板子通电,手机蓝牙**已配对**(显示 HID 就绪)
- [ ] 手机 App 打开,**悬浮窗权限已给**
- [ ] **目标 App 已登录**
- [ ] 想抢的票已加入 **「我的 → 抢票预约」**,并**选好票档**
- [ ] **实名购票人 / 观演人已设置**
- [ ] 确认 App 里没有挡在前面的弹窗(更新提示、活动广告)
- [ ] 手机**别息屏**(把息屏时间调长)
- [ ] 把 App 加进 **MIUI 后台白名单**(不然定时不会触发)

### 录流程

1. 打开目标 App,停在**第一个要点的位置**
2. 悬浮窗 **📐** → 点屏幕上的目标位置 → 自动记下坐标
3. App → **新建流程** → 选指令 → 填入坐标 → **加个备注**(「点我的票」)
4. 需要等待就插 `wait 3000 等页面加载`
5. 页面不确定就加 `waitfor 关键字 5000`
6. **保存到板子**

### 试跑

1. 流程页 → **运行**
2. 看 **日志** 页:每步都会显示「点击:点我的票」
3. **不对就重新拾取坐标**(界面改版/换机型后必须重拾)

### 定时开抢

1. 流程页 → **定时…** → **指定时刻** → 填开抢时间
2. **执行次数** 填 1
3. 保存后把流程改成 **开启** 状态
4. ⚠️ **确认流程是「开启」而不是「暂停」** —— 暂停状态到点不会执行
5. 到点前把手机放好,目标 App 停在首页

### 运行期间

- **别手动碰手机** —— 注入的是绝对坐标,你碰了会打架
- 悬浮窗会显示进度和倒计时
- 要停就在 App 里点停止(悬浮窗上是**长按停止**)

### 屏幕不会息屏(自动的)

手机设置里息屏时间最大只到"分钟"级、**没有"永不"**,所以 App 做了三件事:

| 机制 | 需要权限 |
|---|---|
| **执行时把系统息屏时间临时改成"永不",结束自动改回** | 需要「修改系统设置」 |
| 悬浮窗加 `FLAG_KEEP_SCREEN_ON`(只要可见就压住息屏) | **不需要** |
| 进程被杀后下次启动自动恢复 | — |

**触发条件是"板子在忙"**(跑流程 或 频率循环),
所以 **App 点的 / 网页点的 / 定时触发的 / 频率循环的** 全都覆盖。

设置里能看到状态:

```
执行时保持屏幕常亮
  ✅ 已开启 · 当前系统息屏:10 分钟
```

> ⚠️「修改系统设置」是**特殊权限**,要在系统设置里手动开。
> 没开的话只有悬浮窗那一层兜底(悬浮窗收起来时就压不住了)。

## 9. 排障

### 9.1 板子连不上

| 现象 | 排查 |
|---|---|
| App 显示"连不上板子" | 点 **🔍 自动查找板子**(会自动广播找) |
| 找不到 | 手机和板子**必须同一 WiFi**;**不要用手机热点/流量**;路由器别开「AP 隔离」 |
| 换了网络 | App 会自动重新发现;不行就 `op=forgetwifi` 回热点模式重配 |
| 网页打不开 | 板子 IP 变了 —— 看串口日志,或用自动发现 |

### 9.2 蓝牙连上了但点不动

**判断**:App 状态页看 `HID` 是不是 ✅ 就绪。

| 现象 | 原因 | 解 |
|---|---|---|
| `peers=1 subs=0` | **手机没订阅 HID 通知** | 手机上**取消配对 → 重新配对** |
| 完全没有设备 | 蓝牙没连 | 检查板子蓝牙是否广播中 |
| Android 10 特有 | HOGP 重连后**不会自动重订阅** | 同上,取消配对重来 |

App 状态页有 **「修复蓝牙连接」** 按钮可以一键尝试。

### 9.3 手机弹出的怪提示

| 提示 | 原因 | 解 |
|---|---|---|
| 「是否连入外接键盘」 | 固件 HID **Appearance 写成了键盘**(0x03C1) | 必须是 **0x03C5(Digitizer Tablet)**,已修 |
| 输入法键盘打不开/自己收起 | `SOFT_INPUT_ADJUST_NOTHING` | 已改成 `ADJUST_RESIZE` |

### 9.4 流程点空

| 原因 | 怎么办 |
|---|---|
| 页面还没加载完 | 把 `wait` 改长,或用 `waitfor 关键字 5000` |
| 界面改版 / 换机型 | **重新拾取坐标** |
| 坐标单位不对 | 拾取器用的是**全屏**归一化,和板子一致 —— 别手工换算 |
| 悬浮窗挡住了 | 点 **🙈** 让它让路 15 秒 |

### 9.5 定时不执行

| 检查 | 说明 |
|---|---|
| 流程是**开启**吗 | 暂停状态到点**不会**执行(看板上会显示 ⚠️) |
| **App 还活着吗** | 定时在 App 里,APP 被杀就不触发 → **加 MIUI 白名单** |
| 时间对不对 | 看流程列表的倒计时 |
| 过期了吗 | 过期的流程会变红,且禁止开启 |

### 9.6 页面识别不工作

| 现象 | 排查 |
|---|---|
| 悬浮窗没有 `🔍` 行 | 设置 → 页面识别 → 看是不是"未开启" |
| 显示已开启但不更新 | **MIUI 的无障碍会卡在「正在绑定」** → **重启手机** |
| `waitfor` 一直超时 | App 没在前台/被杀 → 加白名单;确认板子状态页的 `page` 字段有值 |

### 9.7 更新没提示

| 现象 | 说明 |
|---|---|
| App 更新弹窗没出来 | **每天只弹一次**;当天弹过就不再弹 |
| 板子固件更新没显示 | 等板子下次心跳(1 小时),或重启板子强制心跳 |
| 上传了但板子不升 | 检查黑白名单;确认 `FW_VERSION` 和服务器版本不一样 |

### 9.8 服务器 404 / 打不开

```bash
ssh root@120.55.183.206 'systemctl status touchpad-server mysqld'
ssh root@120.55.183.206 'journalctl -u touchpad-server -n 30 --no-pager'
```

**看板页面顶部会弹红色横幅**,直接告诉你哪个接口出了问题。

## 附:这套系统的几个关键设计取舍

| 决定 | 为什么 |
|---|---|
| **BLE 而不是 WiFi 注入** | WiFi 注入要 root;BLE HID 免 root,系统当真实触摸屏 |
| **Appearance = 0x03C5** | 写成键盘(0x03C1)会让输入法弹「是否连入外接键盘」 |
| **脚本跑在板子上** | 手机 App 被杀也不影响执行;板子更稳 |
| **定时存在 App 里** | 要用到手机的通知/前台判断,板子做不到 |
| **板子不自动升级** | 会打断正在跑的抢票流程,必须人工确认 |
| **点击走 HID 不用无障碍** | 无障碍的 `ACTION_CLICK` 对 Flutter/自绘控件经常无效 |
| **`waitfor` 超时不报错** | 设计者可能只是"希望"等到,不是"必须" |
| **面板 `FLAG_NOT_TOUCHABLE`** | 否则注入的点击被面板吃掉,流程点空 |
| **流程存板子 Flash** | 断电不丢;换手机不用重录 |
