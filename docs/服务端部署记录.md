## ⚠️ 80 端口的关键结论:不需要备案

一开始测 80 不通,但**失败耗时只有 0.034 秒** —— 这是「连接被拒(RST)」,
不是「超时」。**安全组拦截会表现为超时。**

后来起了个临时监听器验证:

```
服务器: LISTEN 0 5 *:80  python3
公网访问: HTTP 200   ✅
```

**所以安全组早就放行了,之前不通只是因为没人监听。**

> 排查口诀:**秒拒 = 包到了,没人听;超时 = 被安全组/防火墙拦了。**

## 技术选型(为什么这么做)

| 决策 | 原因 |
|---|---|
| **JSON 文件存储,不用 SQLite** | 服务器只有 `gcc`,**没有 `g++`**,`better-sqlite3` 这类原生模块**编译不了** |
| **Node 16 + Express** | 服务器已有 Node;Python 3.6.8 太旧,跑不了 FastAPI |
| **纯 JS 依赖** | 只有 `express` + `multer`,都无需编译 |
| **systemd 托管** | 和现有 bot 保持一致的模式 |
| **写入用"临时文件 + rename"** | rename 原子,断电不会写出半个文件 |

## 安全设计

| 项 | 措施 |
|---|---|
| 板子/App 鉴权 | `X-Token`(首次启动自动生成,在 `data/config.json`) |
| 管理后台 | HTTP Basic + **cookie 会话** + 页面内嵌会话令牌 |
| **WiFi 密码** | **AES-256-GCM 加密**;密钥在 `data/secret.key`(权限 600) |
| 密码可见性 | **只有** `/admin/api/board/:mac` 返回明文;板子/App 接口看不到 |
| 上传限制 | 固件 8MB / APK 64MB |
| 日志 | **不打 body**,避免密码进日志 |
| 服务隔离 | systemd `NoNewPrivileges` + `PrivateTmp` |

> **诚实说明**:密钥和密文在同一台机器上,服务器被 root 了还是能解。
> 这是"防止数据库文件被顺手看到",不是"防止服务器被攻破"。
> 真要更强,得把密钥放到别的机器 —— 超出本项目范围。

## 踩到的一个坑:浏览器认证 + fetch

测试时看板一直显示"加载中",报:

```
TypeError: Failed to execute 'fetch' on 'Window':
Request cannot be constructed from a URL that includes credentials
```

**原因是我在测试 URL 里写了 `http://admin:pass@host/`** ——
浏览器会**拒绝**用相对 URL 发 `fetch()`。

**真实用户是走浏览器认证弹窗登录的,URL 里没凭据,完全正常。**

不过为了更稳(有些浏览器/隐私模式对 Basic + fetch 处理不一致),
还是加了两层兜底:
1. `Set-Cookie` 会话
2. **看板 HTML 动态注入 `adminSession`**,`fetch` 带 `X-Admin-Session` 头

现在 `http://<ip>/admin/?s=<会话令牌>` 也能直接打开(免弹窗)。
