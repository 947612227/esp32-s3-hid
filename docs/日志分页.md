# 日志分页(每页 50 条)

## 改了什么

后台有**两个**日志类列表,原来都不能翻页:

| 位置 | 原来 | 现在 |
|---|---|---|
| 📋 **日志系统** → 操作审计 | 写死 `LIMIT 200`,只能看最新 200 条 | **分页,每页 50 条** |
| 📊 **数据统计** → 事件明细 | `?limit=30`(上限 200) | **分页,每页 50 条** |

---

## 一、服务端

```javascript
GET /api/admin/audit?page=1&size=50
  → { ok, list, total, page, size, pages }

GET /api/admin/events?page=1&size=50[&mac=xx:xx:...]
  → { ok, events, list, total, page, size, pages }
```

要点:

```javascript
const size = Math.min(Math.max(Number(req.query.size) || 50, 1), 200);
const page = Math.max(Number(req.query.page) || 1, 1);
const offset = (page - 1) * size;
const [c] = await db.q('SELECT COUNT(*) n FROM audit_log');   // 总数要单独查
const list = await db.q(`... ORDER BY a.at DESC LIMIT ? OFFSET ?`, [size, offset]);
```

- **`size` 有硬上限 200** —— 别让 ?size=999999 把内存打爆
- **`page` 最小 1** —— 防负数 offset(MySQL 的 `OFFSET -50` 会直接报错)
- **`COUNT(*)` 单独查** —— 和列表查询分两条,别用 `SQL_CALC_FOUND_ROWS`(已废弃且慢)
- 事件接口**兼容老调用**:没传 `page` 就按第 1 页,老代码不会坏

## 二、前端

### 翻页条

```
[‹ 上一页] [下一页 ›]  第 1 / 2 页  共 97 条(本页 1–50)          每页 50 条
```

```javascript
const PG = { audit: { page: 1, size: 50 }, events: { page: 1, size: 50 } };

function pgGo(key, page) {
  if (PG[key]) PG[key].page = Math.max(1, page);
  if (key === 'audit') loadAudit(); else loadEvents();
}
```

### ⚠️ 踩到的两个点

**① 翻页条被 50 行表格顶到屏幕外了**

第一版只把翻页条放在表格**下面** ✅
每页 50 行 ⇒ 要滚很久才看得到 ⇒ **等于没有** ✅

**修:上下各放一个** ✅

```javascript
['Pager', 'PagerTop'].forEach(function (suf) {
  const box = document.getElementById(key + suf);
  if (box) box.innerHTML = html;
});
```

**② 越界页要能自动回退**

比如在第 2 页时,记录被清了一些,`pages` 从 2 变成 1 ✅
这时第 2 页会返回**空列表** ✅ 用户看到一片空白,以为坏了 ✅

```javascript
if (st.page > (d.pages || 1)) { st.page = d.pages || 1; return loadAudit(); }
```

⇒ 自动回到最后一页 ✅

## 五、经验

> **分页不只是"加个 LIMIT/OFFSET"。**
> 真正要做对,得同时想到:
> **① 总数**(不查就没法画"第 1/2 页")
> **② 参数边界**(size 上限、page 最小 1)
> **③ 翻页条的位置**(放下面 = 每页 50 行时等于没有)
> **④ 越界回退**(记录变少时别让用户看到空白页)
>
> 前两条是接口的事,后两条是界面的事 —— **两边都得想**。
