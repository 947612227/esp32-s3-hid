# 悬浮窗「让路」机制

## 背景

原来的设计:点「去启动看看」时**自动把悬浮窗隐藏 20 秒**。

出发点是对的 —— 开屏广告的「跳过」按钮通常在**右上角**,悬浮窗贴右边时会压住它。
但实现很粗糙:

| 问题 | 说明 |
|---|---|
| **一刀切** | 不管压没压住,一律隐藏 |
| **时长写死** | 20 秒靠猜(广告有 5 秒的,也有 30 秒的) |
| **没有反馈** | 悬浮窗突然消失,用户不知道去哪了、什么时候回来 |

## 新方案(C + A)

### C:改成**手动**让路

> ⚠️ **布局已更新**:把柄现在是**竖排 4 个按钮**(⠿/🙈/📐/◀),
> 见 [`悬浮窗把柄竖排.md`](悬浮窗把柄竖排.md)。本文下面的横向示意已过时,
> 但 🙈 让路按钮的**行为**没变。

手柄上新增一个 **🙈** 按钮(排在 ⠿ 和 📐 之间):

```
[⠿] [🙈] [📐] [◀]   🕐 20:26:56
 │    │    │    └─ 收起
 │    │    └────── 拾取坐标
 │    └─────────── 让路(收起 15 秒)
 └──────────────── 拖动
```

点一下就收起,**明确提示**「悬浮窗已收起,15 秒后自动回来」。
因为是用户自己点的,行为完全可预期。

### A:只在**真的挡住**时才提示

启动目标 App 时,判断悬浮窗是否落在**右上角热区**(横向右侧 30%、纵向顶部 25%)。
只有真挡住才弹提示:

> 悬浮窗可能挡住广告的「跳过」按钮,可点悬浮窗上的 🙈 让它让路

不挡就**完全不打扰**。

## 实测

| 项 | 结果 |
|---|---|
| 点 🙈 → overlay 窗口数 | 2 → **0** ✅ |
| 16 秒后 | 回到 **2** ✅ |
| 启动大麦(悬浮窗在左上,不挡)→ 6 秒 | 仍是 **2**(不隐藏)✅ |
| 启动大麦 → 12 秒 | 仍是 **2** ✅ |

## 顺带修的布局问题

手柄从 2 个按钮变成 4 个,宽度从 26dp 涨到 106dp,结果**盖住了面板上的时间文字**。

面板首行是给手柄预留的空位,把它从 `dp(26)` 调到 `dp(108)`:

```java
// ⚠️ 这里要给手柄留出宽度,否则手柄会盖住时间文字
row.addView(pad, new LinearLayout.LayoutParams(dp(108), dp(1)));
```
