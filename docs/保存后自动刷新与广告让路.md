# 保存后自动刷新列表 + 启动 App 时给广告让路

## 一、新建/编辑流程后列表不刷新

### 现象
保存新流程后,列表里看不到它,要手动点「刷新列表」才出现。

### 原因
`editScript()` / `newFlow()` 用的是 **`startActivity()`**(不带结果),
主界面根本不知道编辑页什么时候关掉了,自然就不会重新拉列表。

### 修法
改成 **`startActivityForResult()`**,回来时统一重新拉一次:

```java
private static final int REQ_FLOW_EDIT = 4101;

@Override
protected void onActivityResult(int req, int res, Intent data) {
    if (req == REQ_FLOW_EDIT) {
        loadScripts();     // 不管保存还是取消,都刷一次
        return;
    }
    ...
}
```

配合已有的排序规则,**新流程会直接出现在顶部**(创建时间最新)。

### 实测
```
新建流程 → 用指令库插入一行 → 保存
→ 自动回到流程页,「大麦X」出现在列表第一条  ✅
(全程没点过「刷新列表」)
```

> 注意:板子会**校验脚本**。只写个 `H` 是存不进去的,会提示
> `第 1 行 H:参数不足(用法:H x y [ms])`。这是正常的 ——
> 快捷指令只插指令本身,参数要自己填完再保存。

## 二、悬浮窗挡住启动广告的「跳过」按钮

### 现象
很多 App 启动时的开屏广告,「跳过/关闭」按钮在**右上角**。
悬浮窗拖到右边贴边后,正好压住它,点不到。

### 修法
**启动目标 App 前,先把悬浮窗收起来**,20 秒后自动恢复:

```java
// FloatingWindow
public void hideTemporarily(long ms) {
    if (!showing) return;
    hide();
    restoreRunnable = new Runnable() { public void run() { show(); } };
    ui.postDelayed(restoreRunnable, ms);
}
```

```java
// MainActivity.launchSelectedApp()
if (floatWin != null && floatWin.isShowing()) {
    floatWin.hideTemporarily(20000);
    toast("悬浮窗已隐藏 20 秒(给启动广告让路)");
}
```

手动关闭悬浮窗时会 `cancelRestore()`,不会莫名其妙又弹回来。

### 实测
```
启动前:overlay 窗口数 = 2      (悬浮窗可见)
点「去启动看看」→ 大麦启动
启动后:overlay 窗口数 = 0      ✅ 让开右上角
第 18 秒:overlay 窗口数 = 2    ✅ 自动恢复
```

### 为什么不是"让悬浮窗不接收触摸"
悬浮窗**必须可触摸**才能拖动、收起、展开、点 📐 拾取坐标。
所以正确做法是**在需要让路的时候整个撤掉窗口**,而不是让它变成点不透的装饰。

> 另外注意:光把窗口根视图设 `GONE` **不够** —— 窗口还在 WindowManager 里,
> 依然参与触摸判定。要让路必须真的 `removeView`。(这个坑之前踩过)
