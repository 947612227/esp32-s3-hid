# 遇到滑动验证码怎么办

## 你的方案

> 出现这个弹窗就 waitfor 5 分钟,后面如果出现继续尝试就点尝试然后继续提交订单,
> 如果 waitfor 5 分钟之后(手动验证完成验证码),是支付宝付款界面就是成功了。

**方向是对的,但有个明显浪费 —— 我有更好的方案。**

---

# 你的方案的问题

**固定等 5 分钟,不管验证码什么时候滑完。**

| 情况 | 你的方案 | 结果 |
|---|---|---|
| 验证码 **30 秒**就滑完了 | 还是干等到 5 分钟 | ❌ **白等 4.5 分钟** |
| 验证码 4 分半才滑完 | 等 5 分钟 | ✅ 刚好 |
| 验证码 5 分钟后才滑完 | 已经走了 | ❌ 放弃 |

**而且这 5 分钟里,大麦可能已经把订单放掉了。** 抢票场景下时间很宝贵。

---

# 我的方案:**轮询**,不固定等

**每 2 秒探测一次,最长等 5 分钟:**

```
遇到验证码弹窗
   ↓
notify 通知你(手机响,知道要手动滑)
   ↓
循环 150 次(150 × 2 秒 = 5 分钟):
   每 2 秒检查一次:
     · 已是「支付宝付款」 → notify 成功 + 立即结束 ✅
     · 出现「继续尝试」   → 点它 → 回到主循环继续抢 ✅
     · 都不是             → 继续等(说明你还在滑)
   ↓
5 分钟还没结果 → notify 放弃 + 结束
```

| 情况 | 我的方案 |
|---|---|
| 验证码 30 秒滑完 | **最多 2 秒后就继续** ✅ 不浪费 |
| 验证码 4 分半滑完 | 继续 ✅ |
| 一直没滑 | 5 分钟后放弃,并且**通知你** ✅ |
| **滑完跳到付款页** | **最多 2 秒就 notify 你** ✅ |

**核心差别:反应延迟从"最多 5 分钟"降到"最多 2 秒",而最长时间仍然是 5 分钟。**

# 完整流程(板子上已建好)

流程名:**`大麦抢票-带验证码处理`**

```
 1. wait 1 前置 确认在「确认购买」页
 2. waitfor 确认购买 5000
 3. wait 500 给页面一点渲染时间
 4. #主循环                                    ← 标号
 5. repeat 30                                  ← 主循环:最多提交 30 次
 6. T 0.801 0.911 30 ① 点「立即提交」
 7. waitfor 继续尝试 3000                      ② 最多等 3 秒看结果
 8. ifpage 继续尝试
 9. T 0.522 0.594 30 ③ 弹了就点「继续尝试」
10. endif
11. ifpage 支付宝付款                           ④ 成功了
12. notify 抢到了!页面已跳到付款 快去付款
13. goto 结束                                   ← 跳出去(跨两层循环)
14. endif
15. ifpage 操作过于频繁                         ⑤ 遇到滑动验证码
16. notify 需要手动滑验证码!请在 5 分钟内完成 我在这等着
17. goto 等验证码                               ← 跳到验证码处理段
18. endif
19. wait 300 这轮没结果 进入下一轮
20. endloop
21. goto 结束
22. #等验证码                                    ← 标号
23. wait 500 验证码弹窗 开始等你手动滑
24. repeat 150 最多等 150 x 2 秒 = 5 分钟        ← 轮询,不是死等
25. wait 2000 每 2 秒看一次
26. ifpage 支付宝付款
27. notify 验证通过 已跳到付款页 快去付款
28. goto 结束
29. endif
30. ifpage 继续尝试
31. T 0.522 0.594 30 验证过了 点「继续尝试」
32. goto 主循环                                 ← 回去继续抢
33. endif
34. endloop
35. notify 验证码等了 5 分钟还没结果 我放弃了
36. goto 结束
37. #结束                                       ← 标号
38. wait 1 流程结束
```

## 三个可选调整

| 想改什么 | 改哪里 |
|---|---|
| 主循环最多提交几次 | 第 5 行 `repeat 30` |
| 验证码最长等多久 | 第 24 行 `repeat 150`(× 第 25 行的 2000ms) |
| 探测间隔 | 第 25 行 `wait 2000`(改 1000 = 每秒看一次) |

> **探测间隔越小反应越快,但日志越多。** 2 秒是个好平衡。

# 关键:这里用到了 `goto`

**为什么不能用 `break`:**

`break` 只跳出**最内层**一层循环。而这个流程有**两层**嵌套:

```
repeat 30            ← 外层(主循环)
  ifpage 支付宝付款
    break            ← 只会跳到这里
  endif
endloop
... 后面还有一堆步骤要跳过
```

**`goto 标号` 可以跳到任意位置** ✅ 一次跳过两层 ✅

**实测(专门测了跨两层跳):**

```
[3/15] 等待:外层第几轮
[4/15] 重复                    ← 内层
[6/15] 如果是页面:触摸注入板 → 匹配,继续
[7/15] 等待:条件满足 应该跳到最外层之后
[8/15] 跳转:结束
[15/15] 等待:结束标号           ← 直接跳过去了 ✅
完成:9 步,耗时 40 ms
```

# `goto` 的用法

```
#标号名                       ← 单独一行,# 后面紧跟名字,**不能有空格**
...
goto 标号名                   ← 跳到那个位置
```

| 规则 | 说明 |
|---|---|
| **标号名不能含空格** | 有空格的行会被当**注释**(把 `# 这是注释` 和 `#标号` 区分开) |
| 标号不占步骤 | 所以不消耗 `SCRIPT_MAX_STEPS` |
| 最多 16 个标号 / 16 个 goto | 超了会报错 |
| 死循环保护 | 单次运行超过 1024 步会报错退出 |

# ⚠️ 这次挖出的三个真 bug

## Bug ① 注释被当成标号,把标号数组挤爆

我写了 13 条 `#` 注释 + 3 个真标号 = 16 个,而 `MAX_LABELS` 只有 **8** ⇒
**后面的真标号被静默丢弃**,报错写成:

```
保存失败:找不到标号 '#结束'
```

**完全看不出是注释挤掉的** ✅

### 修法:标号名不能含空格

```cpp
bool isLabel = (*name != '\0');
if (isLabel) {
  for (const char *q = name; *q; q++) {
    if (*q == ' ' || *q == '\t') { isLabel = false; break; }   // 有空格 = 注释
  }
}
```

顺带把上限提到 16 ✅

> **约定**:`#标号名`(无空格)= 标号;`# 说明文字`(有空格)= 注释 ✅

## Bug ② `goto` **根本不能往返** —— 一编辑就毁

回读流程时显示:

```
13. # (goto 跳转到第 34 步)      ← goto 变成了注释!
```

而且 `#主循环` / `#等验证码` / `#结束` 三个标号**全没了** ✅

**根因**:`scriptToText()` 把 goto 写成注释,而且标号名只存在解析时的临时数组里,没进步骤 ✅

### 修法

1. 解析时把标号名存进步骤的 `note` ✅
2. 回读时写回 `goto <标号名>` ✅
3. 有 goto 指向某一步 → 在那一步**前面补输出** `#标号名` ✅

## Bug ③ `goto 结束 结束` —— note 又被附了一遍

修完 ② 之后,读回来是:

```
13. goto 结束 结束
```

**`noteShown` 又漏了一个** ✅ ——

| # | 漏了谁 | 现象 |
|---|---|---|
| 1 | `WaitFor`/`IfPage` | `waitfor homepage homepage` |
| 2 | `Notify` | `notify 内容 内容` |
| 3 | **`Goto`** | **`goto 结束 结束`** |

**三次都是同一个坑:`note` 字段被"输出两次"。**

> **教训:新增指令时,`scriptToText()` 里的 `noteShown` 判断必须同步更新。**
> 现在它长这样,以后加指令记得往这里加:
>
> ```cpp
> bool noteShown = (st.op == StepOp::WaitFor || st.op == StepOp::IfPage
>                   || st.op == StepOp::Notify || st.op == StepOp::Goto);
> ```
