# 板子能连几台手机?能同步操作吗?

> **状态:方案研究 + 已保留的基础改动(2026-10-02)**
>
> 本次为回答"能否多机同步"做了验证,**App 层的多机功能一行未做**。
> 固件侧顺带修的两个 bug + 一个诊断接口,经确认**保留**:
>
> | 改动 | 性质 | 决定 |
> |---|---|---|
> | 连接状态改计数 | 真 bug 修复 | ✅ 保留 |
> | 连上后继续广播 | 行为改变(支持多机) | ✅ 保留 |
> | `/api/ble?op=info` | 只读诊断 | ✅ 保留 |
>
> 保留"继续广播"意味着:板子连上手机后**仍然对外可见**。
> 周围设备能搜到它,但要真正控制必须配对(bond)。

## 结论

| 问题 | 答案 |
|---|---|
| 同时能连几台? | **最多 3 台**(NimBLE 上限 `CONFIG_BT_NIMBLE_MAX_CONNECTIONS=3`),**已实测 2 台** |
| 能同步操作吗? | **能** —— 一次 `notify()` 会发给**所有已订阅的手机** |
| 配对记录存几台? | **3 台**(`CONFIG_BT_NIMBLE_MAX_BONDS=3`) |

## 实测数据(板子自己报的)

```bash
curl -X POST "http://192.168.5.37/api/ble?op=info"
```

```json
{
  "peers": 2,              ← 同时连了 2 台(手机 + Mac)
  "subs": 1,               ← 其中 1 台订阅了触摸上报
  "maxConnections": 3,
  "maxBonds": 3,
  "advertising": true,     ← 连上后仍在广播,第二台才搜得到
  "bondList": ["80:39:8c:e7:64:a1"]
}
```

## 原理(已在库里验证)

`NimBLECharacteristic::notify(value, len, connHandle)`:

> `connHandle` 传 `BLE_HS_CONN_HANDLE_NONE`(默认)= 通知发给
> **所有已订阅的客户端**。

所以我们调一次 `notify()`,**所有连着的手机同时收到同一个触摸**。

## 这次顺带修掉的两个真 bug

### bug 1:任何一台断开 → 全部失效

**原来**用**一个布尔**记录连接/订阅状态:

```cpp
volatile bool _connected;
volatile bool _touchSubscribed;
```

**实测踩到**:手机连着(peers=1),Mac 又连一台,Mac 一断开就把
`_connected=false` —— 虽然手机还在,但**手机的触摸注入直接失效**。

**改成按数量统计**:

```cpp
volatile int _subCount;                     // 已订阅的客户端数
int peers() { return _server->getConnectedCount(); }  // 让协议栈当权威
bool ready() { return _ok && peers() > 0 && _subCount > 0; }
```

`onDisconnect` 只在**一台都不剩**时才清状态。

### bug 2:连上就停广播 → 第二台根本搜不到

NimBLE 默认一连上就停广播。原来第二台手机**搜不到板子**,
自然谈不上多机同步。

**改成连上后继续广播**(只要没到 3 台上限):

```cpp
if (peers() < CONFIG_BT_NIMBLE_MAX_CONNECTIONS
    && !NimBLEDevice::getAdvertising()->isAdvertising()) {
  NimBLEDevice::startAdvertising();
}
```

## 多机同步的实际限制(重要)

虽然技术可行,但要真正"同步操作"得满足几个条件:

### ① 时序不是毫秒级同步

每台手机是**独立的 BLE 连接**,各有自己的连接间隔(我们请求 7.5~15ms)。
同一条报告发到两台的时间差**大约 10~20ms**。

> 对"两边点同一个按钮"够用;对严格同时的场合不够。

### ② 界面必须停在同一个页面

注入的是**绝对坐标**(归一化 0~1)。如果手机 A 在页面 X、手机 B 在页面 Y,
同一个坐标点下去结果完全不同。

**这是最大的实际约束** —— 得保证所有手机状态一致。

### ③ 屏幕比例不同会有偏差

归一化坐标保证的是**相对位置相同**:
- 同型号手机 → 完全一致 ✅
- 比例不同的手机(比如 20:9 和 16:9)→ 同一相对位置可能落在不同控件上 ⚠️

### ④ 每台都要配对

HID 服务需要绑定(`setSecurityAuth(true,false,true)`),所以每台手机都要走一次配对,
最多 3 台。

## 已知遗留

- **3 台同时连接**没实测过(手上只有一台手机 + 一台 Mac),3 是协议栈配置上限
- Mac 作为第二台能**连接**(peers=2 验证过),但它没完成 HID 订阅 ——
  是我的测试脚本问题,不是板子限制(触摸特征是 `READ|NOTIFY`,不要求加密)
