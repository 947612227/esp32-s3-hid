## 怎么恢复的

### 关键判断

| 事实 | 含义 |
|---|---|
| 板子用 **LittleFS**(写时复制文件系统) | 删除只是标记,数据块**在被覆盖前还在** |
| `fsUsedKB=16`,运行仅 19 分钟 | 删除的块**大概率还没被复用** |
| 脚本内容是**纯文本** | 可以在原始 flash 里直接 grep 出来 |

### 步骤

**① dump 出 LittleFS 分区**

```bash
# 分区表里 spiffs 在 0x610000,大小 1MB
python3 ~/.platformio/packages/tool-esptoolpy/esptool.py \
  --chip esp32s3 --port /dev/cu.usbmodem101 --baud 460800 \
  read_flash 0x610000 0x100000 /tmp/fsdump.bin
# → Read 1048576 bytes, 23.8 秒
```

> 需要 `pip install intelhex`(esptool 的依赖,PlatformIO 的 venv 里没装)

**② 在 dump 里找文件名**

```python
d = open('/tmp/fsdump.bin','rb').read()
i = d.find('大麦app.txt'.encode())
# @0x170f7: '...å¤§éº¦app.txt7P..\xa0....P.\x83T 0.8990 0.9180 30.wait 5000.T 0.61...'
```

**找到了** —— 文件名和正文都还在。

**③ 抠出正文**

文件名后面是约 12 字节的 LittleFS 元数据(非 ASCII),然后是正文。
以「第一个 `T `/`#`/`wait ` 开头的位置」为起点,读到不可打印字节为止。

**④ 写回板子**

```bash
curl -X POST "http://192.168.5.37/api/save?name=大麦app" \
  -H "Content-Type: text/plain" --data-binary $'T 0.8990 0.9180 30\nwait 5000\n...'
```

### 恢复结果

```
大麦.txt (2 步)      T 0.5000 0.5000 60 / H 0.5000 0.5000 900
大麦app.txt (9 步)   T 0.8990 0.9180 30 / wait 5000 / T 0.6160 0.4080 30
                    / wait 5000 / T 0.8920 0.5160 30 / wait 5000
                    / T 0.5990 0.9080 30 / wait 5000 / T 0.5950 0.9160 30
```

**⚠️ 一个小坑**:抠出来的第一行开头有个 `#`,差点把整行变成注释。

查原始字节:

```
37 50 00 0e a0 00 00 00 17 50 00 | 23 | 54 20 30 2e 35 ...
                                   ↑
                          0x23 是 LittleFS 的元数据 tag,不是内容
```

**正文其实从第 13 字节才开始。**

## 加了什么防护

### ① 板子心跳上报**流程内容**(不只名字)

```json
{
  "flowNames": ["大麦", "大麦app", ...],
  "flowTexts": { "大麦": "T 0.5 0.5 60\nH 0.5 0.5 900", ... }
}
```

### ② 服务端留底 + 历史版本

| 表 | 存什么 |
|---|---|
| `board_flows.text` | **当前**的流程内容 |
| `flow_history` | **每一版历史内容**(内容变了就存一份,只留最近 10 版) |

**实测**:

```
name                  内容字节数   前几行
大麦                   27        T 0.5 0.5 60 | H 0.5 0.5 900
大麦 王源 10月11_19:00    17        T 0.598 0.904 30
大麦app                125       T 0.899 0.918 30 | wait 5000 | T 0.616 0.408 3
大麦app 三星s23         125       T 0.899 0.918 30 | wait 5000 | T 0.616 0.408 3
大麦小米8               124       T 0.919 0.908 30 | wait 3000 | T 0.639 0.403 3
```

### ③ 查询接口

```
GET /api/admin/flow-backup?mac=<板子MAC>
→ { flows: [...当前内容], history: [...历史版本] }
```

**以后误删了,直接从服务器复制回来就行,不用再 dump flash。**

## 结论

| | |
|---|---|
| 数据丢失 | ❌ 没有,100% 恢复 |
| 根因 | 我用坐标盲点做 UI 验证,误触删除 |
| 恢复手段 | dump LittleFS 分区 + grep 纯文本 |
| 防护 | 心跳上报内容 + 服务端留底 + 历史版本 |

**⚠️ 给以后的自己的提醒**:

1. **有「删除」的界面,不要用坐标盲点验证** —— 要么用 App 内部的接口,要么先把危险按钮位置拍下来确认
2. **LittleFS 删除的数据在覆盖前可恢复** —— APP 分区 OTA、大量写文件都会覆盖,**发现误删要立刻 dump,别继续操作**
3. **改完代码必须验证字符串真的生效** —— 这次同一轮里,备注提示的改动也是「脚本说成功、实际没改」
