# 代码/配置备份:服务器上的 git 仓库

> 目标:`github.com/947612227/esp32-s3-hid`(**私有**)
> 角色分工:**本机改代码 → 服务器当版本库 → 推送 GitHub**

---

## 一、为什么这么绕(三个实测约束)

| # | 约束 | 实测证据 |
|---|---|---|
| 1 | **GitHub 的 HTTPS 主站在国内被干扰** | 服务器上 `curl https://github.com` **3 次全超时**;`git clone https` 报 `Empty reply from server` |
| 2 | **但 SSH 是通的** | `ssh -T git@github.com` → `Permission denied (publickey)`(**传输成功**,只差钥匙)✅ 443 端口也通 ✅ |
| 3 | **服务器上没有、也不该有 ESP32 工具链** | 装 PlatformIO + 交叉编译链要 1GB+,而构建频率极低 ⇒ 不值 |

**⇒ 结论**:
- **走 SSH,不走 HTTPS** ✅(已配 `~/.ssh/config` 把 `github.com` 指向 `ssh.github.com:443` ✅)
- **构建仍在开发机**(`tools/release-firmware.sh` 上传产物 ✅),服务器只做**版本库 + 分发** ✅

## 三、⚠️ 还差一步:把公钥加到 GitHub(**需要你手动做**)

### 推荐:用「Deploy key」(只对这一个仓库有效,比账号级密钥安全)

1. 打开 https://github.com/947612227/esp32-s3-hid/settings/keys
2. 点 **Add deploy key**
3. **Title** 填:`touchpad-server`
4. **Key** 粘贴上面那串(整行,以 `ssh-ed25519` 开头)
5. ✅ **勾上 `Allow write access`**(不勾只能读,推不上去)
6. 点 **Add key**

### 之后我就能推送了

```bash
cd /root/esp32-s3-hid && git push -u origin master
```

## 四、以后怎么备份(一条命令)

```bash
export SSHPASS='<服务器密码>'
./tools/sync-to-server.sh "这次改了什么"
```

它做四件事:
1. 打包本机代码(自动排除 `.pio/` / `.git/` / `node_modules/` ✅ 并且关掉 macOS xattr 噪音)
2. 上传到服务器
3. 服务器解压覆盖工作区 → `git add -A` → 有变化就提交
4. `git push` 到 GitHub

**⚠️ 注意**:脚本用 `tar --exclude='./.git'` 覆盖工作区 ✅
所以服务器上的 `.git` **不会被本机的覆盖** ✅(本机的 git 库是空的,覆盖了就丢历史 ✅)

## 五、⚠️ 凭据问题(**你选择了"原样推"**,这里如实记录)

推送的内容里**包含真实凭据** ✅ 私有仓库所以没公开 ✅ 但**团队里能看到仓库的人都能看到** ✅

| 凭据 | 文件 | 建议 |
|---|---|---|
| **服务器 root 密码** | `tools/release-firmware.sh:74` | 🔴 **建议改成读环境变量**,并轮换密码 |
| **后台管理员密码** | `tools/shot_admin.js:31` | 🔴 同上 |
| **WiFi 名 + 密码** | `secrets.h`(**已忽略** ✅)但**烧进了 `dist/*.bin`** | 🔴 二进制里的没法改,只能不传 `dist/` |
| 板子 / App token | `Server.java` 等 5 个文件 | 🟡 建议改成首次运行时输入 |
| MySQL 密码 | 多个 docs | 🟡 |

**改起来其实很快**(半小时内):
```bash
# tools/*.sh 改成从环境变量读
export SSHPASS="${SSHPASS:?请先 export SSHPASS}"
export ADMIN_PASS="${ADMIN_PASS:?请先 export ADMIN_PASS}"
```
再把 `dist/` 加进 `.gitignore` ✅

> **⚠️ 如果哪天这个仓库改成公开,凭据就永久留在 git 历史里了** ✅
> 那时**删文件没用,必须改密码** ✅

## 六、踩到的两个环境坑

| 坑 | 现象 | 修法 |
|---|---|---|
| **CentOS 7 的 OpenSSH 7.4 太老** | `~/.ssh/config` 里写 `StrictHostKeyChecking accept-new` 报 `unsupported option` | 改成 `no` + 预先 `ssh-keyscan -p 443` 写 known_hosts |
| **git 1.8.3.1 太老** | ① 默认分支是 `master` 不是 `main` ② 没有 `git remote get-url` | 用 `git rev-parse --abbrev-ref HEAD` 取分支名;用 `git remote -v` 看远程 |
| **macOS 的 xattr 噪音** | tar 刷了几百行 `Ignoring unknown extended header keyword LIBARCHIVE.xattr...` | `COPYFILE_DISABLE=1 tar ...` |
