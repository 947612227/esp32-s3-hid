# 过期流程禁止开启 + 目标 App 不一致提示

## 一、已过期的流程禁止开启(但可以运行)

### 需求
- 已过期 → **不能改成开启状态**
- 但 **「运行」照旧可用**(手动执行)

### 实现
在 `toggleFlow()` 的"开启"分支前面加拦截:

```java
FlowStore.Meta chk = flows.get(name);
long t = chk.targetMillis();
if (t > 0 && chk.expired(time.nowMs())) {
    Dialogs.info(this, "无法开启",
        "「" + name + "」的定时已经过期,不能开启。\n\n"
        + "过期流程开启后不会执行,还会占着「同一时间只能开一个」的名额。\n\n"
        + "想跑的话:点「运行」手动执行,或者先用「定时…」把时间改到未来。");
    return;
}
```

**理由**:过期流程开启后**根本不会执行**(调度器里有 expired 判断),
却会占用"全局唯一开启"的名额,把别的流程挤掉 —— 纯负收益。

### 实测
```
点过期流程的「开启」→ 弹出「无法开启」说明  ✅
点过期流程的「运行」→ 正常弹出运行弹窗      ✅
```

## 二、目标 App 不一致时询问

### 需求
流程运行前,如果"流程里保存的 App"和"当前选中的 App"不一致,
弹窗询问是否改成当前选择的。

### 为什么重要
流程里的坐标是**针对某个 App 的界面**录的。
如果实际启动的是另一个 App,那套坐标会点到完全不相干的位置
—— 甚至可能落到别处的删除/确认按钮上。

### 实现
`askRun()` 开头做检查:

```java
String fp  = mm.appPkg == null ? "" : mm.appPkg;
String sp2 = selectedAppPkg == null ? "" : selectedAppPkg;
if (!fp.isEmpty() && !sp2.isEmpty() && !fp.equals(sp2)) {
    askRunAppMismatch(idx, name, mm);
    return;
}
askRun2(idx, name);
```

弹窗内容:

```
目标 App 不一致
流程「X」保存时用的是:  大麦
现在选择的是:          101 Okey Plus
流程里的坐标是针对原来那个 App 录的。
用别的 App 跑,点击会落到完全不相干的位置。

[改成「101 Okey Plus」]  [保持「大麦」]
```

- **改成当前** → 更新流程的 `appPkg/appName`,然后继续运行
- **保持原样** → 不改,直接继续运行

### 注意:只在流程**指定了 App** 时才检查

如果流程的 `appPkg` 是空的(比如固件内置的示例流程、或创建时没选 App),
就**跟随全局选择**,不弹提示 —— 因为"没指定"就不存在"不一致"。

> ⚠️ 这条我用现有流程没能测到:示例流程和用户新建的流程 `appPkg` 都是空的。
> 代码路径已就位,需要**新建一个"指定了 App"的流程**再换全局选择才能看到弹窗。

## 三、状态总表

| 流程状态 | 「开启」 | 「运行」 | 会定时执行 |
|---|---|---|---|
| 未设定时 | ✅ | ✅ | — |
| 有定时,未过期 | ✅ | ✅ | 开启后才会 |
| 有定时,已过期 | ❌ 弹「无法开启」 | ✅ | ❌ |
| 已开启 + 已过期 | 自动暂停 | ✅ | ❌ |

## 四、编辑定时后的状态重置

见 `docs/定时状态管理.md`:保存定时会调 `resetRunState()`,
清掉 `fired/appLaunched`,否则改完时间后新定时**永远不会执行**。
