# ⚠️ Bug ①:并发连接风暴 —— 表现为"列表一直超时"

## 现象

logcat 里 `已配对设备数=1` **每秒刷十几次** ✅ 流程列表一直 `读取失败:蓝牙请求失败/超时` ✅

## 根因

```java
// Board.bleUsable() —— 错的写法
if (!b.ready) {
    b.connect(ctx, null);    // ← 每次请求都触发一次连接!
    return false;
}
```

`connect()` 是**异步**的,立刻返回 ✅
→ 下一个请求又发现"还没就绪" → **再发起一次连接** ✅
→ 几十个 GATT 连接尝试互相打架 ⇒ **永远稳不下来** ✅

> **教训:异步操作必须有"进行中"标志。**
> "发现没就绪就发起" 这种写法,在**高频调用**的路径上一定会变成风暴。

## 修

```java
private volatile boolean connecting = false;

public synchronized void connect(Context ctx, Cb onDone) {
    if (ready) { ...; return; }
    if (onDone != null) waiters.add(onDone);
    if (connecting) return;      // ← 已经在连了就只挂回调
    connecting = true;
    ...
}
```

**效果:日志从"每秒十几次"降到 2 条** ✅

# ⚠️⚠️ Bug ②:非法帧头 → OutOfMemoryError 崩溃(**最严重**)

## 现象

App 每次连上蓝牙控制,**过一会儿就自己消失** ✅
(和之前那个"App 自己消失 + 无障碍绑定卡死"的坑表现一样,但原因完全不同 ✅)

## 崩溃栈

```
java.lang.OutOfMemoryError: Failed to allocate a 1096045920 byte allocation
    at java.io.ByteArrayOutputStream.<init>
    at com.dsh.touchpad.Ble.onChunk(Ble.java:348)
```

**1,096,045,920 ≈ 1GB** ✅

## 根因

协议原本**只在第一片带长度头**:

```
[4字节总长][数据...]         ← 第 1 片
[数据...]                   ← 第 2..N 片(没有头!)
```

App 收到**任何**片时,如果 `rxWant == 0` 就把**前 4 字节当长度** ✅

**一旦丢片**(Android 侧收 BLE 通知确实会丢 ✅),
后续的**数据片**就被当成帧头 ✅ → 读出 `0x6676...` 这种天量数字 ✅ → **直接申请 1GB → OOM 崩掉** ✅

## 修(两层)

### ① 立即可用的防护:校验长度合法性

```java
if (len <= 0 || len > MAX_RESP /*1MB*/) {
    Log.w("TouchBle", "非法帧头 len=" + len + ",丢弃这片");
    rxWant = 0;
    return;                  // 丢掉,等下一个真正的帧头
}
```

**效果:同样的数据,从"崩溃"变成"记一条日志然后丢弃"** ✅

### ② 根治:协议 v2 —— **每片都带** [总长][偏移]

```
[4字节总长][4字节本片偏移][数据]      ← 每片都有
```

App 按**偏移直接落位** ✅

- 丢片能被**立刻发现**(偏移有缺口)
- 错位**不会蔓延**
- 校验更严:`len` 范围 + `off < len` + `HDR + (len-off) >= v.length`

```java
if (len <= 0 || len > MAX_RESP || off < 0 || off >= len
        || HDR + (len - off) < v.length) {
    Log.w("TouchBle", "非法片头 len=" + len + " off=" + off + ",丢弃");
    return;
}
```

**实测效果:非法片头从"刷屏"变成 0 次** ✅

> **教训:凡是"从字节流里读长度"的协议,都必须当成敌意输入来校验。**
> BLE 通知、串口、socket —— **都会丢片**,不能假设"第一片一定收得到"。
>
> **更强的教训:把长度头放在只出现一次的地方,是脆弱设计的典型。**
> 每片自带定位信息,才能自恢复。
