# 悬浮窗日志要先进日志页签 + 频率挪到定时页

## 你反馈的三件事

> 我指的是悬浮窗里面的日志,必须要先在 app 里面点击手势右边的 tab 日志页签后,
> 悬浮窗才会出现日志,而且日志不会刷新,日志持久化暂时没有必要,
> 将流程中的频率功能挪到定时页面中。

---

# ① 悬浮窗日志:**两个 bug 叠在一起**

## 根因

```java
// netTick:2 秒一次
if (tab == TAB_STATUS) {
    fetchStatus();
} else if (tab == TAB_LOGS) {
    pullLogs();              // ← bug A:只有"日志页签"才拉日志
}

private void pullLogs() {
    if (logView == null) return;   // ← bug B:没进过日志页,logView 是 null,直接返回
    ...
}
```

- **bug A**:日志只在「日志」页签激活时才拉
- **bug B**:`logView` 是**日志页签里的控件**,没进过那个页就是 `null` —— **连请求都不发**

两个叠一起 → **必须先点日志页签,而且切走就不再刷新** ✅ 完全对上你的描述。

## 修法:把「喂悬浮窗」和「喂日志页」解耦

```java
private void pullLogs() {
    final boolean needFloat = (floatWin != null && floatWin.isShowing());
    if (logView == null && !needFloat) return;      // 两边都不在才不请求

    board.logs(new Board.Cb() {
        public void done(boolean ok, String body) {
            // ① 喂悬浮窗 —— 不管在哪个页签
            if (floatWin != null && floatWin.isShowing()) {
                ...最近 30 行...
                if (!t.equals(lastLogText)) { lastLogText = t; floatWin.setLog(t); }
            }
            // ② 喂日志页签 —— 可能根本没建过
            if (logView == null) return;
            ...
        }
    });
}
```

`netTick` 里**只要悬浮窗在显示就拉**:

```java
if (tab != TAB_LOGS && floatWin != null && floatWin.isShowing()) {
    pullLogs();
}
```

## 实测

**改前**:悬浮窗日志区一直是空的(除非你先进日志页)
**改后**:直接就有,而且跟着流程跑实时刷新

# ② 日志持久化:**不做**(按你说的)

日志仍然只存在板子的内存环形缓冲(150 行),**重启就没了**。
需要的时候再加"随心跳上报 + 服务器存表"。

# ③ 频率:从流程卡片挪进「定时设置」页

## 改前

流程卡片上有 7 个按钮:

```
[运行] [开启] [定时…] [频率…] [编辑] [复制] [删除]
                    ↑ 单独一个按钮,和定时分开了
```

## 改后

卡片上 **6 个按钮**,频率配置进「定时…」里:

```
[运行] [开启] [定时…] [编辑] [复制] [删除]
```

点「定时…」打开定时设置页:

```
← 返回   定时设置                       [确定]
[不定时] [指定时刻] [倒计时]

不设定时间,只在你点「运行」时执行
─────────────────────────────
🔁 执行频率
   启用后:这个流程每次被运行/定时触发时,按下面的配置循环执行。
   不启用 → 运行一次就结束。

   ⭕ 未启用(点一下启用)

   间隔        100       [−] [+]
   连续执行多久
   小时 0 / 分钟 1 / 秒 0
```

**频率区放在三个页签下面** —— 因为它和"定时模式"无关,
三种模式(不定时 / 指定时刻 / 倒计时)都可能要配频率。

## 语义没变

频率**仍然是流程自己的属性**:

| | |
|---|---|
| 不启用 | 被运行/定时触发时**只执行一次** |
| 启用 | 按「每 N 毫秒一次」循环,**连续跑设定时长后自动停** |
| 计时者 | **板子**(App 被杀也会按时停) |

流程卡片上的状态行也保留着,一眼能看到:

```
大麦app 三星s23                          9 步
  定时:未设置
  🔁 频率:每 100 毫秒 · 连续 1 分 0 秒
```

# ⚠️ 顺带记录一个危险窗口

测试时我用 **API 从 App 外面**启动了一个流程,
而当时**前台是 App 自己** —— 那一下注入点击落到了 App 的
「重启板子」按钮上(弹出了确认框,已取消)。

**原因**:遮罩由「板子在忙」驱动,而这个状态靠 **2 秒一次的状态轮询**同步 ——
**从网页/API 启动流程时,有最多 2 秒的窗口遮罩还没盖上来。**

### 以后要注意

| 场景 | 风险 |
|---|---|
| App 里点「运行」 | ✅ 安全(`exec()` 立刻上锁) |
| **网页/API 启动流程** | ⚠️ **2 秒窗口**,期间别让 App 在前台 |
| 定时触发 | ✅ 安全(走 `exec()`) |

### 给用户的自保办法

**跑流程前,先把 App 切到后台**(或让目标 App 在前台)。
不要让「App 在前台 + 从网页启动流程」同时发生。
