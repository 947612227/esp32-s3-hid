# 悬浮窗出现两个 + 参数单位标注

## 一、悬浮窗出现两份

### 现象
屏幕上有**两个**悬浮窗(错位叠着)。

### 定位
```bash
adb shell dumpsys window windows | grep -c APPLICATION_OVERLAY
# 输出 4 —— 不是预期的 2
```

4 个窗口 = **两套**(每套 = handle + panel):

```
(11,178) handle + panel   ← 第一份
(11,381) handle + panel   ← 第二份
```

### 根因
`MainActivity.onCreate()` 里 `new FloatingWindow(this)`。

**Activity 重建时会再 new 一个,而旧实例的窗口还挂在 WindowManager 上没被移除**
(悬浮窗本来就要在 App 退到后台后继续显示,所以 `onDestroy` 故意不摘它)。

结果:旧实例的窗口泄漏在屏幕上 + 一直持有已销毁的 Activity。

### 修法
1. **改成进程级单例** `FloatingWindow.get(ctx)` —— 重建时复用同一个实例
2. `show()` 之前先 `forceDetach()` —— 防御性摘掉可能残留的窗口
3. 单例持有 **applicationContext**(原来持有 Activity,会泄漏)

### 验证
```
反复 后台→前台 重建 3 次:overlay 数始终 = 2  ✅
```

## 二、参数单位标注

### 原来的样子(单位重复)

```
X 坐标                        0.500
Y 坐标                        0.500
持续(毫秒)                     60 ms      ← 单位和数值挤在一起
```

### 改成

```
X 坐标                        0.500      ← 不需要单位的,不加
Y 坐标                        0.500
持续 ms                        60        ← 单位挂到标签上,数值只留数字
```

### 规则

| 参数类型 | 标签 | 数值 |
|---|---|---|
| 坐标 / 间距 | `X 坐标` | `0.500` |
| 时长 | `持续 ms` | `60` |
| 次数 | `次数` | `3` |

**判定方式**:单位统一由 `CmdLib.Param.unit` 承载,界面拼成 `名称 + 空格 + 单位`;
`unit` 为空就不加。所以加新参数时**不用管界面**,填对 `unit` 就行。

### 顺带统一的地方

- 「写法」行:`T x y [毫秒]` → **`T x y [ms]`**(全部 8 条)
- 详细说明:`毫秒 = 按下停留多久…` → **`ms = 按下停留多久…`**
- 修掉一个别扭的拼法:`次数` 原本 unit 是「次」,会拼成「次数 次」

### 实测

| 指令 | 标签 | 写法 |
|---|---|---|
| T 点击 | `X 坐标` / `Y 坐标` / `持续 ms` | `T x y [ms]` |
| S 直线滑动 | `X 坐标`×2 / `Y 坐标`×2 / `持续 ms` | `S x1 y1 x2 y2 [ms]` |
| repeat 重复 | `次数` | `repeat 次数` |

生成的行始终是纯数字:`T 0.500 0.500 60`
