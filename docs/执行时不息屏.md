# 执行期间不让手机息屏

## 你反馈的问题

> 这个手机息屏最大时间只有分钟级别 不能关闭自动息屏

**确实如此** —— 手机设置里息屏时间最大只给到"分钟"级,没有"永不"选项。

## 为什么 Activity 上常用的办法不管用

跑流程时**目标 App(大麦)在前台,我们的 App 在后台**,
所以 `Activity` 上的 `FLAG_KEEP_SCREEN_ON` **不起作用**(那是给前台窗口用的)。

## 实测:这个键接受超大值

```bash
adb shell settings put system screen_off_timeout 2147483647
adb shell settings get system screen_off_timeout
→ 2147483647      # 约 24.8 天,等于"永不"
```

**MIUI 的 UI 只是不让选,系统本身接受。**

## 实现:三重保活

### ① 系统设置(主力,需要权限)

执行开始 → 把息屏时间改成 `2147483647`;**执行结束 → 自动改回原值**。

```java
// 只改一次,并且只在还没改过的时候记原值(避免把 NEVER 记成原值)
if (cur != NEVER) sp.edit().putInt(K_SAVED, cur).apply();
Settings.System.putInt(cr, Settings.System.SCREEN_OFF_TIMEOUT, NEVER);
```

需要 **`WRITE_SETTINGS`** 权限(特殊权限,要在系统设置里手动授权)。
App 设置里有入口,没授权时会显示红字提示。

### ② 悬浮窗 `FLAG_KEEP_SCREEN_ON`(零权限兜底)

```java
handleLp.flags |= WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON;
panelLp.flags  |= WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON;
```

悬浮窗只要**可见**就压住息屏,**不需要任何权限**。

### ③ 进程被杀也能恢复(防呆)

如果执行中 App 被杀,息屏时间会卡在"永不"。所以**每次启动检查一次**:

```java
public static void restoreIfStuck(Context ctx) {
    if (当前值 == NEVER) 恢复成上次记下的原值;
}
```

## 驱动方式:绑在「板子是否在忙」

**没有**把 hold/release 写在 `exec()` 里 ——
那样只能覆盖"App 点运行"这一条路径。

改成在 1 秒的 UI 节拍里统一判断:

```java
boolean schedOn = sched.optBoolean("active", false);
boardBusy = running || schedOn;          // 跑流程 或 频率循环
if (boardBusy) KeepAwake.hold(this);
else           KeepAwake.release(this);
```

**这样四条触发路径全覆盖**:
App 点的 / 网页点的 / 定时触发的 / 频率循环的。

## 实测

```
执行前: screen_off_timeout = 600000      (10 分钟)
+6s:    2147483647                       ← 变成「永不」✅
+12s:   2147483647                       ← 保持
+26s:   600000                           ← 自动恢复 ✅
```

设置界面还会实时显示:

```
执行时保持屏幕常亮
  ✅ 已开启 · 当前系统息屏:10 分钟
  　→ 点这里关闭
```

## ⚠️ 两个坑

### 坑 1:重装 App 会重置权限

```bash
adb shell appops get com.dsh.touchpad android:write_settings
→ WRITE_SETTINGS: ignore          # 重装后又变回 ignore
```

**重新授权**:
```bash
adb shell appops set com.dsh.touchpad android:write_settings allow
```
或者走 App 设置里的红字入口 → 系统设置 → 允许修改系统设置。

### 坑 2:MIUI 上 `appops get` 一开始可能还是 ignore

实测第一次 `set` 完 `get` 还是 `ignore`,**再执行一次才生效**。
所以如果发现没效果,先确认这个值是 `allow`。

# 附:顺手修的两个问题

## ① 「开始升级」按钮之前是空的

点板子固件那行 → 弹确认框 → 点「开始升级」→ **只弹个提示,没真升级**。

现在补上了 **`POST /api/ota/from-server`**:

板子自己去控制中心下载 `.bin`,边下边写进备用分区,写完重启。

**为什么让板子自己下而不是 App 转存**:
- 板子直连服务器带宽更好
- `Update.writeStream()` 是**流式**的,不占内存
  (固件 1.2MB,板子只有 ~160KB 空闲 RAM)

**实测**:

```
POST /api/ota/from-server
→ {"ok":true,"message":"固件已写入,正在重启..."}
耗时 26 秒,第 13 秒回来
mac=AC:A7:04:26:5E:40 · HID=就绪 · 5 个流程(没丢)
```

