# 编辑流程时键盘把编辑框挤没了

## 你反馈的

> 新建流程或编辑流程时,输入法弹出后编辑框可视范围很小,能调整吗,
> 指令快捷输入也要能可视。

**完全复现了。**

---

## 复现(改前)

键盘一弹,编辑框只剩 **2~3 行**:

```
流程内容   [☰可视化] [✎文本]
每行一个动作…            [⛭ 指令库]
[T点击] [D双击] [H长按] [S直线滑动]      ← 快捷输入在
───────────────────────────────
T 0.899 0.918 30                    ← 编辑框被挤成一条缝
wait 5000
T 0.616 0.408 30
───────────────────────────────
坐标:0.5 或 50% 或 16384 …            ← 这些「参考信息」
💬 备注:…                             占了约 200px
定时:未设置                             而且**不让位**
[设置定时]
───────────────────────────────
(键盘占了大半屏)
```

## 根因

| # | 问题 |
|---|---|
| ① | `bodyEd` 用 `android:layout_weight=1` —— 键盘弹出后父容器变矮,它被按比例挤扁 |
| ② | 下面那些**参考信息**(坐标写法 / 备注说明 / 定时信息 / 设置定时按钮)是**固定高度**,不会缩也不会让位,白占约 200px |
| ③ | 整页没有兜底滚动 |

---

## 改了什么

### ① 编辑框设最小高度(挤不扁)

```java
bodyEd.setMinHeight(dp(150));
```

### ② 键盘弹出时,参考信息**自动让位**

监听根布局的可见高度,键盘出现就收起那几行:

```java
root.getViewTreeObserver().addOnGlobalLayoutListener(() -> {
    Rect r = new Rect();
    root.getWindowVisibleDisplayFrame(r);
    int hidden = root.getRootView().getHeight() - r.bottom;
    boolean kb = hidden > screenH * 0.18;      // 键盘一般占 20% 以上
    if (kb != kbShown) { kbShown = kb; applyKbLayout(kb); }
});

private void applyKbLayout(boolean kb) {
    int v = kb ? View.GONE : View.VISIBLE;
    coordTip.setVisibility(v);      // 坐标写法提示
    noteTipView.setVisibility(v);   // 备注说明
    schedInfo.setVisibility(v);     // 定时信息
    schedRow.setVisibility(v);      // 设置定时按钮
    newFlowTip.setVisibility(v);    // 新建流程提示
}
```

> 这三个判定阈值是刻意"宽松"的 —— 判错了只是布局不最优,**不影响功能**。

### ③ 指令快捷输入**不动**

芯片行(`T点击 / D双击 / H长按 / S直线滑动`)和「⛭ 指令库」按钮
本来就一直可见,这次**特意没把它们放进让位列表**。

## 教训

**`layout_weight=1` 的输入框 + 固定高度的辅助信息 = 键盘一弹就被挤没。**

凡是"输入为主"的页面:
1. 输入控件给 **minHeight** 兜底
2. 辅助信息在键盘弹出时**主动让位**
3. 别指望 `adjustResize` 一个设置解决所有问题 ——
   它只负责让 Activity 变矮,**怎么分配空间还得自己安排**
