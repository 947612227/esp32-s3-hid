# 板子的灯:控制链路 + 怎么关 / 怎么改颜色

# 〇、控制链路(**不是** 服务器→App→板子)

**一共五条路**,按"生效快慢"排:

```
① 串口            电脑 ──USB串口线──> 板子 COM 口           立刻
② 板子 HTTP       同一WiFi的设备 ──> http://<板子IP>/api/led  立刻
③ 蓝牙控制通道     App ──BLE GATT(A5C1/A5C2)──> 板子        立刻
④ App「💡灯」按钮  ──> 走 ② 或 ③(蓝牙就绪就走蓝牙)          立刻
⑤ 后台「💡灯」按钮 后台 ──> 服务器 ──存库──> ...              最多 2 分钟
```

## ⚠️ 第 ⑤ 条**不经过 App 的"转发"**,而是**板子自己去拉**

```
后台(浏览器)
   │  POST /api/admin/led  {mac, mode}
   ▼
服务器  ──写入──>  MySQL settings 表  k='led:<mac>'
                        ▲
                        │  ① 板子自己有网时:板子心跳时取走
                        │     POST /api/v1/board/heartbeat → 响应里带 led
                        │
                        │  ② 板子没网时(**你现在就是这样**):
                        │     App 代报时取走
                        └──   POST /api/v1/app/board-relay → 响应里带 led
                             → App 再通过 ③ 蓝牙通道 / ② 局域网 HTTP
                               下发给板子(立刻)
```

**核心是"板子来问,顺路捎回去"** ✅ —— 因为板子在内网,服务器**够不到它** ✅

## 🐛 这里原本有个断层(已修)

设计时只做了"板子自己心跳来取" ✅
但**这块板子连不上外网**(公司网要飞连认证,只能开热点)⇒ **它永远发不出心跳** ✅
⇒ 后台存的命令**没人来取** ⇒ **后台「💡 灯」看着成功,板子毫无反应** ✅

**修法**:让 **App 代报时顺路把命令取走**,再通过直连下发给板子 ✅
(见 `server/index.js` 的 `/api/v1/app/board-relay` 和 App 的 `applyServerLed()`)

**实测:**
```
① 后台下达「红」  → {"ok":true,...}
② 命令进库       → led:28:84:... = {"r":255,"g":0,"b":0,"ms":0}   ✅
③ 中继一次       → {"ok":true,"led":{"r":255,"g":0,"b":0,"ms":0}}  ✅
④ 库里剩余命令   → 0                                              ✅ 取走即删
```

## 怎么选

| 场景 | 用哪条 |
|---|---|
| 就想马上看到效果 | **App 的「💡 灯」**(④,直连) |
| 手边有电脑接了串口 | **串口**(①,最快) |
| 只想在后台点一下 | **后台**(⑤,等 ≤2 分钟;前提是 App 在跑或板子自己有网) |

> ⚠️ **后台那条依赖 App 在运行**(或板子自己有外网)✅
> 如果 App 被杀掉了、板子也没网,后台点的灯**不会生效** ✅

# 一、你看到的蓝灯是什么

## 先说清楚:你看到的蓝灯是什么

板子刚上电时灯是**暗蓝色** —— 这是**「自动」模式下的状态色**:

| 颜色 | 含义 |
|---|---|
| **暗蓝** | 未连接(手机没连上板子) |
| 暗绿 | 已连接 |
| 暗黄 | 流程执行中 |

**所以灯是蓝的 = 板子现在没被手机连上** ✅ 这不是故障 ✅

---

## 怎么关

### 方法一:App(推荐,立刻生效)

App → **状态页** → 「💡 点亮板子」按钮(现在改叫「💡 灯」)→ 选 **⚫ 关灯** ✅

### 方法二:后台

`http://120.55.183.206/admin/` → **控制中心** → 板子那行点 **💡 灯** → 选 **⚫ 关灯** ✅

⚠️ **后台要等最多 2 分钟**才生效 ✅
因为服务端**够不到内网的板子**,只能把命令存起来,等板子下次心跳(2 分钟一次)取走 ✅
**App 那条路是直连,立刻生效** ✅

### 方法三:串口(最快)

用串口工具(115200)连板子的 COM 口,发:

```
LED OFF
```

## 怎么改成指定颜色

三种方式都有,命令一样:

| 想亮的颜色 | 命令 / 选项 |
|---|---|
| 🔴 红 | `LED 255 0 0` |
| 🟢 绿 | `LED 0 255 0` |
| 🔵 蓝 | `LED 0 0 255` |
| 🟡 黄 | `LED 255 180 0` |
| 🟣 紫 | `LED 180 0 255` |
| ⚪ 白 | `LED 255 255 255` |
| ⚫ 关灯 | `LED OFF`(等同于 `LED 0 0 0`) |
| 🔄 回状态色 | `LED AUTO` |

**App / 后台**里就是那个「💡 灯」对话框里的按钮 ✅

**亮度自己调**:每个通道 0~255 ✅ 比如 `LED 20 0 0` 就是很暗的红 ✅

## ⚠️ 一个重要的行为变化(这次新加的)

**手动设的颜色 / 关灯会「锁住」** ✅

以前的问题:

```
你手动把灯设成红色 / 或者关掉了
  → 手机一连上板子
  → 状态色把它盖成绿色 / 又亮起来
  → 你看着莫名其妙:"我明明关了它怎么又亮了"
```

现在:

```
手动设过颜色之后 = 进入「手动模式」
  → 状态变化**不会**再动它
  → 要显式选「🔄 回到自动」才交还给状态色
```

**怎么知道自己现在在哪个模式** —— 串口发 `LED`(不带参数)会告诉你:

```
LED 当前模式:自动(随状态)
```
或
```
LED 当前模式:手动色
```
或
```
LED 当前模式:关灯(手动)
```

## 完整的命令参考

### 串口

```
LED             看当前模式
LED r g b [ms]  设颜色;ms 省略 = 一直保持;带 ms = 只亮这么久,到点自动回状态色
LED AUTO        回到状态色
LED OFF         关灯
BLINK           找板子(快-快-慢 + 绿色常亮 60 秒)
```

### HTTP

```
GET /api/led                   找板子(闪)
GET /api/led?mode=off          关灯
GET /api/led?mode=auto         回状态色
GET /api/led?r=255&g=0&b=0&ms=0   指定颜色
```

### 蓝牙控制通道

```
LED / LED AUTO / LED OFF / LED r g b [ms]
```

### 后台

```
POST /api/admin/led
  { "mac": "...", "mode": "blink" | "off" | "auto" | "color",
    "r":255, "g":0, "b":0, "ms":0 }
```

### 板子上的按钮

**BOOT 键长按 1.2 秒** = 找板子(灯闪)✅
现场没带手机电脑时按一下就行 ✅

## ⚠️ 这次修掉的一个隐蔽 bug

`LED AUTO` / `LED OFF` 一开始**报"用法错误"** ✅ 而 `LED 255 0 0` 却正常 ✅

根因:

```cpp
// 上游拆词:
char word[16]; sscanf(line, "%15s", word);
const char *rest = line + strlen(word);   // "LED AUTO" → rest = " AUTO"(带前导空格!)

// 我的判断:
if (!strcasecmp(args, "AUTO")) { ... }    // " AUTO" ≠ "AUTO" ❌
```

**为什么 `LED 255 0 0` 能过**:`sscanf` 会自动跳过前导空白 ✅
所以这个 bug **只在纯字母参数上暴露** ✅ 特别隐蔽 ✅

而其它 handler(`RUN`/`DEL`/…)开头都有 `while (*args == ' ') args++;` ✅ —— 我漏了 ✅

> **教训:同一个文件里别人怎么写,往往就是"这里有个坑"的提示。**
> 那几个 `while (*args == ' ')` 不是废话,是在绕一个真实的坑 ✅
