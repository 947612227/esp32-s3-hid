# 悬浮窗倒计时 + 流程列表排序

## 一、悬浮窗新增「最近定时」

```
🕒 15:45:29
📱 大麦
⏳ 大麦ZZtest · 还有 4 分 5 秒      ← 新增
📍 已拾取:0.833 0.777(已复制)
```

三种状态:

| 情况 | 显示 |
|---|---|
| 正在跑流程 | `▶ 流程名 执行中`(绿色) |
| 有定时没到点 | `⏳ 流程名 · 还有 X 分 X 秒`(黄色) |
| 没有定时 | `⏳ 无定时任务`(灰色) |

**找哪一个**:
1. 优先看**已开启**的那个(它才是真会跑的);
2. 没有已开启的,就在所有流程里找**最近的一个**(仅展示);
3. 每秒刷新一次。

## 二、流程列表排序

按优先级:

| 优先级 | 类型 | 说明 |
|---|---|---|
| ① | **正在执行的** | 板子 `run.running` 且名字匹配 |
| ② | **已开启的** | `●` 状态 |
| ③ | 其余 | **按创建时间倒序(新建的在前)** |
| ④ | **已过期的** | **沉到最下方**(不清理) |

### 关于「已过期」

**不清理,只沉底。** 理由:"这个流程本来定过某个时间但没跑成"本身就是有用的信息。

判定:`目标时刻已过 1 分钟以上`。

**一个细节**:过期状态是**动态变化**的(时间一直在走)。所以列表不能只在
"刷新"时排序 —— 否则一个流程刚过期,它还挂在上面,要等你手动刷新才沉下去。

处理方式:

```
每秒检查"哪些流程已过期",拼成一个签名
  ↓
签名变了(有人刚过期 / 刚重新定时)→ 重排一次
签名没变 → 什么都不做
```

⚠️ **不能每秒都重排** —— 重建视图会让正在点的按钮移位(这个坑踩过:
倒计时刷新时重排,导致点击落空)。所以只在**状态真的变化**时才重建。

实测:

```
● 大麦ZZtest      1 步    定时:... · 还有 4 分 5 秒      ← 已开启,排最前
○ 向下滚动        6 步
○ 回桌面          1 步
○ 曲线滑动        3 步
```

新建一个流程后,它会出现在**已开启的下面、其他流程的上面** —— 不用翻找。

## 三、顺带修掉一个会"误触发"的问题

**问题**:一个**已过期**的定时,只要一开启就会**立刻触发一次**。

实测:我有个 12:42 的定时,当时是 15:30,一点「开启」就马上启动了目标 App 并跑流程。

**原因**:调度逻辑是 `now >= target` 就执行,没管"过期多久"。

**修法**:加上过期判断 —— 超过目标时间 1 分钟就算过期,**只展示不执行**。

```java
if (!m.fired && now >= target && !m.expired(now)) { ... }
```

## 五、排序的取舍说明

**"新建的排最前"是用创建时间实现的**,而不是把板子的顺序倒过来。

好处:
- 板子上的顺序保持不变(网页控制台看到的还是原顺序);
- 排序只影响 App 的展示,两边不会互相干扰。

注意:`createdAt` 是 **App 侧**记的。所以:
- 在 App 里新建的流程 → 有创建时间 → 排前面;
- 在**网页控制台**建的流程 → 没有创建时间(`createdAt=0`)→ 按板子的原顺序排。

如果你希望网页端建的也排前面,可以在板子侧记录创建时间,但那要动固件。
