# 复制「大麦通用版本-智能等待」并改成 ifpage 安全版

## 原版的问题

```
 1. waitfor 首页 5000
 2. waitfor 我的 100
 3. T 0.9 0.914 30 点击我的
 4. waitfor 抢票预约 3000
 5. T 0.631 0.419 30 点击抢票预约
 6. waitfor 1张 3000
 7. T 0.449 0.533 30 点击预约的票
 8. waitfor 预约 3000
 9. T 0.629 0.917 30 点击已预约
10. waitfor 可预约 3000
11. T 0.573 0.915 30 点击立即预定
```

**`waitfor` 超时会照常往下走** —— 于是后面那个 `T`(点击)**一定会执行**。
页面没到,那一指就点到别的地方去了。

> 实测日志里 `[6/11] 等待页面:1张 → 超时` 紧接着 `[7/11] 点击`,就是这个情况。

## 新版:每次点击前先判断页面

```
 1. waitfor 首页 8000         ① 等大麦首页(开屏广告会一直等)
 2. ifpage 首页
 3.   T 0.9 0.914 30           点底部「我的」
 4. else
 5.   wait 1 不在首页 跳过点我的
 6. endif
 7. waitfor 我的 3000         ② 等「我的」页
 8. ifpage 我的
 9.   waitfor 抢票预约 3000     等「抢票预约」入口
10.   ifpage 抢票预约
11.     T 0.631 0.419 30       点「抢票预约」
12.   else
13.     wait 1 我的页没有抢票预约入口 跳过
14.   endif
15. else
16.   wait 1 没进我的页 整段跳过
17. endif
18. waitfor 1张 3000          ③ 等票档页
19. ifpage 1张
20.   T 0.449 0.533 30         点想预约的那张票
21. else
22.   wait 1 票档没出来 跳过点票
23. endif
24. waitfor 预约 3000          ④ 等预约相关页
25. ifpage 预约
26.   T 0.629 0.917 30         点「已预约」
27. else
28.   wait 1 不在预约页 跳过
29. endif
30. waitfor 可预约 3000        ⑤ 等最后确认页
31. ifpage 可预约
32.   T 0.573 0.915 30         点「立即预定」
33. else
34.   wait 1 没到可预约页 跳过最后一步
35. endif
36. wait 1 流程结束
```

**36 步**(原 11 步)。

## 核心差别

| | 原版 | ifpage 版 |
|---|---|---|
| 页面没到时 | **照常点** ← 危险 | **跳过不点** ✅ |
| 日志 | 只有"超时" | "✅匹配"或"❌不匹配,跳过" |
| 出错时 | 点到别的地方,不好查 | 日志直接告诉你跳过了哪一步 |

# ⚠️ 改这个的过程中发现两个真 bug,都修了

## Bug ① 嵌套 `ifpage` 的 `else` 会配对错

```cpp
// 找这对 if/endif 之间的 else
for (uint8_t k = ifIdx + 1; k < i; k++) {
    if (out.steps[k].op == StepOp::Else) { out.steps[k].next = i + 1; break; }
}
```

**没跳过嵌套的 `if...endif`** —— 外层 `endif` 会先找到**内层的 `else`**,
把它错指到外层之后 ⇒ **内层 else 的分支被整段吃掉**。

### 修法:数嵌套深度

```cpp
int depth = 0;
for (uint8_t k = ifIdx + 1; k < i; k++) {
    StepOp o = out.steps[k].op;
    if (o == StepOp::IfPage) depth++;
    else if (o == StepOp::EndIf) depth--;
    else if (o == StepOp::Else && depth == 0) { out.steps[k].next = i + 1; break; }
}
```

### 实测(专门做了个 `嵌套测试` 流程)

```
[2/13] ifpage 触摸注入板       → 匹配,继续
[3/13] ✅外层匹配              ← 走到
[4/13] ifpage 绝不存在的词xyz  → 不匹配,跳到第 7 步
[7/13] ✅内层不匹配            ← 走的是**内层的 else**
[9/13] ✅内层之后              ← 正确越过内层 else
[13/13] ✅全部结束             ← 跳到外层 endif 之后
```

**一个 ❌ 分支都没走到** ✅ 修复确认。

## Bug ② 步数上限 32 → 48 导致 `/api/save` **必然断连**

「ifpage 版」36 步 > 32,所以把 `SCRIPT_MAX_STEPS` 提到了 48。
结果**连 3 步的小流程都存不进去了**:

```
GET  /api/status     200  ✅
POST /api/logs/clear 200  ✅     ← 其它 POST 都正常
POST /api/save       000  ❌     ← 只有它断
```

### 根因:**栈溢出**

```cpp
Script tmp;                                    // ← 在栈上
memset(&tmp, 0, sizeof(tmp));
```

一个 `Script` = `SCRIPT_MAX_STEPS × ~100 字节`:

| 步数上限 | `sizeof(Script)` |
|---|---|
| 32 | 3.3 KB |
| **48** | **4.9 KB** |

而 **Arduino 的 loop 任务栈默认只有 8KB**,WebServer 回调就跑在里面。
4.9KB + 各种缓冲 ⇒ 溢出 ⇒ 连接被掐断。

### 修法:双保险

1. **临时对象挪到堆上**

```cpp
Script *tmp = (Script *)calloc(1, sizeof(Script));
if (!tmp) { setErr(errBuf, errLen, "内存不足"); return false; }
if (!parse(text, *tmp, errBuf, errLen)) { free(tmp); return false; }
...
free(tmp);
```

2. **把 loop 任务栈加大到 16KB**(`platformio.ini`)

```ini
-DARDUINO_LOOP_STACK_SIZE=16384
```

### 实测

```
{"ok":true,"message":"已保存 保存测试"}                     HTTP 200  0.43s
{"ok":true,"message":"已保存 大麦通用版本-智能等待-ifpage版"}  HTTP 200  0.23s
```

> **教训**:`SCRIPT_MAX_STEPS` 这类"数组长度"常量改大时,
> **必须同时算一遍 `sizeof(整个结构)`** ——
> 一旦它有对象会落在**栈**上,8KB 的默认栈说爆就爆。
> 而且爆的时候**没有 panic 日志**,只是连接断掉,非常难查。

# ⚠️ 一个还没解决的问题:关键字太"大众"

新版的判断词里,`首页` 和 `我的` 是**大麦底栏的常驻页签** ——
它们**在每个大麦页面上都有**,所以:

```
ifpage 首页      → 在任何大麦页面都会匹配 ✅(等于没判断)
ifpage 我的      → 同上
```

**所以这两层的保护其实很弱。** 只有这几层是真的在判断:

| 关键字 | 真的能区分页面吗 |
|---|---|
| `首页` / `我的` | ❌ 底栏常驻,每页都有 |
| `抢票预约` | ✅ 「我的」页独有 |
| `1张` | ✅ 票档页独有 |
| `预约` / `可预约` | ⚠️ 比较宽泛,还好 |

## 怎么换成好的关键字

**用悬浮窗的 🔍 挑带 ⭐ 的词**(⭐ = 上一页没有、只在本页出现):

```
① 在大麦首页点 🔍        → 记下首页的词
② 切到「我的」再点 🔍     → ⭐ 标出「我的」页独有的词
③ 点那个 ⭐ 词           → 剪贴板就是能直接用的整行
```

把 `ifpage 首页` 换成 `ifpage <首页独有的词>`,保护才真正生效。
