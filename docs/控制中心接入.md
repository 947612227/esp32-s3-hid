# 控制中心接入(固件 + App)

> 服务端见 [`服务端部署记录.md`](服务端部署记录.md)。本文是**两端接上**的记录。

## 总体链路

```
┌─────────┐  心跳(上电 + 每小时)   ┌──────────────┐
│  ESP32  │ ──────────────────────▶│ 控制中心      │
│  板子    │◀──── hasUpdate + url ──│ 120.55.183.206│
└─────────┘                        │              │
                                   │  · 板子台账   │
┌─────────┐  查更新(启动,15s 超时)│  · 固件 OTA   │
│ 手机 App │ ──────────────────────▶│  · APK 分发   │
│         │  上报手机信息 + 已装App │  · 黑白名单   │
└─────────┘                        └──────────────┘
```

**关键设计:板子不自动升级。**
心跳拿到 `hasUpdate` 只**存进自己的状态**,App 读出来提示用户,
**用户确认后**才让板子去下载。避免自动升级打断正在跑的抢票流程。

## 一、固件侧

### 配置(`secrets.h`)

```c

### 实测

```
服务器上:

**MAC 的坑**:板子的 **WiFi MAC 是 `...5e:40`,蓝牙 MAC 是 `...5e:41`**

## 二、App 侧

### 新增 `Server.java`

| 方法 | 作用 |
|---|---|
| `checkUpdate()` | 查 APK 更新,**15 秒超时** |
| `reportPhone()` | 上报型号/Android 版本/WiFi |
| `reportApps()` | 上报已装 App(只报有桌面图标的) |
| `startupPing()` | 启动时统一处理(上报 6 小时节流) |

**设计原则:一切失败都静默。**
服务器连不上、超时、返回垃圾 —— 对 App 正常使用**零影响**。
这本来就是锦上添花的功能,不能因为它把主流程拖死。

## 三、悬浮窗:点句柄复制

### 需求

> 悬浮窗上的当前窗口的句柄点击后可以复制

### ⚠️ 踩到的坑:面板**收不到点击**

本来我把复制事件挂在面板的 `📱/🔍` 那一行上,结果**点了没反应**。

原因:

```java
// 面板永远不可触摸:注入的点击 100% 穿透
WindowManager.LayoutParams.FLAG_NOT_TOUCHABLE
```

**面板是故意设计成不可触摸的** —— 否则板子注入的点击会被面板吃掉,流程就点空了。

### 解决办法:按钮做在把柄上

把柄是唯一可触摸的窗口,所以加了**第 5 个按钮**:

```
[⠿]  ① 拖动          蓝色
[🙈]  ② 暂时隐藏       橙色
[📐]  ③ 坐标拾取       紫色
[🔍]  ④ 复制页面句柄   绿色   ← 新增
[◀]  ⑤ 收到边框       灰色
```

点绿色按钮 → 复制**完整 Activity 类名**到剪贴板。

### 实测(包括后台场景)

**场景:大麦在前台,我们的 App 在后台** —— 点绿色按钮:

```
已复制页面句柄:
cn.damai.trade.newtradeorder.ui.projectdetail.ui.activity.ProjectDetailActivity
```

✅ **后台也能复制成功。**

> **重要发现**:Android 10 只限制**读**剪贴板(非焦点应用读不到),
> **写是不限制的**。所以后台写剪贴板没问题 ——
> 这也说明之前坐标拾取器的"复制失败"另有原因(不是写入被拒)。

## 四、两个我修正的设计问题

### ① 重复上传 APK 没去重

第一次测试传了一个,后面又传了一个,`versionCode` 都是 3 → 看板上出现两条。
已删除旧的(服务在运行时不能直接删文件,要**走 API**,否则内存里的副本还在)。

> **踩坑**:我先用 `rm` 删了 `firmware.json`,但服务在跑,**内存里的数据还在**,
> 下次保存又写回去了。**必须先停服务或走 API。**

### ② "在线"判定和心跳间隔不匹配

```js
const ONLINE_MS = 5 * 60 * 1000;   // ❌ 5 分钟
```

但板子是**每 1 小时**心跳一次 → **板子几乎永远显示离线**(实测就踩到了)。

已改为:

```js
const HEARTBEAT_INTERVAL_MS = 60 * 60 * 1000;
const ONLINE_MS = HEARTBEAT_INTERVAL_MS + 30 * 60 * 1000;   // 90 分钟
```

## 五、运维

```bash
# 本地部署服务端
cd server && SSHPASS=<密码> ./tools/deploy.sh

# 看板
http://120.55.183.206/admin/

# 上传固件(看板上有表单,也可以命令行)
curl -u admin:<密码> -X POST http://120.55.183.206/admin/api/firmware \
  -F "file=@.pio/build/ble/firmware.bin" -F "version=1.2.0" \
  -F "channel=stable" -F "notes=更新说明"

# 上传 APK
curl -u admin:<密码> -X POST http://120.55.183.206/admin/api/apk \
  -F "file=@android-app/build/触摸注入板.apk" -F "versionCode=4" \
  -F "versionName=2.2" -F "notes=更新说明"
```

**升级流程**:
1. 本地 `pio run -e ble` 编译
2. **改 `platformio.ini` 里的 `FW_VERSION`**(比如 1.1.0 → 1.2.0)
3. 上传固件到服务器
4. 等板子下次心跳(或重启板子强制心跳)
5. App 上会弹「板子固件有新版本」→ 确认 → 板子自己下载重启
