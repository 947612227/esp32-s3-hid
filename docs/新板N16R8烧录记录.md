# 第二块板(N16R8)烧录记录 + 公司网络怎么用

## 一、板子实测数据

用 `esptool.py flash_id` 探到的真实参数:

```
Chip        ESP32-S3 (QFN56) revision v0.2
Features    WiFi, BLE, Embedded PSRAM 8MB (AP_3v3)
Flash       16MB  (Manufacturer c2 = Macronix, Device 2018)
Flash 模式  quad(4 线) —— 写在 eFuse 里
晶振        40MHz
MAC         28:84:85:89:78:c8      ← 新板子的 MAC
串口        /dev/cu.usbmodem5CBC0615521
```

## 二、这块板和上一块的区别

| | 上一块(N8R8) | **这一块(N16R8)** |
|---|---|---|
| Flash | 8MB | **16MB** |
| PSRAM | 8MB OPI | 8MB(同为 R8) |
| USB 口 | 1 个(原生) | **2 个:`COM` + `USB`** |
| **串口日志** | ❌ **看不到**(原生 USB 被 HID 占了) | ✅ **能看**(COM 口是 CH343 串口桥) |
| 串口芯片 | 无(原生 USB) | **CH343**(Vendor `1a86` Product `55d3`) |

### 双 USB 口怎么用

``` 
┌─────────────────────────────────────────┐
│  COM 口  ──→ 接电脑                     │
│    · 烧录                                │
│    · **看串口日志**(这块板的一大优势)     │
│    · 串口命令行(输入 ? 看帮助)          │
├─────────────────────────────────────────┤
│  USB 口  ──→ 接手机(仅 USB HID 版需要)  │
│    · 蓝牙版(ble)用不到这个口             │
└─────────────────────────────────────────┘
```

> **推荐用蓝牙版(ble)** —— 这样 `USB` 口空着,`COM` 口常接电脑,
> **随时能看日志,特别好排查**。

## 三、16MB Flash 要不要专门适配?—— **不用**

| 疑问 | 答案 |
|---|---|
| 固件是按 8MB 编的,能用吗? | ✅ **能用** —— 只用前 8MB,后 8MB 闲着 |
| 要不要为 16MB 重编分区表? | ❌ **不用** —— 脚本引擎在 **RAM** 里,`spiffs` 1MB 早就够 |
| 多出来的 8MB 有用吗? | 对当前功能**没用**。除非以后要把脚本数量从 16 提到几百 |

**结论:直接烧现有的 8MB 固件,零改动。**

## 四、烧录过程(实测)

```bash
PORT=/dev/cu.usbmodem5CBC0615521

# 单文件固件,烧到 0x0
esptool.py --chip esp32s3 --port $PORT --baud 921600 \
  write_flash -z --flash_mode keep --flash_freq keep --flash_size keep \
  0x0 dist/touchpad-ble-full.bin
```

输出:

```
Wrote 1332048 bytes (821167 compressed) at 0x00000000 in 14.5 seconds
Hash of data verified.          ← ✅ 校验通过
Hard resetting via RTS pin...
```

**烧完直接就能跑,不用手动复位。**

## 五、⚠️ 公司网络的问题

### 现象

板子上电后尝试连编译期写死的 WiFi(`ZTE-2009-2.4G`,家里的):

```
[net] 连接 WiFi: ZTE-2009-2.4G
....................................          ← 36 个点 ≈ 9 秒
```

**12 秒超时后自动退到热点模式** ✅

### 用串口确认

这块板有串口命令行,直接问它:

```
> NET
网络模式: AP(板子热点)
IP      : 192.168.4.1
访问地址: http://192.168.4.1/
HID     : 就绪
脚本    : 6 个
```

### 公司网络为什么连不上

公司 WiFi 要**飞连认证** ✅ ESP32 做不了 802.1X / 门户认证 ✅
所以板子**永远连不上公司网**,只能走下面的方案 ✅

## 六、三种可用方案

| 方案 | 板子 | 手机 | 能连服务器 | 适合 |
|---|---|---|---|---|
| **A. 板子热点**(当前) | 开热点 `ESP32-Touch-xxxx` | 连它 | ❌ 手机没网 | **马上能用**,纯本地控制 |
| **B. 手机热点** ⭐ | 连手机热点 | 开热点 | ✅ 走手机流量 | **推荐**,云功能也能用 |
| **C. 家里/其他 WiFi** | 连那个 | 同一个 | ✅ | 回家再配 |

### 方案 A:板子热点(现在就是这个状态)

```
手机 WiFi → 连 ESP32-Touch-78C8(密码 12345678)
App → 🔍 自动查找板子 → 认到 192.168.4.1
```

**优点**:一分钟搞定,**纯本地**,不依赖任何外部网络 ✅
**限制**:手机连上板子热点后**没有互联网** ——
  服务器心跳、云端统计、远程 OTA 都用不了(会静默失败)✅

### 方案 B:手机热点 ⭐

```
① 先让一个**第二设备**(另一台手机 / 笔记本)连上板子热点
② 打开 http://192.168.4.1/ → 填手机热点的 SSID 和密码 → 保存
③ 手机开热点 → 板子自动连上(走手机流量,能到服务器)
④ 手机上 App → 查找板子
```

> ⚠️ **为什么需要第二设备**:手机一旦开了热点,就**不能同时当客户端**
> 去连板子的热点了 ✅ 所以配置这一步得换个设备做。
>
> **Mac 可以担当这个角色** —— 我实测过:Mac 上网走**有线(en16)**,
> WiFi 空着,连板子热点不影响公司网络 ✅

### 方案 C:回家配

在家连一次家里的 WiFi,凭据会存进 **NVS**,以后再上电就直接连 ✅
(除非又换网络 ✅)

## 七、怎么给板子改 WiFi(实测步骤)

```bash
# 1. 让 Mac 连板子热点(不影响公司有线网)
networksetup -setairportnetwork en0 "ESP32-Touch-78C8" "12345678"

# 2. 确认连上了
ipconfig getifaddr en0            # → 192.168.4.2
route -n get default | grep interface   # → 还是 en16(公司网没断)

# 3. 打开配置页(浏览器)
open http://192.168.4.1/
#    填新的 WiFi 名和密码 → 保存 → 板子重启去连

# 4. 用完把 WiFi 关掉,恢复原状
networksetup -setairportpower en0 off
```

> **AP SSID 的后缀是 MAC 后两位** —— `28:84:85:89:78:c8` → `ESP32-Touch-78C8` ✅
> 多块板子同时上电时靠这个区分 ✅

## 八、这块板特有的好处:**能看串口日志**

上一块板(原生 USB 单口)是看不到日志的,排查问题只能靠网络 ✅

**这块板有串口桥,`pio device monitor` 直接能看:**

```bash
pio device monitor -p /dev/cu.usbmodem5CBC0615521 -b 115200
```

**而且固件带了串口命令行** —— 输入 `?` 看全部命令:

| 命令 | 作用 |
|---|---|
| `NET` | 看网络状态(IP / 模式) |
| `LIST` | 列脚本 |
| `RUN <名字>` | 跑脚本 |
| `FILES` | 看文件系统占用 |
| `G` | **自检:点四角 + 中心** |
| `WIFI OFF` | 关 WiFi,射频全让给 BLE(降触摸延迟) |
| `?` | 帮助 |

**实测启动日志:**

```
ESP-ROM:esp32s3-20210327
[boot] ESP32-S3 HID Touch Injector
[boot] Report Map 92 字节, 槽位 10, 最大触点 10
[ble] Appearance = 0x03C5 (数字转换器/触摸屏;0x03C1 是键盘)
[boot] HID 就绪(传输层: BLE HID (NimBLE / HOGP))
[script] LittleFS 就绪:分区 1024 KB,已用 16 KB
[script] 载入 向下滚动 / 回桌面 / 曲线滑动 / 最近任务 / 返回 / 逐级返回后回桌面
[script] 跳过 重复演示:repeat 没有对应的 endloop
[script] 可用脚本 6 个

....................................          ← 连不上,12 秒后转 AP
[net] 自动发现已就绪:UDP 45678
```

> `跳过 重复演示` 是**正常的** —— 那是老的示例脚本,
> 用的 `repeat` 没写 `endloop`(后来加的规则),新引擎拒绝加载它 ✅
> 不影响别的脚本 ✅
