# 板子 IP 自动发现(UDP 广播)

## 你问的两个问题

### Q1:换网络后板子 IP 变了,新手机能自动识别吗?

**现在能了。** 之前**不能** —— 只能手动填 IP。

### Q2:所有 IP 都参数化了吗?有没有写死?

**之前有 5 处写死了 `192.168.5.37` 作为默认值**,现在**全部改成空 + 自动发现**:

| 文件 | 改前 | 改后 |
|---|---|---|
| `Board.java` | `host = "192.168.5.37"` | `host = ""` |
| `MainActivity` / `FlowEditActivity` / `DebugReceiver` | 兜底默认 `"192.168.5.37"` | `""` |

**固件侧本来就干净** —— 全程 DHCP,一行 IP 都没写死 ✅

## 自动发现的实现

### 协议(极简)

```
手机 → 广播 255.255.255.255:45678   "TOUCHPAD_DISCOVER"
板子 → 单播回手机                     "TOUCHPAD_HERE 192.168.5.37 80"
```

### 为什么用 UDP 广播而不是 mDNS

很多路由器**默认不转发组播**,而广播基本都能通。
而且广播不需要任何额外权限(有 `INTERNET` 就够)。

### 固件侧

```cpp
#define DISCOVER_PORT   45678
#define DISCOVER_MAGIC  "TOUCHPAD_DISCOVER"
#define DISCOVER_REPLY  "TOUCHPAD_HERE"
```

在 `NetManager::loop()` 里收包并回复自己的 `WiFi.localIP()`。

### App 侧

`Discovery.java`:
- 同时广播到 **`255.255.255.255`** 和**本网段广播**(如 `192.168.5.255`),提高命中率
- 每 400ms 重发一次(板子可能刚上电还没起来)
- 收到回复就回调 IP

## 三个触发时机

| 时机 | 行为 |
|---|---|
| **首次使用**(没存过地址) | 启动后自动广播查找 |
| **连不上板子**(连续失败 2 次) | 静默广播查找 |
| **手动** | 状态页 →「🔍 自动查找板子」 |

## 关于"蓝牙自动识别 IP"

你提到"新手机**蓝牙**连接板子之后自动识别 IP" —— 这里说明一下:

**手机连板子蓝牙时,是我们的 App 从 WiFi 拿 IP,不经过蓝牙。**

原因:板子做的是 **BLE HID 外设**,手机是 HID 主机。
系统把这条 BLE 连接**独占**给 HID 用了,App 拿不到它去做 GATT 读写。

**所以走 WiFi 广播是正解** —— 反正 App 本来就要用 WiFi 连板子。

## 找不到板子时排查

App 会给出提示:
- 板子已通电、且连上同一个 WiFi
- 手机连的是同一个局域网(**不是手机热点/流量**)
- 路由器没开「**AP 隔离**」(隔离后设备之间不能互通)

实在不行还能手动填(设置 → 板子地址)。
