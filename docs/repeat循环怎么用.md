# 循环:`repeat n` … `endloop`

## 你的需求

> 当我点击立即提交后会弹出继续尝试的弹窗,点击继续尝试之后又要点立即提交,
> 这两个步骤需要一直循环指定的次数

**`repeat` 之前是坏的(死循环),已经修好了。**

---

# 一、必须成对用

**`repeat` 和 `endloop` 是一对** —— 就像 `ifpage` 和 `endif` 一样。
单独写哪个都会**保存失败并报错**:

| 你写的 | 结果 |
|---|---|
| 只有 `repeat`,没有 `endloop` | ❌ `repeat 没有对应的 endloop` |
| 只有 `endloop`,没有 `repeat` | ❌ `第 N 步 endloop 没有对应的 repeat` |
| 成对写上 | ✅ 保存成功 |

> **为什么要报错而不是忽略:**
> 这两种都是"打错字/多写一行"的典型情况。
> 如果静默忽略,你只会发现「**怎么没循环?**」却查不出原因 ——
> 所以宁可保存时就明确告诉你。

## 谁需要配对,谁不需要

| 指令 | 要配对吗 | 配对写法 |
|---|---|---|
| `repeat n` | **要** | `repeat n` … `endloop` |
| `ifpage 关键字` | **要** | `ifpage` … `else`(可省)… `endif` |
| `waitfor 关键字` | 不要 | 单行,自己就是完整的 |
| `wait ms` | 不要 | 单行 |
| `T` / `S` / `D` … | 不要 | 单行 |
| `goto 标号` | 不要 | 单行(跳到 `#标号`) |

# 二、怎么用

```
repeat <次数>
  ... 要重复的步骤 ...
endloop
```

**举例**(你的场景):

```
wait 1 前置 确认在「确认购买」页
waitfor 确认购买 5000 等确认购买页 等不到也会继续
wait 500 给页面一点渲染时间

repeat 20                                  ← 循环次数,改这一行就行
T 0.801 0.911 30 ① 点「立即提交」
waitfor 继续尝试 2000 等「继续尝试」弹窗 等不到也照点
T 0.522 0.594 30 ② 点「继续尝试」
wait 300 让页面反应一下 再进下一轮
endloop

wait 1 循环结束 次数用完了
```

**已经在板子上建好了**,叫 `大麦抢票-提交并继续尝试循环版`。

## 嵌套

`repeat` 可以嵌套(最多 16 层):

```
repeat 3
  T ... 外层第 N 轮
  repeat 5
    T ... 内层跑 5 次
  endloop
  wait 500 内层跑完歇一下
endloop
```

# ⚠️ 修之前它是**死循环**

实测:

```
[script] [2/5] 重复
[script] [2/5] 重复
[script] [2/5] 重复      ← 卡在"重复"这一步,循环体一次都没执行
... 把 150 行日志缓冲刷满
```

## 原因

```cpp
// 解析时
st.next = out.stepCount;   // = 自己的下标

// 执行时
case StepOp::Repeat:
  if (repeatLeft[pc] > 1) { repeatLeft[pc]--; pc = (uint8_t)st.next; }  // 跳回自己
  advance = false;          // ← 而且永远不前进
  break;
```

`pc = st.next` 跳回**自己**,`advance = false` 又让 pc **不动** ⇒
在这一个步骤上原地打转,永远出不去 ✅

**而且没有任何"循环体结束"的标记** —— 引擎根本不知道循环到哪算一轮 ✅

## 修法:加 `endloop`,配对回填(和 `ifpage`/`endif` 一个思路)

```
Repeat.next  = 匹配的 EndLoop **之后**(循环跑完从这继续)
EndLoop.next = 配对的 Repeat 下标(还有剩余次数时跳回去)
```

```cpp
case StepOp::Repeat:
  // 首次进入 → 记下次数,然后**往下走进循环体**
  if (repeatLeft[pc] == 0) repeatLeft[pc] = (st.repeat > 0 ? st.repeat : 1);
  break;

case StepOp::EndLoop: {
  uint16_t loopPc = st.next;
  if (repeatLeft[loopPc] > 1) {
    repeatLeft[loopPc]--;
    pc = (uint8_t)loopPc;      // 回跳,再走一遍
    advance = false;
  } else {
    repeatLeft[loopPc] = 0;    // 清零,便于复跑
  }
  break;
}
```

配对回填用**栈**,支持嵌套:

```cpp
if (op == StepOp::Repeat) stack[sp++] = i;
else if (op == StepOp::EndLoop) {
  int repIdx = stack[--sp];
  out.steps[repIdx].next = i + 1;      // 循环结束 → 从 endloop 之后继续
  out.steps[i].next = repIdx;          // 回跳目标
}
if (sp > 0) { setErr(..., "repeat 没有对应的 endloop"); return false; }
```

> `repeat` 没有 `endloop` 会**直接报错**,而不是默默死循环 ✅

# ⚠️ 又踩了一次同一个坑:`endloop` 回读失败

加完 `endloop` 之后,App 读流程显示:

```
 9. # 未知步骤        ← endloop 变成了这个
10. wait 1 循环结束
```

**因为 `scriptToText()`(回读/编辑用)没加 `EndLoop` 分支** ——
**一编辑一保存,`endloop` 就变成注释,循环结构彻底毁掉** ✅

> **这已经是第二次了**:
> 上次是 `waitfor`/`ifpage`/`else`/`endif` 漏了同样的分支 ——
> 当时的现象是"编辑流程会破坏 waitfor 逻辑"。
>
> **教训:加新指令时,要改的地方有 4 个:**
> 1. `StepOp` 枚举
> 2. `stepOpName()`(日志用)
> 3. `stepToText()`(显示用)
> 4. **`scriptToText()`(回读/编辑用)← 最容易漏,后果最严重**
>
> 漏了第 3 个只是显示难看;**漏了第 4 个会静默毁掉用户的流程。**

**修完实测往返**:

```
读出来 10 行 → 存回去 → 再读
  有 repeat  : ✅
  有 endloop : ✅
  有 # 未知步骤: ✅ 没有
```

# 三、中途停止循环:`break`

## 你的需求(已确认)

> 点立即提交之后有可能出现继续尝试,如果出现继续尝试就点继续尝试然后点立即提交,
> 如果点了立即提交之后出现的是支付宝付款就停止。

**逻辑图:**

```
                    ┌──────────────────────────┐
                    │  点「立即提交」            │
                    └────────────┬─────────────┘
                                 │
              ┌──────────────────┴──────────────────┐
              ▼                                     ▼
     出现「继续尝试」                        出现「支付宝付款」
              │                                     │
     点「继续尝试」 ──┐                        break 停止 ✅
                     │                              │
                     └──► 回到「立即提交」          ▼
                          (循环)              去付款
```

**这个理解完全正确。** 下面这个流程就是这么实现的 👇

## ⚠️ 但顺序很关键:先等哪个

**两种写法的耗时差很多:**

| 写法 | 每轮耗时 | 问题 |
|---|---|---|
| 先 `waitfor 支付宝付款 8000` | **≈10.3 秒** | 「继续尝试」是每轮都出现的,但代码先花 8 秒等一个**通常等不到**的「支付宝付款」 |
| **先 `waitfor 继续尝试 2500`** | **≈1.5 秒** | 弹了立刻返回;然后再花 0.1 秒查一下「支付宝付款」 |

**抢票场景下 10 秒一轮基本没戏** —— 所以要**先等那个"每轮都会出现"的条件**。

```
每轮耗时 = 1.5秒(等继续尝试,弹了就秒过) + 0.3秒 + 每轮查一次支付宝
         ≈ 1.8 秒     ← 比 10.3 秒快 5 倍多
```

## 最终流程(板子上已更新)

```
 1. wait 1 前置 确认在「确认购买」页
 2. waitfor 确认购买 5000
 3. wait 500 给页面一点渲染时间
 4. repeat 30                                 ← 最多尝试 30 轮
 5. T 0.801 0.911 30 ① 点「立即提交」
 6. waitfor 继续尝试 2500 ② 弹了就秒过 没弹说明可能成了
 7. ifpage 继续尝试
 8. T 0.522 0.594 30 ③ 弹了就点「继续尝试」
 9. else
10. wait 1 ③ 没弹「继续尝试」可能已经跳去付款了
11. endif
12. ifpage 支付宝付款 ④ 每轮都查一次
13. break 抢到了 跳出循环去付款
14. endif
15. wait 300 进入下一轮 再点一次「立即提交」
16. endloop
17. wait 3000 循环结束
```


**B. 支付宝没出现 → 继续循环**

```

```

# 四、`break` 的细节

## 你的场景

> 点击立即提交后不是继续尝试,而是 waitfor 支付宝付款 8000 等「支付宝付款」出现,
> 这个出现后就立即停止循环

**用 `break`** —— 立即跳出当前最内层循环 ✅

```
repeat 20
T 0.801 0.911 30 ① 点「立即提交」

waitfor 支付宝付款 8000 ② 看有没有跳到支付宝付款
ifpage 支付宝付款
break 抢到了 跳出循环去付款            ← 关键就是这一行
endif

waitfor 继续尝试 2000 ③ 没抢到 等继续尝试弹窗
T 0.522 0.594 30 ④ 点「继续尝试」
wait 300 再来一轮
endloop

wait 3000 循环结束 如果是抢到跳出来的 这里就是付款页了
```

**逻辑**:

| 情况 | 走法 |
|---|---|
| 8 秒内跳到「支付宝付款」 | `ifpage` 匹配 → **`break`** → 直接跳到 `endloop` 之后 ✅ |
| 8 秒内没跳 | `ifpage` 不匹配 → 跳过 break → 点「继续尝试」→ 下一轮 |

## `break` 的规则

| 项 | 说明 |
|---|---|
| 位置 | **必须在 `repeat…endloop` 里面** —— 外面写会**保存失败并报错** |
| 跳去哪 | **最内层**循环的 `endloop` 之后 |
| 备注 | 可以写,`break 抢到了 跳出循环` |
| 嵌套 | 只跳出**最内层**那一层,外层继续 ✅ |

## 嵌套时只跳一层

```
repeat 3                       ← 外层
  repeat 5                     ← 内层
    waitfor 支付宝付款 8000
    ifpage 支付宝付款
      break 跳出内层            ← 只跳出内层这 5 次
    endif
    ...
  endloop
  wait 1 内层结束了 外层继续      ← 会走到这里
endloop
```

**想一次跳两层**,就在外层也加一个判断 ✅

## 实测

```
[2/10] 重复
[3/10] 等待:循环体第一步
[4/10] 等待页面:ProjectDetail → 页面已出现(等了 0 ms)
[5/10] 如果是页面:ProjectDetail → 匹配,继续
[6/10] 跳出循环:条件满足 第 1 轮就该跳出
       → break:跳出循环,从第 10 步继续        ← 跳了
[10/10] 等待:循环之后 跳出后从这里继续          ← 直接到循环后面

```

**第 1 轮就跳出,后 4 轮没跑** ✅

## 对比:三种"结束"方式

| 想做什么 | 写法 |
|---|---|
| 跳到**某一步**(任意位置) | `goto 标号` + `#标号` |
| 提前结束**循环** | **`break`** ← 最清楚 |
| 跳到 `ifpage` 分支结束 | `endif`(自动,不用写) |

> **`break` 比 `goto` 好在**:不用起标号名、不依赖步骤位置、
> 循环里嵌套 `ifpage` 时也不会搞错跳转目标 ✅
