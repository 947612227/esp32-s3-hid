# App 启动提醒(使用前须知)

## 为什么要做

流程只是**按坐标点击**,它不知道:

- 你没登录
- 你没把票加进「抢票预约」
- 你没选购票人
- 目标 App 前面还挡着个弹窗

**这些不准备好,流程必然失败**,而且失败原因极难查(现象只是"点了没反应")。
所以启动时把清单摊开讲清楚。

## 弹窗内容

```
① 权限
   ✅ 悬浮窗权限:已开启
      (悬浮窗、坐标拾取 📐 都需要它)        ← 没开的话这里会变成红色 + 一键去开
   网络权限安装时已自动授予。
   蓝牙是系统层面配对板子,不需要 App 权限。

② 用之前必须准备好(否则流程必然失败)      ← 黄色高亮
   · 先登录目标 App —— 流程不会帮你登录
   · 想抢的票先加进「我的 → 抢票预约」,并选好票档
   · 在「我的」里设置好实名购票人 / 观演人
   · 确认 App 里没有挡在前面的弹窗(更新提示、活动广告等)

③ 注意事项
   · 流程运行期间别手动碰手机 —— 注入的是绝对坐标,会和你打架
   · 别让手机息屏(建议把息屏时间调长,或临时设为永不熄屏)
   · 同一时间只能开启一个流程(开启新的会自动暂停别的)
   · 开跑前确认:蓝牙已连板子,且 HID 显示「就绪」
   · 换了 WiFi 后点「自动查找板子」,不用手填 IP
   · 界面变化(改版/换机型)后,坐标要重新拾取

④ 用途边界
   这是个通用的触摸注入工具,只按你录的坐标点击。
   请在你有权操作的设备和你自己的账号上使用。

☐ 不再提示(设置里可以再看,取消勾选可恢复)

                                          [关闭]  [我知道了]
```

## 行为

| 场景 | 行为 |
|---|---|
| 每次启动 | 弹出(**除非**勾过「不再提示」) |
| 权限未开 | ① 里显示红色 + 「→ 点这里去开启」直达系统设置 |
| 勾选「不再提示」+ 确定 | 以后不再弹 |
| **设置 → 使用前须知** | 随时重看;**默认不勾选**,直接确定就等于**恢复启动提醒** |

## 实现细节

### 显示时机
```java
ui.postDelayed(() -> showStartupNotice(), 1000);   // 先让主界面画出来
```

### 悬浮窗会让开(踩过的坑)

悬浮窗是**系统级覆盖层**,会盖在弹窗上面 —— 实测把「① 权限」那一段完全挡住。

```java
final boolean hadFloat = (floatWin != null && floatWin.isShowing());
if (hadFloat) floatWin.hideTemporarily(120000);   // 弹窗期间收起来
dlg.setOnDismissListener(d -> {                   // 关掉再放回来
    if (hadFloat && floatWin != null && !floatWin.isShowing()) floatWin.show();
});
```

### markdown 标记不能乱用

第一版我写了 `**先登录**` 想加粗 —— 结果**字面显示出了星号**,
因为 `Dialogs.label()` 是普通 `TextView`,不渲染 markdown。

已全部改成纯文本 + 颜色区分(黄色=重点,灰色=次要)。

## 实测

| 项 | 结果 |
|---|---|
| 启动弹出 | ✅ |
| 悬浮窗让开、弹窗完整可读 | ✅ |
| 勾选「不再提示」→ 重启不再弹 | ✅ |
| 设置入口重看 | ✅ |
| 在设置里取消勾选 → 恢复启动提醒 | ✅ |
| 权限未开时显示红色提示 | ✅(逻辑就位) |

# App 更新弹窗:改成每天只弹一次

## 需求

> app 更新弹窗,每天第一次启动弹窗就行

## 改动

### 之前:每次启动都弹

只要有新版本,每次冷启动都弹一遍 —— 一天开十次弹十次。

### 现在:按「本地日历日」判断

```java
final String today = new SimpleDateFormat("yyyy-MM-dd", Locale.US)
        .format(new Date());
if (today.equals(sp.getString("updateShownDate", ""))) {
    return;               // 今天弹过了,静默跳过
}
sp.edit().putString("updateShownDate", today).apply();
// …弹窗
```

**要点**:

- 用 **`yyyy-MM-dd` 本地日期**,不是"间隔 24 小时" ——
  这样"今天 23:59 弹过、明天 00:01 再启动"**会**弹,符合"每天第一次"的直觉
- 记的是**弹过**的日期,不是"点过下载"的日期 ——
  用户点了「以后再说」今天也不会再烦他
- 弹窗里加了一行说明:**(这个提醒每天只弹一次)**

### 存的位置

`SharedPreferences("board")` 里的 `updateShownDate`,和 App 其他本地设置在一起
(**重装 App 会清掉**,重装后当天会再弹一次 —— 这符合预期)。

## 实测

| 启动 | 结果 |
|---|---|
| 第一次(当天首次) | ✅ 弹出「App 有更新 · 新版本 2.1(3)」 |
| 点「以后再说」后再启动 | ✅ **不弹了**,直接进主界面 |
| 第二天首次启动 | 会再弹(日期变了) |

## 顺带说明:板子固件更新**不是弹窗**

它是状态卡里的一行:

```
板子固件    1.0.0 → 1.1.0
点这里升级板子固件
```

**得你自己点才会弹确认框**,不会主动打扰 —— 所以没做每日限制。

> 两种提醒的区别:
> - **App 更新** = 弹窗(会打断)→ 每天一次
> - **板子固件** = 状态卡一行(不打断)→ 一直显示,你什么时候想升就点

# 设置里可以手动检查更新

## 需求

> 设置中,最底下点击底部的版本号信息可以检查更新。

## 之前

设置弹窗**最底下没有版本信息**,想看版本号只能去系统「应用信息」里翻。

## 现在

设置滚到最底下:

```
────────────────────────────────
        触摸注入板 v2.0 (build 2)
           👆 点一下检查更新
```

**点版本号那一行就会检查更新。**

## 和启动时那个弹窗的区别

| | 启动时 | 手动点 |
|---|---|---|
| 触发 | App 冷启动 | 你主动点 |
| **每天一次限制** | ✅ 有 | ❌ **没有** —— 你主动点就该给你看 |
| 没更新时 | **静默**(什么都不显示) | **明确告诉你「已是最新版本」** |
| 检查过程 | 静默 | 弹「正在检查更新…」 |
| 关了「以后再说」 | 今天不再弹 | 再点还会弹 |

## 实现

把原来那个 `checkAppUpdate()` 拆成了三个:

```java
checkAppUpdate()      // 启动时:每天一次限制,失败静默
manualCheckUpdate()   // 手动:无限制,有"正在检查…"和明确结果
showUpdateDialog()    // 两者共用同一个弹窗
```

弹窗里那行「(这个提醒每天只弹一次)」**只在启动弹出的版本里显示** ——
手动点的时候不显示,免得让人误会。

## 实测

点版本号 →

```
正在检查更新…          (转圈)
      ↓
App 有更新
新版本 2.1(3)
当前版本:2.0
大小:112 KB
新增:页面识别、句柄复制、控制中心接入
点「去下载」会用浏览器打开下载地址,下完手动安装即可
                    [以后再说]  [去下载]
```

> ⚠️ 那行 `(这个提醒每天只弹一次)` **没有出现** —— 说明手动检查走的是正确分支。

## 附带:版本号对齐

之前服务器上的 APK 是**旧包**,点「去下载」会下到更老的版本。
现在把 App 的 `versionCode` 提到 **3**、`versionName` 提到 **2.1**,
并上传了**当前这份 APK**:

```
本地 build=2 → hasUpdate=True  最新=2.1(3)     ← 老版本能看到更新
本地 build=3 → hasUpdate=False                 ← 新版不再提示
```

# 🐛 修正:检查更新的入口在**菜单底部**,不是设置里

## 你说的问题

> 你改的是哪里啊,我点了没反应啊,是不是手机上的 app 没更新呢

**两个原因都对了一半。**

## 原因 ① 我改错地方了

你说的"版本号信息"是**右上角菜单(☰)最底下**那一块:

```
☰ 菜单
  📱 App 列表
  ⚙️ 设置
  ℹ️ 关于
  ─────────────────
  版本 2.0 (build 2)      ← 你点的是这个
  作者:一个好人
```

而我把它加到了**「设置」弹窗**里面 —— 那个弹窗要滚到最底部才看得到,你根本没往那儿找。

**已改**:菜单底部那一整块现在**可点击 = 检查更新**,而且加了一行明显的提示:

```
  ─────────────────
  版本 2.1 (build 3)
  🔄 点这里检查更新         ← 新增
  作者:一个好人
```

> 设置弹窗里那个入口**保留**(两个入口都能进,更好找)。

## 原因 ② 版本号是**写死的**,所以你看到的也是过期的

```java
// About.java —— 改之前
public static final String VERSION_NAME = "2.0";    // ❌ 写死
public static final int    VERSION_CODE = 2;        // ❌ 写死
```

**我改 AndroidManifest 的版本号时忘了同步这里。**
结果手机装的明明是 build 3,菜单还显示 `build 2` —— 你会以为"App 没更新"。

**已改成从系统实时读**:

```java
public static String versionName(Context ctx) {
    return ctx.getPackageManager()
              .getPackageInfo(ctx.getPackageName(), 0).versionName;
}
```

**现在永远不会对不上。**

## 原因 ③(次要)我改成 build 3 后**忘了重新装到你手机上**

改成 build 3 之后我只编译了、没 `adb install`。
所以你手机上跑的还是 build 2 —— 而 build 2 里**根本没有菜单底部那个检查入口**(我加的是设置弹窗里的)。现在已装上。

## 实测

点菜单底部的「🔄 点这里检查更新」→

```
已是最新版本
当前版本:2.1

(检查失败也会显示这个 —— 服务器超时 15 秒就算了,
 没网/服务器挂了不影响 App 正常使用)
                              [知道了]
```

因为 App 是 build 3、服务器上也是 build 3,所以正确报"已是最新" ✅

## 教训

**同一个信息写两处,迟早对不上。**
版本号这种东西必须**单一来源**(从 AndroidManifest 实时读),
不能有"常量副本"。
