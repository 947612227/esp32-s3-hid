# 二、核心改进:固件合并成**单文件**

## 为什么要合并

原来编译出来是三四个文件,每个要烧到不同偏移:

```
0x0      bootloader.bin
0x8000   partitions.bin
0xe000   boot_app0.bin
0x10000  firmware.bin
```

**手抖填错一个偏移,板子就变砖** ✅ 对不熟悉的人太不友好。

## 合并后

```bash
esptool.py --chip esp32s3 merge_bin -o touchpad-ble-full.bin \
  --flash_mode keep --flash_freq keep --flash_size 8MB \
  0x0     .pio/build/ble/bootloader.bin \
  0x8000  .pio/build/ble/partitions.bin \
  0xe000  $HOME/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin \
  0x10000 .pio/build/ble/firmware.bin
```

**烧录时就一条命令,烧到 `0x0`** ✅

> ⚠️ 用 `--flash_mode keep` 而不是 `qio` ——
> bootloader 自带 hash 校验和,强行改 flash 参数会报 warning ✅

# 四、两个烧录脚本

## `flash-windows.bat`(用户双击)

```bat
1. 找固件(默认 BLE 版,可传参数换 usb / touchtest)
2. 没装 esptool → 自动 python -m pip install esptool
3. 用 pyserial 列出串口,取第一个
4. esptool write_flash -z --flash_mode keep --flash_freq keep
                      --flash_size 8MB 0x0 <固件>
5. 失败时打印**具体原因**(没进下载模式 / 线不行 / 串口被占)
```

## `flash-mac-linux.sh`

逻辑一样 ✅ 串口自动探测 `/dev/cu.usbmodem*`、`/dev/ttyUSB*`、`/dev/ttyACM*` ✅

**两个脚本都会在失败时给出可操作的提示**,而不是只丢一句错误码 ✅

# 五、踩的两个坑

## ① 静态目录路径写错,全部 404

```js
const DATA_DIR = path.join(__dirname, 'data');
const DOWNLOAD_DIR = path.join(DATA_DIR, 'download');   // ❌ 变成 data/download
```

但发布脚本传到的是 `__dirname/download/` ⇒ **所有文件 404** ✅

**修**:

```js
// ⚠️ 是 __dirname/download,**不是** DATA_DIR/download
const DOWNLOAD_DIR = path.join(__dirname, 'download');
```

## ② 首页 404 —— HTML 放错目录

我把 `index.html` 写到了 `server/public/download/`,
而静态目录是 `__dirname/download/` ⇒ 文件能下但**首页 404** ✅

**修**:`index.html` 也放进 `download/`,并让发布脚本一起上传 ✅

> **教训:加静态目录时,先确认"服务端读哪个路径"和"发布脚本写哪个路径"是同一个。**
