# 三星「是否连入外接键盘」弹窗 —— 最终结论

**日期**: 2026-10-02(在干净重配对后重新完整验证)

## 一、逐条排除(全部实测)

| 假设 | 做法 | 结果 |
|---|---|---|
| 描述符里有键盘集合 | 移除 Keyboard/Consumer/Mouse,设备分类变成 `TOUCH｜TOUCH_MT｜EXTERNAL` | ❌ 弹窗依旧 |
| 描述符 Collection 不配对 | 修掉多余的 `0xC0`,HID 层恢复正常 | 修好了 HID,❌ 弹窗依旧 |
| 蓝牙残留记录 | 解绑再重配 | 解绑期间无弹窗,一配对就恢复 |
| 设备处于「已连接」状态 | 断开(内核设备数=0) | ❌ 仍然弹窗 |
| 三星白名单 `sip_keyboard_type_mouse_id_list` | 加入我们的 `2562:1024` | ❌ 无效 |
| 「下次不再提示」 | 分别试 `否`+勾选、`是`+勾选 | ❌ 都不持久 |
| **蓝牙设备设置里的「文本输入」开关** | **全新配对后确认它是 ON;手动关成 OFF 再测** | **❌ 关掉后弹窗照样出现** |

## 二、结论

> **触发条件 =「板子与手机处于已配对状态」+ 聚焦输入框。**
> 与「描述符里有没有键盘」「有没有连着」「文本输入开关开没开」都**无关**。
> 这是三星系统层面的行为,**没有找到可以由 App 或 adb 关闭的开关**。

## 三、但影响没那么大(重要)

**点一下「否」就恢复正常了。** 实测:

```
弹窗 → 点「否」 → 输入 hello → 输入框内容 = hello ✅ → 弹窗不再出现
```

所以实际体验是:**每个输入场景多点一次「否」**,不是"完全无法输入"。

## 四、可操作的三条路

| 方式 | 说明 | 代价 |
|---|---|---|
| **A. 直接点「否」**(推荐) | 点一次即可,之后正常输入 | 每次输入多点一下 |
| **B. 需要长时间打字时临时解绑** | 蓝牙 → 设备齿轮 → 取消配对 | 用完要重新配对 |
| **C. 用电脑浏览器开板子的网页控制台** | 在电脑上打字 | 需要电脑 |

## 五、对 App 设计的影响(已落实)

**不要假设"板子连着时手机还能顺畅手输"**。所以:
- App 里需要键盘输入的地方**尽量少**;
- 数值参数一律用**步进器(+/-)** 而不是文本框(定时、频率都是这么做的);
- 设置页里有「打字时弹『是否连入外接键盘』?」入口,给出上面三条办法,
  并可以一键跳到蓝牙设置。

## 六、复现步骤(留给以后)

```bash
# 1. 确认已配对
adb shell dumpsys bluetooth_manager | grep -E 'name:"ESP32'
# 2. 点任意输入框
adb shell am start -a android.settings.SETTINGS
adb shell input tap 515 2079
# 3. 看弹窗
adb shell uiautomator dump /sdcard/x.xml && adb shell cat /sdcard/x.xml | grep 外接键盘
# 4. 解绑后再试 → 弹窗消失
```
