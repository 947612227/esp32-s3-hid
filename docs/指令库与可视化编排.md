# 指令库 + 可视化编排(流程内容编辑)

## 做了什么

流程编辑页从"只能手写文本"变成**双模式**:

```
┌──────────────────────────────────────┐
│ ← 返回   新建流程              [保存] │
├──────────────────────────────────────┤
│ 流程名(默认取目标 App 名字,可改)      │
│ [大麦                              ] │
├──────────────────────────────────────┤
│ 流程内容(每行一个动作)      [⛭ 指令库] │  ← 新增入口
│ [T 点击][H 长按][S 直线滑动][wait 等待][Z 捏合缩放] │  ← 快捷条
│ ┌──────────────────────────────────┐ │
│ │ T 0.167 0.939 60                 │ │  ← 文本框**保留**
│ │ H 0.5 0.5 900                    │ │
│ │ S 0.5 0.75 0.5 0.25 300          │ │
│ └──────────────────────────────────┘ │
│ 看不懂指令?点上面「⛭ 指令库」…        │
└──────────────────────────────────────┘
```

## 三种插入方式

| 方式 | 操作 | 适合 |
|---|---|---|
| **参数编辑** | 点指令库里的某条 → 拖滑块 → 插入 | 不知道参数该填多少 |
| **示例直插** | **长按**指令库里某条 | 直接要一条能用的 |
| **快捷条** | 点内容框上方那排按钮 | 常用的几条 |

## 指令库长什么样

按 4 组分类,每条给出:**助记符 / 中文名 / 写法 / 一句话作用 / 参数逐项说明 / 可直接用的示例**。

例:

```
[T] 点击
写法:T x y [毫秒]
在指定位置点一下。
x, y = 屏幕位置,写 0.5 表示 50% 处(也可以用 50% 或 16384)
毫秒 = 按下停留多久,默认 60。太短可能被系统当成误触。
示例:T 0.5 0.5 60
```

## 参数编辑页

每个参数一个**滑块**,底部**实时预览**将会写进编辑框的那一行:

```
点击(T)                        [插入]
在指定位置点一下。
写法:T x y [毫秒]
─────────────────────────────
X 坐标                     0.167
[●────────────────────────]
Y 坐标                     0.939
[────────────────────────●]
持续(毫秒)                   60 ms
[──●──────────────────────]
─────────────────────────────
将要插入的这一行:
T 0.167 0.939 60
```

拖动滑块时预览实时变化,**不用记参数顺序,也不用会算坐标**。

## 12 条指令(严格按 `script_engine.cpp` 的真实解析整理)

| 分组 | 指令 | 写法 | 作用 |
|---|---|---|---|
| 点击/长按 | `T` | `T x y [ms]` | 点击 |
| | `D` | `D x y [间隔]` | 双击 |
| | `H` | `H x y [ms]` | 长按 |
| 滑动/手势 | `S` | `S x1 y1 x2 y2 [ms]` | 直线滑动 |
| | `C` | `C x1 y1 cx cy x2 y2 [ms]` | 曲线滑动(带控制点) |
| | `P` | `P x1 y1 x2 y2 [间距] [ms]` | 双指滑动 |
| | `Z` | `Z cx cy 起始间距 结束间距 [ms]` | 捏合缩放 |
| 按键 | `K` | `K usage` | 键盘按键(默认接口关闭) |
| | `V` | `V usage` | 多媒体键(默认接口关闭) |
| 流程控制 | `wait` | `wait ms` | 等待 |
| | `repeat` | `repeat n` | 重复本行 N 次 |
| | `goto` | `goto 标号` | 跳转(配合 `#标号`) |

坐标三种写法都支持:`0.5` / `50%` / `16384`(原始值)。

## 实测验证

| 项 | 结果 |
|---|---|
| 指令库列出 12 条 + 完整说明 | ✅ |
| 点 T → 参数页 | ✅ |
| 拖滑块 → 预览实时更新(`T 0.500 0.939 60`) | ✅ |
| 点插入 → 写进文本框 | ✅ |
| 快捷条「H 长按」→ 插入 `H 0.5 0.5 900` | ✅ |
| 快捷条「S 直线滑动」→ 插入 `S 0.5 0.75 0.5 0.25 300` | ✅ |
| 文本框保留、可继续手写 | ✅ |

## 实现说明

- `CmdLib.java` —— 指令定义(助记符/分组/说明/示例/参数规格),**单一数据源**
- `CmdPickerActivity` —— 指令库列表(点=参数编辑,长按=插示例)
- `CmdParamActivity` —— 通用参数表单(按 `Param` 规格自动生成滑块)
- `FlowEditActivity` —— 保留文本框,加「⛭ 指令库」+ 快捷条 + 光标处插入

新增指令只需在 `CmdLib` 里加一条,UI **自动生成**,不用改界面代码。

## 踩到的一个小坑

指令库卡片是**外层 LinearLayout 可点,里面的文字不可点**。
自动化测试按文字点击时点不到 —— 给 `tools/uitap.py` 加了
"向上找可点祖先"的能力才解决。

# 可视化编辑(第二轮)

## 双模式

编辑页顶部有 `[☰ 可视化] [✎ 文本]` 切换,**两个模式随时来回切,内容双向同步**。

```
┌──────────────────────────────────────────┐
│ ← 返回  新建流程                  [保存] │
├──────────────────────────────────────────┤
│ 流程名                                    │
│ [大麦                                  ] │
│                    [☰ 可视化] [✎ 文本]    │ ← 模式切换
├──────────────────────────────────────────┤
│ 1. [T] 点击                               │
│    50.0% · 90.0% · 60ms                   │ ← 中文参数摘要
│    T 0.500 0.900 60                       │ ← 原始那一行
│    [↑] [↓] [✎ 编辑] [✕ 删除]              │
├──────────────────────────────────────────┤
│ 2. [S] 直线滑动                            │
│    50.0% · 75.0% · 50.0% · 25.0% · 300ms  │
│    S 0.5 0.75 0.5 0.25 300                │
│    [↑] [↓] [✎ 编辑] [✕ 删除]              │
├──────────────────────────────────────────┤
│           [＋ 添加步骤]                    │
└──────────────────────────────────────────┘
```

## 每张卡片能看到三层信息

| 层 | 内容 | 作用 |
|---|---|---|
| 中文名 | `点击` / `直线滑动` | 不用记助记符 |
| **参数摘要** | `50.0% · 90.0% · 60ms` | 一眼看懂参数含义(坐标换算成百分比) |
| 原始行 | `T 0.500 0.900 60` | 想手改时能对照 |

## 关键能力:反向解析

可视化编辑的前提是**能把已有的一行拆回参数**:

```
"T 0.500 0.900 60"  →  cmd=T, x=0.500, y=0.900, ms=60
```

所以在卡片上点「✎ 编辑」,会**带着原参数**打开滑块页,拖完插回原位置。
坐标的三种写法(`0.5` / `50%` / `16384`)都能正确解析。

## 操作一览

| 想做什么 | 怎么做 |
|---|---|
| 加一步 | 点「＋ 添加步骤」→ 指令库 → 选指令 → 拖滑块 → 插入 |
| 快速加一步 | 指令库里**长按**某条 → 直接插示例 |
| 改参数 | 卡片上点「✎ 编辑」→ 拖滑块 → 插入 |
| 调顺序 | 卡片上 `↑` `↓` |
| 删一步 | 卡片上「✕ 删除」 |
| 手写/粘贴 | 切到「✎ 文本」模式 |

## 实测验证

| 项 | 结果 |
|---|---|
| 切到可视化 | ✅ |
| 添加步骤(T 点击) | ✅ 卡片显示 `点击 / 50.0% · 50.0% · 60ms` |
| 点「✎ 编辑」 | ✅ 带原参数 `0.500/0.500/60`,标题显示「· 编辑」 |
| 拖 Y 滑块到 0.9 → 插入 | ✅ 卡片更新为 `50.0% · 90.0% · 60ms` |
| `↑` `↓` 调顺序 | ✅ S,T → T,S |
| 「✕ 删除」 | ✅ |
| 可视化 → 文本 | ✅ 文本框里出现 `T 0.500 0.900 60` |
| 文本加一行 → 切回可视化 | ✅ 变成 2 张卡片 |
| 保存 | ✅ 可视化模式下会先把卡片写回文本再保存 |

## 为什么用 ↑↓ 而不是拖拽排序

拖拽需要在 ScrollView 里拦截触摸 + 重排子 View,在这一轮已经踩过太多
"点击被父容器吃掉"的坑。**↑↓ 按钮 100% 可靠**,而且一步就能到位,
对只有几十步的流程来说够用。以后要拖拽可以再加。

## 实现位置

| 文件 | 职责 |
|---|---|
| `CmdLib.java` | 指令定义(**唯一数据源**)+ 反向解析 `parse()` + 摘要 `summary()` |
| `CmdPickerActivity` | 指令库列表 |
| `CmdParamActivity` | 通用滑块参数页(支持用已有行初始化) |
| `FlowEditActivity` | 双模式容器 + 卡片渲染 + 增删改排序 |
